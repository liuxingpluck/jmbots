## 0. 定下来的名字

| 原来叫 | 现在叫 | 为什么 |
| --- | --- | --- |
| jmindex | **memorycli** | 用户 2026-11-04 定。它是 jmbots 的"记忆"——记住项目里有什么、谁和谁有关；cli 说明它首先是个命令行程序 |
| `.jmindex/` | `.memorycli/` | 默认索引目录跟着改名 |
| 运行时目录 `jmindex/` | 运行时目录 `memorycli/` | jmbots 启动时自动迁（`Resources.ts` 的 `LEGACY_FOLDERS`） |

## 1. 它是什么，不是什么

**一句话**：把一个目录里的代码和文档"读一遍、记下来"，存成一个 SQLite 文件，然后能**搜**（这件事在哪几个文件里）、能**查关系**（谁调用谁、哪篇文档讲哪段代码、哪些文件说的是同一件事）。

- 是：**单个可执行文件**（Rust），不用装数据库，不配模型时完全不联网；Windows、Linux、macOS 都能跑。
- 是：**增量的**。第一次全量，之后只处理改过的文件（按内容哈希比）；中途停掉，下次接着打剩下的标签。
- 不是向量数据库：不算 embedding。"意思相近"靠 **AI 标签**——模型给每个文件打几个主题词，标签相同的文件就连在一起。
- 不是 jmbots 的一部分：jmbots **只把它当一个 HTTP 服务用**，它没起来 jmbots 照常干活，只是少了"挑上下文"这一块。

## 2. 术语表

| 词 | 意思 |
| --- | --- |
| 库 | 一个 SQLite 文件（`index.db`），对应**一个**被索引的目录（根目录）。今天批量建了 28 个库 |
| 根目录 `--root` | 被索引的目录。路径都相对它记 |
| 摄取 ingest | 扫目录 → 解析变了的文件 → 打标签 → 重算关系图。第一次就是全量，之后就是"更新" |
| 文件 file | 一个被收进来的文件，分三种：code（代码）、doc（文档）、config（配置，只进全文检索） |
| 声明 symbol | 代码里的函数、类、方法、接口……；文档里的标题。全名写成"外层.名字"，如 `createEngine.handleMessage` |
| 引用 ref | 代码里调用了谁、把谁当回调传出去、把谁当类型用（原样记下，算边时再去对声明） |
| 提及 mention | 文字里提到的文件路径、反引号里的代码名、Markdown 链接 |
| 块 chunk | 正文切成的段，全文检索按块搜、按块给片段。Markdown 按标题切，其他按固定行数切（前后重叠） |
| 标签 tag | 模型给文件打的主题词（3～8 个），如"飞书""长期记忆""命令审核" |
| 整合 merge | 模型把意思一样的标签并成一个标准名（"飞书""Feishu""飞书渠道" → "飞书"），记成别名 |
| 边 edge | 关系图谱里的一条线：从哪个节点到哪个节点、什么关系、置信度（0～1）、出现在哪些行 |
| 节点 ID | `file:路径`、`sym:路径#全名`、`tag:标签`、`pkg:外部包` |
| 四路搜索 | 正文、声明名、标签、路径四路各排一次名，用 RRF（每路按名次给 1/(60+名次) 分再加起来）合成一个 |

## 4. 目录分层

### 4.1 代码目录（`memorycli/`）

| 层 | 文件 | 管什么 |
| --- | --- | --- |
| 入口 | `src/main.rs` | 命令行：`ingest`、`search`、`graph`、`serve`，全局参数 `--root`、`--db`、`--config` |
| 入口 | `src/http.rs` | HTTP：四个接口，都回 JSON；`/graph?format=html` 回网页 |
| 流程 | `src/ingest.rs` | 增量摄取的整条流程，打标签并发（`model.concurrency`） |
| 流程 | `src/search.rs` | 四路搜索、RRF、给每个命中的文件配摘要、标签、片段、相关文件 |
| 流程 | `src/graph/` | `build.rs` 从原始记录算边（`rebuild`）；`query.rs` 按名字找起点走几步（`query`、`describe`）；`view.rs` 导网页（`to_html` + `view.html`）；`mod.rs` 节点 ID 和对外转出 |
| 能力 | `src/parse.rs` | tree-sitter 解析 TS/TSX/JS/Rust/Go/Python：声明、引用、导入 |
| 能力 | `src/doc.rs` | Markdown 按标题切块、提取链接和代码名；其他文字按行切块；找文字里提到的路径 |
| 能力 | `src/text.rs` | 全文检索的文字处理：汉字一个一个隔开（中文两个字的词也搜得到）、拼 FTS 查询 |
| 能力 | `src/ai.rs` | 三种接口格式（OpenAI、Anthropic、Gemini）调模型；`tag_file` 打标签、`merge_tags` 整合 |
| 存储 | `src/store.rs` | 建表、增删改文件和它的全部记录、标签和别名 |
| 配置 | `src/config.rs` | 读 `.memorycli/config.yaml`，没有就写模板 |
| 其他 | `tests/flow.rs` | 整条流程测试（本机起假模型服务，三种接口格式都测） |
| 其他 | `bench/` | 准确度对比（拿 jmbots 的 codegraph 当标准答案）、测速 |

### 4.2 运行时目录（jmbots 的 `<jmbots 运行时目录>\memorycli\`）

```
memorycli/
  config_deepseek.yaml   config_minimax.yaml     批量建库用的配置（有 Magpie 密钥，不要打开打印）
  run_deepseek.cmd  run_deepseek2.cmd  run_minimax.cmd   三条任务链
  deepseek.status  deepseek2.status  minimax.status       每个库什么时候开始、结束、退出码
  memory/  aiskills/  knowledge/  pi/  cua/ ……             每个库一个目录：index.db + ingest.log
  关系图*.html                                             jmbots 导出来给人看的关系图
```

被索引的目录（记忆库、技能库、各个项目）**一个字节都不写**：索引和配置都用 `--db`、`--config` 指到这里。

## 5. 每层对外有什么

### 5.1 命令行

| 命令 | 做什么 | 例子 |
| --- | --- | --- |
| `ingest [--no-ai]` | 摄取（增量） | `memorycli ingest --root <记忆库目录> --db ...\memory\index.db --config ...\config_deepseek.yaml` |
| `search 词... [--limit 10]` | 搜，几个词是"或"，都命中的排前面 | `memorycli search 飞书 发件箱 --db ...\memory\index.db` |
| `graph [名字] [--depth 1] [--html 文件]` | 查关系；不写名字是整张图（文件这一层） | `memorycli graph handleMessage --depth 2 --html 图.html` |
| `serve [--host] [--port]` | HTTP 服务，默认 127.0.0.1:30090 | `memorycli serve --root <jmbots 源码目录>` |

### 5.2 HTTP

| 接口 | 回什么 |
| --- | --- |
| `GET /health` | 活着吗、库里有多少文件、声明、边 |
| `POST /ingest {"ai": true}` | 摄取一次，回统计 |
| `GET /search?q=词&limit=10` | 命中的文件：路径、摘要、标签、哪几路命中、命中的声明、片段、相关文件 |
| `GET /graph?q=名字&depth=1` | 节点和边（JSON）；加 `&format=html` 回能点开的网页 |

### 5.3 库内部（Rust 模块的对外函数）

| 模块 | 对外函数 |
| --- | --- |
| ingest | `ingest(store, root, config, options, log) -> Stats` |
| search | `search(store, query, limit) -> SearchOut` |
| graph | `rebuild(store, root)`、`query(store, 名字, depth) -> GraphOut`、`describe(store, 节点ID)`、`find_start(store, 名字)`、`to_html(GraphOut)` |
| ai | `complete(model, system, user)`、`tag_file(...) -> Tagging`、`merge_tags(...)` |
| parse / doc / text | `parse(lang, src) -> Parsed`；`markdown(text)`、`window_chunks(...)`、`path_mentions(text)`；`to_fts`、`terms`、`fts_query` |
| store | `open`、`files`、`file_by_path`、`replace_file`、`remove_file`、`set_ai`、`tags_of`、`aliases`、`tag_vocabulary`、`set_aliases`、`symbol_names`、`counts` |
| config | `load(root, 指定的文件)`、`default_path(root)` |

## 6. 怎么用：几个真实例子

### 6.1 一次摄取走一遍：给记忆库建索引（2026-11-04 真跑的）

命令：`memorycli ingest --root <记忆库目录> --db ...\memory\index.db --config ...\config_deepseek.yaml`（模型 deepseek-v4.1-flash，并发 8，每个文件最多给模型看 16000 字）

| # | 模块 | 做了什么 |
| --- | --- | --- |
| 1 | `config.load` | 读指定的配置：模型、并发、排除路径 |
| 2 | `ingest` 扫描 | 走一遍目录，跳过 node_modules、.git、target 等和超过 2 MB 的文件；按扩展名分 code / doc / config |
| 3 | `ingest` 比哈希 | 每个文件算内容哈希，和库里的比：新的加、变的重解析、没了的删、没变的不动。第一次全是新的 |
| 4 | `parse` / `doc` | 代码用 tree-sitter 取声明、引用、导入；Markdown 按标题切块、取链接和代码名；所有文件找提到的路径 |
| 5 | `store.replace_file` | 一个文件的全部记录在一个事务里换掉 |
| 6 | `ai.tag_file` × 8 并发 | 2110 个文件，每个一次请求：一句摘要 + 3～8 个标签。提示词带上已有标签，让模型能用就用。每打完一个就写库，日志一行 `[368/2110] 路径：标签、标签…` |
| 7 | `ai.merge_tags` | 有新标签就整合一次：把近义的并成标准名 |
| 8 | `graph.rebuild` | 从声明、引用、导入、提及、标签算出全部边，写进 edges |
| 9 | 输出 | 统计 JSON：扫了多少、加了多少、打了多少标签、失败几个、用时 |

**中途停掉会怎样**：打过标签的已经写进库，下次再跑只打剩下的；第 8 步没跑到的话，下次跑完会重算。

### 6.2 一次搜索走一遍：`search 飞书 发件箱`

| # | 做了什么 |
| --- | --- |
| 1 | `text.terms` 拆成两个词；`text.fts_query` 拼全文检索的查询（汉字一个一个隔开，所以"发件箱"能对上） |
| 2 | 四路各排一次名：正文（FTS5 + BM25，也搜 AI 摘要块）、声明名、标签（按标准名）、路径 |
| 3 | RRF 合分：每路第 n 名给 1/(60+n)，加起来；两个词都命中、几路都命中的排前面 |
| 4 | 每个命中的文件配上：AI 摘要、标签、哪几路命中（matched）、命中的声明和行号、正文片段、关系最强的几个相关文件 |

### 6.3 jmbots 里怎么用

| 用在哪 | 怎么用 | 代码 |
| --- | --- | --- |
| 分派挑上下文 | 分派阶段拿任务原文去 `/search`；每个命中的文件交给决策模型三路判断（keep / drop / look 各给概率，不是一个阈值卡死）；只把 keep 的塞进执行者的系统提示词 | `src/capabilities/Context.ts` |
| `memsearch` 工具 | 机器人干活时自己搜；填 graph 时导出关系图网页到运行时 `memorycli/` | `src/capabilities/tools/Tools.ts` |
| 开关 | config.yaml 的 `engine.index_url`（如 `http://127.0.0.1:30090`）；不写就整块不启用，行为和没有它一样 | `src/resources/Resources.ts` |

### 6.4 批量建库：用掉快过期的模型额度（2026-11-04）

用户在 Magpie 用量页看到 MiniMax 有 800 积分当晚过期、WorkBuddy 的 deepseek-v4.1-flash 本周期只用了一半，要"多花掉些"。memorycli 打标签是**每个文件一次模型调用**，正好把额度换成有用的东西：

| 任务链 | 模型 | 库 |
| --- | --- | --- |
| `run_deepseek.cmd` | deepseek-v4.1-flash，并发 8 | 记忆库、aiskills、knowledgeBase、learning、AOBB、aoci、codegraph |
| `run_deepseek2.cmd` | 同上 | Pi、ai-memory、Jev-Mem、hindsight、codebase-memory-mcp、repowise、graphify-rs、hermes-agent、nanobot、agent-jev、AnyJev、RSI-Jev、jev-ultrafast、deepseek-harness、dsh-superagent、spec-kit、AAASkills、yichen-skills |
| `run_minimax.cmd` | MiniMax-M3.1-Flash，并发 4 | cua、crawl4ai |

实测速度：deepseek 每秒 2～4 个文件，MiniMax 每秒约 1 个；头几千个文件 0 失败。

## 7. 现状：哪里没分好【现状】

和 jmbots 改造前一样，"分了文件"不等于"分好了层"：

1. ~~**流程层绕过存储层直接写 SQL**~~（2026-11-04 已改：第 1 步）。原来 `store.conn` 是公开的，`graph.rs` 里 17 处、`search.rs` 里 10 处 SQL 直接打数据库。
2. ~~**graph.rs 一个文件管三件事**~~（2026-11-04 已改：第 2 步，拆成 `graph/build.rs`、`query.rs`、`view.rs`）。
3. ~~**一个服务只挂一个库**~~（2026-11-04 已改：第 3 步，`serve --libs 目录`）。
4. ~~**HTTP 单线程，摄取时搜索要等着**~~（2026-11-04 已改：第 5 步，摄取放后台线程）。
5. **改一个文件要重算整张图**：小库无所谓，几十万条边时要 9～11 秒。
6. **jmbots 那边没真用上**：`serve` 没开机自启，`engine.index_url` 没配。
7. ~~**jmbots 自己拼的关系图网页**只画点和线、不能交互~~（已改：直接要 memorycli 的网页，`/graph?format=html`，Windows 实测 200 text/html）。

## 8. 改造顺序【目标】

前两步不改行为，先把边界理清；后面每步都能单独上线。

| 步 | 内容 | 为什么 |
| --- | --- | --- |
| 1 | `store` 收回 SQL：`conn` 改私有，graph、search 要的查询变成 `store` 的函数 | 表结构只在一个地方 |
| 2 | `graph.rs` 拆成 `graph/build.rs`（算边）、`graph/query.rs`（查图）、`graph/view.rs`（网页） | 一个文件一件事 |
| 3 | **一个服务挂多个库**：`serve --db 记忆库 --db jmbots --db 技能库`（或给一个目录，里面每个子目录一个库）；`/search` 各库各搜一遍再用 RRF 合，结果标上是哪个库的 | 28 个库一次搜到；jmbots 只配一个地址 |
| 4 | jmbots 接上：看门狗顺带起 memorycli 服务（或 jmbots 自己起），配好 `engine.index_url` | 让"挑上下文"真用起来 |
| 5 | 摄取放后台线程，搜索不等 | 大库摄取时照样能搜 |
| 6 | 改一个文件只重算受影响的边 | 大库更新快 |

## 9. 还没定的

- 第 3 步多库怎么给：命令行一个个 `--db`，还是给一个目录自动发现？库多了以后要不要按库加权（记忆库比第三方项目重要）？
- 批量建库的那些第三方项目，以后要不要定期更新（每次更新只花改过的文件的额度）？
- 打标签用哪个模型：今天按额度挑的；以后是固定一个，还是按库挑？
