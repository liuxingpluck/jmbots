# 词汇表：会话字段、“基地”叫法、新人易卡的词

给谁用：刚接手 src7 的人和 AI。读代码时碰到“这个字段是谁加的”“基地和壳子是不是一回事”“前台、relay、journal 到底指什么”，先来这里查。

怎么查：

- 第一节按字段名找（`Ctrl+F` 搜字段名）；
- 第二节按“你看到的那个词”找，看它指什么、建议以后写什么；
- 第三节按词找人话定义和代码里的名字。

写于 2026-11-18（EST）。行号是当天对 `src7/` 和 `local/` 的 grep 结果，代码一改就会偏，以 grep 为准。这份表只是文档：没改任何代码和名字，“建议”都等第二阶段（改事件收完）以后再动。来源：云端报告 `docs/开发进度/云端报告汇总_20261118.md` 第二节第 7 条，原始分析见 `src7/docs/云端/02_新人接手成本_20261118.md` 第 5 节。

## 一、会话字段汇总

会话（Session）= 一份记录（`row`，类型 `SessionRow`）+ 推它往下走的循环（`Sessions.ts` 文件头注释）。骨架只定义 9 个字段；插件用 `declare module '../../Sessions.ts'` 往 `SessionRow` 上加自己的字段，存库时一起存（`Sessions.ts:137` 注释）。

### 1.1 骨架的 9 个字段（`Sessions.ts:139` 起的 `SessionRow`）

| 字段 | 行 | 意思 | 谁写、谁读 |
| --- | --- | --- | --- |
| `id` | `Sessions.ts:141` | 会话号，20 位纯数字（`createTimestampId`） | 新开会话时骨架生成；所有人读 |
| `kind` | `Sessions.ts:143` | 种类，骨架不解释，只拿去对工具登记的 kinds | 开会话的插件给；工具登记、各插件按它 `find` |
| `parent` | `Sessions.ts:145` | 小会话嵌在哪场会话里 | `ask()` 开小会话时设 |
| `model` | `Sessions.ts:147` | 用哪个模型，供应商名/模型 ID | 开会话时给，不给用配置默认；发请求时读 |
| `thinking` | `Sessions.ts:158` | 思考档 | 同上 |
| `state` | `Sessions.ts:160` | running / done / stopped / failed | 骨架的循环写；界面、插件读 |
| `reply` | `Sessions.ts:162` | 这一轮要回给用户的话（出错、停下时是原因） | 循环写；bots 发回渠道时读 |
| `messages` | `Sessions.ts:164` | 整场对话 | 循环写；memory、web-api 等读 |
| `updatedAt` | `Sessions.ts:166` | 最后一次存库的毫秒时间戳 | 存库时写 |

## 二、“基地”的叫法

指同一个东西：Windows 上那个 Rust（Tauri）写的常驻程序 `jmbots.exe`，源码在 `local/`。它守护后端、换版本、带托盘、提供 30085 接口（`CLAUDE.md:128`、`:147`）。一共 7 种叫法：

| 叫法 | 出现在哪（文件:行号） | 建议 |
| --- | --- | --- |
| **基地** | `plugins/base-bridge/index.ts:2`、`src7/Main.ts:45`、`CLAUDE.md:128`、`local/src/supervisor.rs:1` | **统一用这个词**：中文注释、文档、给用户的话都写“基地” |
| 壳子 | `plugins/memory/Services.ts:4`、`plugins/web-api/index.ts:281`、`:295`、`local/src/config.rs:1` | 注释里逐步改成“基地”；历史记录（带日期的进度、`Services.ts:4` 那句引用用户 11-14 的话）可以保留 |
| `jmbots.exe` | `plugins/web-api/index.ts:281`、`CLAUDE.md:85` | 只在指**文件本身**时用：换 exe、托盘退出、版本号 |
| base（`ctx.base`、`base/request`、`Base` 类、`base-bridge` 插件） | `plugins/base-bridge/index.ts:116`（`base/request`）、`:52`（`ctx.base`）、`:91`（`class Base`） | 代码标识符保留 base，和“基地”是英文对中文，不再另起名；改名等第二阶段 |
| shell（配置键 `shell:`、`shell.port`） | `local/src/config.rs:4`、`:210`；`config.example.yaml:93`（注释“壳子的 HTTP 接口”） | 只在**配置键**场合保留，配置键不改；文字里写“基地” |
| local（`local/` 目录、旧配置键 `local:`） | `CLAUDE.md:128`（`local/` 是 Rust 写的基地）、`local/src/config.rs:5`、`:208`（旧名过渡期照读） | 只当源码目录名；旧键 `local:` 以后删，不要新用 |
| supervisor（`local/src/supervisor.rs`） | `local/src/lib.rs:13`、`:28`、`local/src/supervisor.rs:1`、`CLAUDE.md:81` | 只当 Rust 模块名（它管守护和换版本），不当程序的名字用 |

另外几个常跟着出现、**不是**别的叫法但容易混的：

- `engine.index_url`（`config.example.yaml:46`）：后端找基地用的配置，默认 `http://127.0.0.1:30085`。
- 30085：基地的 HTTP 接口端口（`CLAUDE.md:147`）；30086 是主服务。
- `shell/`（Go 写的 jmshell，11-03 加的，见 `src7/docs/云端/04_历史包袱_20261118.md:46`）：是**更早的旧壳子**，不是现在的基地，别混。

建议统一的词：**基地**。

## 三、新人容易卡的词

| 词 | 一句人话 | 代码里的名字 |
| --- | --- | --- |
| 会话 / Session | 一场对话：一份记录加推它往下走的循环 | `Session`（`Sessions.ts:414`）、`SessionRow`（`Sessions.ts:242`）、服务 `ctx.sessions` |
| 小会话 | 嵌在另一场会话里问一次就走的会话（决策、审核、总结用） | `Sessions.ask()`（`Sessions.ts:482`）、`AskInput`（`Sessions.ts:286`），记录上有 `parent` |
| 前台 | 机器人对某个客户的第一线对话，简单的自己答，复杂的转后台 | 会话 `kind: 'front'`（`bots/FrontDesk.ts:334`）、类 `FrontDesk`（`FrontDesk.ts:102`） |
| 工作会话 / 后台 | 前台派出去干活的会话 | `kind: 'work'`（`bots/DispatchTools.ts:239`） |
| frontDesk（容易错） | 是**服务名**，实现它的类却是 `Dispatch`；`FrontDesk.ts` 里的 `FrontDesk` 类不是服务 | `ctx.frontDesk`（`Dispatch.ts:24`）、`class Dispatch`（`Dispatch.ts:46`） |
| 派后台 | 前台用工具把活交给一场后台，结果回前台整理再发回 | `bots/Dispatch.ts`（文件头 `:2`） |
| relay / 转话 | 一个不调模型的机器人，把用户的话转给外部助手，等回信再回给用户 | 插件 `relay`（`relay/index.ts:1` 文件头）、类 `Relay`（`:239`）、工具 `relay_send` |
| 留言 | **两个意思**：`docs/协作/留言/` 是 AI 之间留话；relay 的收件箱 `inbox.jsonl` 是转给外部助手的话。两者无关 | 前者是文件夹；后者见 `relay/index.ts:5`、`:107` |
| journal / 流水 | 把“跟踪行”（函数行、事件行）记进库，给网页追溯和 `GET /api/events` 查 | 插件 `journal`（`journal/index.ts:25`）、类 `Journal`（`:131`）、表 `journal_lines` |
| trace / 跟踪点 | 代码里发的跟踪行：`//T` 标记的点；控制台和 journal 共用同一种格式 | `utils/Trace.ts`（`MODES` 在 `:35`，`buildDispatchLine` 在 `:103`） |
| 追溯 | 网页上看“这条回话怎么来的”：从 journal 现拼，不另存 | `plugins/web-api/Trace.ts`（文件头 `:1`） |
| 轨迹 / 泳道 / boot（教程插件里） | 教程页上画一条请求经过哪些插件的几种图 | `tutorial/Trail.ts`、`tutorial/Lanes.ts`、`tutorial/Boot.ts`（只确认了文件在） |
| 决策 | 一道是非题交给模型打分，得出 allow / deny / unsure；不拦事件、不记表 | 插件 `decision`（`decision/index.ts:16`）、事件 `decision/judge`；小会话 `kind: 'decision'`（`decision/index.ts:3` 注释） |
| 审核 / 待确认 | 一件事要不要用户点头：先程序规则→决策模型→审核小会话；`ask` 登记待确认 | 插件 `approval`（`approval/index.ts:1` 文件头）、事件 `approval/request` |
| 渠道 / channel | 消息进出的入口：飞书、微信、网页（http）、命令行（cli） | `ChannelOrigin`（`Channels.ts:75`）、事件 `channel/message`（`Channels.ts:483`）、`channel/reply`（`:469`）、`ctx.bots.channel` 登记发送函数 |
| 客户 / customer | 对话对面的那个人或那个群，`渠道:用户` 一个字符串 | `row.customer`（`bots/index.ts:96`），见第一节 |
| 机器人 / bot | 一个人设加一份名单：自己的前台、后台、记忆、工作区 | `Bots`（`bots/index.ts:309`）、`Bot`（`:811`） |
| 工作区 | 一个机器人可以有几个，各有唯一 ID，后台会话按 ID 绑定 | 插件 `workspaces`（`workspaces/index.ts:26`）、`Workspaces`（`:163`）、`row.workspaceId` |
| 骨架 / 插件 | 骨架是 `src7/` 下 `plugins/` 以外的代码，只让一条消息走通；业务功能都是插件 | `CLAUDE.md` “骨架代码少之又少”一条 |
| 关口 | 会话每一步的四个事件，插件挨个看，写了 `stop` 就停 | `session/before-model`、`session/after-model`、`session/before-tool`、`session/after-tool`（`Sessions.ts` 文件头） |
| `kind`（一个词多个意思） | 会话种类（front、work、decision……）和待确认种类、回话种类、模型种类共用这个词，`review`、`decision`、`progress` 在多套取值里同时出现 | 见 `src7/docs/云端/02_新人接手成本_20261118.md` 第 5 节 |
| `http`（一个词两个意思） | 插件名（唯一的 Fastify 服务），也是网页这个渠道的渠道名 | `plugins/http`、`web-api` 里的 `customer: 'http:本机'`（`web-api/index.ts:504`） |
| 派 / pi | 用户语音里的“派”“pi”指 PI agent SDK（`@earendil-works/pi-ai`） | `Sessions.ts:7` |
