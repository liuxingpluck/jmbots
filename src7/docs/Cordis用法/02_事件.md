# 第二块：事件

读完这一块，你能说清楚：`emit`、`serial`、`parallel` 三种发法各在什么时候用，监听按什么顺序被调，`on` 登记的监听为什么插件一卸就没了。

只讲 4 个概念。

## 概念一：`ctx.on`：在分诊台登记

**一句话**：`ctx.on('事件名', 回调)` 把回调登记到这个事件的名单上，登记在 **当前插件的 fiber 名下**，插件卸下时自动撤掉，不用自己 `off`。

**Cordis 源码**：`EventsService.on`（L802–812）先确认插件还活着（L806），再 `register`（L784–791）：放进 `_hooks[事件名]`，整个动作包在 `ctx.fiber.effect` 里，撤销就是 `unregister`。

```js
// node_modules/cordis/lib/index.js（cordis 4.0.0-rc.12）
784	  register(label, name, callback, options) {
785	    const method = options.prepend ? "unshift" : "push";
786	    return this.ctx.fiber.effect(() => {
787	      const hooks = this._hooks[name] ??= [];
788	      hooks[method]({ ctx: this.ctx, callback, ...options });
789	      return () => this.unregister(name, callback);
790	    }, label);
791	  }
```

## 概念二：先登记先调用

**一句话**：同一个事件的监听按登记先后排队（`push`），只有传 `prepend` 才插到最前（`unshift`）；所以 **插件在 `config.yaml` 里的先后，就是监听被调的先后**。

**Cordis 源码**：L785 `options.prepend ? "unshift" : "push"`，L788 放进名单。


## 概念三：`emit` 是通知，`serial` 是挨个问

**一句话**：`emit` 同步地把名单上的人挨个调一遍，不等异步、不看返回值，发完就走——这是“通知”；`serial` 一个个 `await`，前一个做完才问下一个，谁返回“截停”值就不再往下问——这是“挨个问”，适合关口：每个插件都能改同一份数据、拦下它。

**Cordis 源码**：`emit`（L750–753）、`serial`（L754–760）。

```js
// node_modules/cordis/lib/index.js（cordis 4.0.0-rc.12）
750	  emit(...args) {
751	    const [thisArg, callbacks] = this._resolve("emit", args);
752	    for (const callback of callbacks) Reflect.apply(callback, thisArg, args);
753	  }
754	  async serial(...args) {
755	    const [thisArg, callbacks] = this._resolve("serial", args);
756	    for (const callback of callbacks) {
757	      const result = await Reflect.apply(callback, thisArg, args);
758	      if (isBailed(result)) return result;
759	    }
760	  }
```

`emit` 的监听如果是 async 函数，抛的错 Cordis 接不到、也不等它；要等结果或要能拦，就用 `serial`。组块阅读第一块“事件分两种——挨个问和通知”讲的是同一件事在骨架里的用法。

**类比**：`emit` 是广播“三号诊室空了”，谁听见谁处理，广播员不等回话。`serial` 是病历会签：病历挨个科室传，每个科室都能批注、能写“停，不能做”，传完一个才给下一个。

## 概念四：`parallel`：同时问（我们没用）

**一句话**：`parallel` 把名单上的回调同时跑，等全部结束；有人出错就合起来抛 `AggregateError`。它不能截停、也不保证先后，我们的代码目前没有调用它。

**Cordis 源码**：`parallel`（L742–749）。

```js
// node_modules/cordis/lib/index.js（cordis 4.0.0-rc.12）
742	  async parallel(...args) {
743	    const [thisArg, callbacks, name] = this._resolve("parallel", args);
744	    const results = await Promise.allSettled(callbacks.map(async (callback) => Reflect.apply(callback, thisArg, args)));
745	    const errors = results.filter((result) => result.status === "rejected");
746	    if (!errors.length) return;
```

**我们代码里**：没有调用。`src7/utils/Trace.ts` 的 `MODES` 表把 `parallel` 也翻成“通知”，只是预留：万一有人用了，跟踪点也认得。

**类比**：同时把会诊单发给几个科室，一起等回复；谁先回不重要，谁也不能替别人做主。
