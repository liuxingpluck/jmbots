# Cordis 用法：总览

Cordis 是 src7 底下的插件框架：骨架三样（资源、工具、会话）和所有插件都是它挂上去的。这一组只讲 **我们代码里真的用到的那部分**，照组块阅读的办法拆成 4 块，每块 3～5 个概念。每个概念都给四样：一句话、Cordis 源码位置、我们代码里的例子（文件:行号）、看诊类比。

源码按本仓库装的版本核对：`node_modules/cordis/lib/index.js`，cordis **4.0.0-rc.12**（`node_modules/cordis/package.json`）。这个包只有这一个源码文件，下文的“Cordis L行号”都指它。升级 cordis 后行号会变，要重新核。

想看时间顺序，点左栏「Cordis 用法」第一行的动态图（[Cordis.json](#lines=Cordis.json)）：一个插件从挂上到卸下，分 4 组走一遍。

## 看诊类比（整组共用）

| Cordis | 看诊 |
|---|---|
| `Context`（`app`） | 一家医院 |
| 插件、`ctx.plugin` | 科室入驻；`apply` 是科室开诊那天要做的事 |
| `Fiber`（`ctx.fiber`） | 科室的入驻档案：状态牌、借了什么、谁在等它 |
| 服务（`cordis.Service`、`ctx.provide`） | 对外开的窗口，比如药房、检验科 |
| `inject` | 开诊条件：药房、检验科开了门我才开诊 |
| `ctx.on` / `ctx.emit` / `ctx.serial` | 分诊台：登记“这类事叫我”、广播通知、病历挨个科室会签 |
| `ctx.effect` | 借东西登记在本科室名下，撤科时统一归还 |
| 换身份（`this.ctx`） | 药房窗口办事时，单子上盖的是来人那个科室的章 |

## 用法表

| 功能 | 一句话 | 在我们代码里的典型位置 | 用了多少处（正式代码 / 测试） |
|---|---|---|---|
| `new cordis.Context()` | 建一家医院（根 ctx） | `src7/Main.ts:79` | 1 / 109 |
| `ctx.plugin` | 挂一个插件，返回能 `await` 的 fiber | `src7/Main.ts:82`、`src7/Main.ts:161` | 4 / 304 |
| `extends cordis.Service` | 写一个服务类，构造时自动 `provide` | `src7/Tools.ts:114`、`src7/Sessions.ts:306` | 18 / 75 |
| `inject` 声明 | 开诊条件：这些服务都在才跑 `apply` | `src7/Sessions.ts:308`、`src7/plugins/wechat/index.ts:51` | 33 / 0 |
| `ctx.inject` | 插件里再开一个“等某服务”的小插件 | `src7/plugins/tutorial/index.ts:450`、`src7/plugins/wechat/index.ts:994` | 20 / 243 |
| `ctx.provide` | 不写类，直接把一个对象挂成服务 | `src7/plugins/feishu/index.ts:980`、`src7/plugins/tutorial/index.ts:444` | 2 / 45 |
| `ctx.get` | 按名字取服务，没挂或没就绪得到 `undefined` | `src7/Main.ts:191`、`src7/plugins/feishu/index.ts:983` | 18 / 26 |
| `ctx.on` | 登记监听，插件卸下时自动撤 | `src7/Main.ts:109`、`src7/plugins/tutorial/index.ts:447` | 119 / 92 |
| `ctx.emit` | 通知：同步挨个调，不等、不管返回值 | `src7/Main.ts:200`、`src7/Resources.ts:312` | 125 / 45 |
| `ctx.serial` | 挨个问：一个个 `await`，谁返回“截停”就停 | `src7/Tools.ts:175`、`src7/utils/RequestEvent.ts:164` | 24 / 23 |
| `ctx.parallel` | 同时问：一起跑，等全部结束 | 没有（只在 `src7/utils/Trace.ts` 的模式表里出现） | 0 / 0 |
| `ctx.effect` | 登记一件“卸下时要撤的事” | `src7/Tools.ts:141`、`src7/Resources.ts:218` | 27 / 5 |
| `ctx.fiber` | 读这个插件的档案（状态、名字、`dispose`） | `src7/Main.ts:148`、`src7/utils/Trace.ts:158` | 2 / 95 |
| `ctx.events` | 直接读事件登记表 | `src7/utils/Trace.ts:157` | 3 / 10 |
| `ctx.reflect` | 直接读服务登记表 | `src7/plugins/tutorial/Snapshot.ts:180` | 3 / 0 |
| `internal/status` | Cordis 自己发的“插件换状态了” | `src7/Main.ts:113`、`src7/plugins/tutorial/Boot.ts:239` | 2 / 0 |

**怎么数的**：扫 `src7/**/*.ts`（不含 `docs/`），先把注释和字符串挖掉再匹配，调用方只认 `ctx.` / `this.ctx.` / `app.` / `sub.` / `root.`；文件名带 `.test.` 或在 `tests/` 下的算测试。`ctx.get` 剔除首参数以 `/` 开头的（那是 Fastify 路由）；`ctx.inject` 的测试数里混着 Fastify 的 `app.inject`（假请求），偏大。中控的粗数（`ctx.plugin` 281、`ctx.on` 231……）连测试、注释一起数，所以和这里对不上；最明显的是 `ctx.parallel`：中控数到 1 处，实际正式代码和测试里都没有调用。
