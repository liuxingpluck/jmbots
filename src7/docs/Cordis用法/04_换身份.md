# 第四块：换身份

读完这一块，你能说清楚：插件 A 调 `ctx.tools.register(...)` 时，`Tools` 方法里的 `this.ctx` 为什么是 A 的 ctx；这对清理意味着什么；什么时候会踩坑。

只讲 3 个概念。要先懂第一块（服务）和第三块（effect 挂在当前插件名下）。

## 概念一：ctx 是一层 Proxy，取服务时换成“调用方视角”

**一句话**：`ctx` 本身是 Proxy；你写 `ctx.tools`，Cordis 不直接把 `Tools` 实例给你，而是用 `getTraceable` 包一层新的 Proxy，记住“是谁在取”。

**Cordis 源码**：根 ctx 一出生就是 Proxy（L1529）；读属性的 `get` 处理（L880 起）对已有属性走 `getTraceable`（L885），对服务也走它（L898）；`getTraceable`（L103–111）看对象有没有 tracker，有就 `createTraceable`。

```js
// node_modules/cordis/lib/index.js（cordis 4.0.0-rc.12）
1529	    const self = new Proxy(this, ReflectService.handler);
```


## 概念二：`createTraceable`：`this.ctx` 读到的是调用方

**一句话**：包出来的 Proxy 里，读 `ctx` 这个属性（tracker.property）返回的是 **调用方的 ctx**（L158 `useSite`）；调方法时再造一个 shadow，让方法里的 `this.ctx` 也是调用方的（L176–178）。

**Cordis 源码**：`createTraceable` 从 L151 开始：

**类比**：药房在单子上盖的是 **来人科室** 的章。科室撤了，凭章就知道哪些单子要作废——不会把药房自己的账一起清掉。

## 概念三：什么时候会踩坑

**一句话**：身份跟着“从哪个 ctx 取到的服务对象”走：从 `sub` 取到并存起来的服务对象，以后谁拿它调，记的都是 `sub` 的身份；服务想在 **自己** 名下登记东西，要在构造或 `apply` 里做，或者先把自己的 ctx 存下来。

**Cordis 源码**：`defSite` / `useSite` 在 `createTraceable` 一开始就定死（L152–153）。

```js
// node_modules/cordis/lib/index.js（cordis 4.0.0-rc.12）
152	  const defSite = ctx[symbols.shadow] ?? ctx;
153	  const useSite = ctx[symbols.shadow] ? Object.getPrototypeOf(ctx) : ctx;
```

**我们代码里**：微信在 `ctx.inject(['approval'], sub => ...)` 里把 `sub.approval` 存到自己身上，以后通过它调 approval 的方法，方法里的 `this.ctx` 都是这个小插件（`sub`）；approval 一撤，小插件跟着卸，挂在它名下的东西一起清掉，正好是想要的：

```ts
// src7/plugins/wechat/index.ts
991	  void ctx.inject(['approval'], (sub) => {
992	    wechat.approval = sub.approval;
```

`Resources` 在构造里调 `this.ctx.effect`，此时 `this.ctx` 是 resources 自己的 ctx（构造时还没换身份），所以关库挂在 resources 名下：

```ts
// src7/Resources.ts
215	    this.ctx.effect(() => {
216	      return () => {
217	        this.db.close();
218	      };
```

反例：在服务的 **方法** 里写 `this.ctx.on(...)`、想登记一个“服务自己的”监听——实际挂在调用方名下，调用方一卸，这个监听就没了。

**类比**：拿着别的科室盖过章的单子去办事，账还是记在那个科室头上；药房自己要用的东西，得在开张那天以药房的名义登记。
