# 第三块：生命周期和清理

读完这一块，你能说清楚：`ctx.effect` 登记的是什么、`ctx.fiber` 上能看到什么，以及插件卸下时 Cordis 按什么顺序替你收拾。

只讲 3 个概念。

## 概念一：`ctx.effect`：登记一件要撤的事

**一句话**：`ctx.effect(() => { 做事; return 撤销 })` 立刻做事，并把“撤销”记在当前插件名下；插件卸下时 Cordis 自动调撤销。`on`、`provide`、子插件全是用它实现的，所以它们都会自动清理。

**Cordis 源码**：`Fiber.effect`（L484–537）。先确认插件还活着（L485），执行（L516），把撤销包成 `wrapper` 放进 `_disposables`（L522–526、L535），返回值本身也能手动调来提前撤。

```js
// node_modules/cordis/lib/index.js（cordis 4.0.0-rc.12）
484	  effect(execute, label = "anonymous") {
485	    this.assertActive();
…
516	      task = this._execute(runner);
…
522	    const wrapper = defineProperty2(() => {
523	      if (!runner.epoch) return;
524	      runner.epoch = false;
525	      return task ? task.then(dispose) : dispose();
526	    }, symbols.effect, meta);
…
535	    disposables.push(this._disposables.push(wrapper));
536	    return wrapper;
```

**我们代码里**：

```ts
// src7/Resources.ts
228	    this.ctx.effect(() => {
229	      return () => {
230	        this.db.close();
231	      };
232	    });
```

```ts
// src7/plugins/wechat/index.ts
250	      //M 按配置周期拉取会话增量，供本地记录和监听逻辑处理。
251	      const timer = setInterval(() => void this.poll(), config.intervalMs);
252	      this.ctx.effect(() => () => clearInterval(timer));
…
255	    //M 拔掉插件时关闭后台发送 worker，避免遗留进程。
256	    this.ctx.effect(() => () => this.sender.close());
```

`setInterval`、数据库连接、子进程这类 Cordis 不认识的东西，都要自己包一层 `effect`，否则插件卸了它们还在跑。

**类比**：科室借了推车、开了水龙头，都在档案上记一笔“撤科时要还 / 要关”。

## 概念二：`ctx.fiber`：插件的档案

**一句话**：每个插件的 ctx 都带着自己的 `fiber`，上面有名字、状态（`state`）、`dispose()`、`await()`；状态一变 Cordis 就发 `internal/status`。

**Cordis 源码**：状态定义 L305–313；`_updateState`（L547–551）状态真变了才发事件；`await()`（L659–664）等手头的加载 / 卸载做完，失败就抛错。

```js
// node_modules/cordis/lib/index.js（cordis 4.0.0-rc.12）
547	  _updateState(callback) {
548	    const oldState = this.state;
549	    this.state = callback() ?? this._getState();
550	    if (oldState === this.state) return;
551	    this.context.emit("internal/status", this, oldState);
```

```js
// node_modules/cordis/lib/index.js（cordis 4.0.0-rc.12）
659	  async await() {
660	    while (this.inertia) {
661	      await this.inertia;
662	    }
663	    if (this._error) throw this._error;
664	    return this;
```

**我们代码里**：

```ts

161	      starting.set(fiber, row);
```


`Main.ts` 拿 fiber 当键记启动状态；tutorial 的启动流程图靠 `internal/status` 画每个插件从 PENDING 到 ACTIVE；跟踪点用 `hook.ctx.fiber.name` 写“谁在听”。

**类比**：档案上有科室名字和状态牌：筹备中（PENDING）、开诊准备（LOADING）、开诊（ACTIVE）、出错（FAILED）、撤科中（UNLOADING）、已撤（DISPOSED）。状态牌一翻，院办广播一次。

## 概念三：卸下时自动清理

**一句话**：插件卸下（`fiber.dispose()`，或它 inject 的服务撤了）时，Cordis 先等依赖它服务的插件都放手，再把它名下的 effect **全部** 撤掉；服务、监听、子插件、你自己的 effect 都在里面。

**Cordis 源码**：插件自己也是父插件的一件 effect（L363，标签 `ctx.plugin()`），所以父插件卸下会连带卸子插件。`_unload`（L628–）：先等 `provisions` 没人依赖（L629–631），再清空 `_disposables` 一个个 await（L633）。
