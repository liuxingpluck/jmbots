# 第一块：插件和服务

读完这一块，你能说清楚：`app.plugin` 做了什么、服务怎么挂出来、`inject` 为什么能让插件“等”别人，以及插件卸下时服务怎么撤。

只讲 5 个概念。事件在第二块，清理细节在第三块。

## 概念一：插件 = 一次 `ctx.plugin`，一个 fiber

**一句话**：插件就是一个函数（或带 `apply` 的模块、或一个类）；`ctx.plugin(插件, 配置)` 给它建一份档案 `Fiber`，返回的东西既是这个 fiber，又能 `await`（等它跑完 `apply`）。

**Cordis 源码**：`RegistryService.plugin`（L1489–1505）建 fiber 并包一层 `then`；`Fiber` 的构造（L330 起）给插件一个新 ctx（L341），执行时类用 `new`、函数直接调（L347–354）。

## 概念三：`ctx.provide`：不写类也能挂服务

## 概念四：`inject`：开诊条件

**一句话**：插件声明 `inject = ['resources', ...]`，列出的服务没全到，Cordis 就不跑它的 `apply`；服务到齐才开跑，服务撤了它也跟着停。`ctx.inject([...], 回调)` 是在插件里临时再开一个带开诊条件的小插件。

**Cordis 源码**：`Fiber._refresh`（L572–583）缺任何一个服务就把 epoch 设成 INACTIVE；`_setEpoch`（L584–597）从 INACTIVE 变有效时 `_reload`（真正跑 `apply`），反过来 `_unload`。`ctx.inject` 就是 `plugin({ inject, apply })`（L1486–1487）。

## 概念五：`ctx.get`：问一声在不在

**一句话**：`ctx.get('名字')` 按名字取服务，没挂、或者挂了但那个插件还没 ACTIVE，都返回 `undefined`；它不等、也不会让你停诊，适合“有就用，没有就算了”。

**Cordis 源码**：`ReflectService.get`（L939），严格模式要求服务所在 fiber 是 ACTIVE（L946）。

**类比**：开诊后临时打电话问检验科有没有人值班，没人就自己先不做那项检查。

## 挂上和卸下（这一块的五个概念串起来）

1. `app.plugin` → `new Fiber`（PENDING），发 `internal/plugin`（L359）；
2. 检查 `inject`，到齐 → LOADING，跑 `apply` / 构造（服务在这里 `provide`）；
3. 跑完 → ACTIVE，发 `internal/status`（L551），`Main.ts:118` 和 `tutorial/Boot.ts:235` 就是在听它；
4. 卸下（`fiber.dispose()`，或它 inject 的服务撤了）→ UNLOADING：先等依赖它服务的插件放手，再把它名下所有 effect 撤掉（第三块细讲）。

状态的数字定义在 Cordis L305–313：PENDING 0、LOADING 1、ACTIVE 2、FAILED 3、DISPOSED 4、UNLOADING 5。
