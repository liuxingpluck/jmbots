云端顾问，2026-11-19。看的提交：`4c68d1e`（0.7.62）。行号以这个提交为准。

范围：`src7/` 下 174 个 .ts（不算测试、迁移、`.d.ts`），约 6.6 万行。方法 A：先问“为什么会长出第二份”，再给合并办法。怎么扫的见第 8 节。

## 一页结论

**判断**：逐字一样的长段落几乎没有：这套写法一行只做一件事，注释又穿插在中间，逐字比对最长只能对上 14 行。真正的重复是**同一件事各写一份**，有三种：

- **协议对象没有构造函数**：回执、历史查询结果、来源快照，每个用的地方都手拼一遍字面量；
- **好用的小函数写成了局部闭包或私有方法**：别处看不见，只好再写一份。同一个“拼回执”现在有 5 个私有版本；
- **通用机制出来以后，老代码没改过去**：`requestEvent` 出来以后，最早手写的两段“发请求、等回执”还留着。`Failure` 类 11-17 已经合成一份，可它的处理逻辑还散在 10 个文件里。

**这不只是行数的事：抄出来的几份已经开始走样。** 回执的 `ok` 有三种算法；回复正文的摘要（payloadHash）有两种算法；HTTP 遇到不是 `Failure` 的错，有的接口回 400，有的回 500；重启恢复的那两处收尾，比别的收尾少清一个标记（第 6 节第 2 条，待核是不是 bug）。

/** 拼回执要从回复请求里抄的几样。 */
export type ReceiptSource = Pick<ChannelReplyRequest, 'replyRequestKey' | 'replyRoundKey' | 'replyIndex' | 'kind' | 'parts'>;


/** 算成功的几种状态。口径见 1.3。 */
const OK_STATUSES = new Set<ReplyStatus>(['sent', 'queued', 'draft']);


/**
 * 按回复请求拼一份回执：每一段同一个状态、同一个原因。
 * 渠道发成、发不成、没人接、超时，都用它拼；ok 只在这里算。
 * @param request 回复请求，只读几个键和 parts。
 * @param status 这次的结果。
 * @param reason 原因；发成的可以不给。
 * @returns 回执。
 */
export function getReceipt(request: ReceiptSource, status: ReplyStatus, reason?: string): ReplyReceipt {
  //M 每一段照抄请求里的段号和种类，状态、原因都一样。
  const parts = request.parts.map((part) => {
    const one: ReplyReceiptPart = { partId: part.partId, kind: part.kind, status };
    if (reason !== undefined) {
      one.reason = reason;
    }
    return one;
  });

  //M 几个键照抄请求，ok 由状态推出来。
  const receipt: ReplyReceipt = {
    v: 2,
    ok: OK_STATUSES.has(status),
    status,
    replyRequestKey: request.replyRequestKey,
    replyRoundKey: request.replyRoundKey,
    replyIndex: request.replyIndex,
    kind: request.kind,
    parts,
    at: Date.now(),
  };
  if (reason !== undefined) {
    receipt.reason = reason;
  }
  return receipt;
}


/**
 * 发 channel/replied：把回执交还给发请求的一方。
 * @param ctx 渠道插件的 ctx。
 * @param request 原回复请求，取 requestId 和 replyRoundKey。
 * @param receipt 回执。
 */
export function emitReplied(ctx: cordis.Context, request: ChannelReplyRequest, receipt: ReplyReceipt): void {
  const event = { requestId: request.requestId, replyRoundKey: request.replyRoundKey, receipt };
  ctx.emit('channel/replied', event);
}

```ts

    //M 只接 channel 是 cli 的查询；onRequestEvent 负责标 handled、带上 requestId 回 channel/history-result。
    const options = { filter: (request: protocol.ChannelHistoryRequest) => request.channel === this.name };
    requestEventModule.onRequestEvent(
      this.ctx,
      'channel/history',
      'channel/history-result',
      (request) => this.getHistory(request),
      options,
    );

  private getHistory(request: protocol.ChannelHistoryRequest): protocol.ChannelHistoryResult {
    //M 把命令行聊天的别名归一，权限判断和读记录都用它。
    const snapshot = request.sourceSnapshot;
    const targetChatId = this.resolveChatId(request.chatId);

    //G 外人只能查自己所在的命令行聊天；本人可以跨渠道查。
    const isOwner = protocol.isHistoryOwner(snapshot);
    const isSameChat = snapshot.channel === this.name && targetChatId === snapshot.chatId;
    if (!isOwner && !isSameChat) {
      const message = `无权访问命令行聊天 ${targetChatId}`;
      return protocol.getHistoryError(snapshot.visibility.scope, 'unsupported', 'forbidden', message);
    }

    //G 命令行没有平台 @ 提及。
    if (request.mode === 'mentions') {
      const scope = `${this.name}:local:${targetChatId}`;
      return protocol.getHistoryError(scope, 'local_only', 'identity_unresolved', '命令行渠道没有平台 @ 提及标识');
    }

    //M 读这个聊天的记录，按统一游标分页。
    const entries = this.readEntries(targetChatId, snapshot.botName);
    const input = { request, channel: this.name, accountId: 'local', chatId: targetChatId, entries };
    return protocol.paginateChannelHistory(input);
  }
```
