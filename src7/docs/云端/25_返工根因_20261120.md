### 1.2 为什么入站这条路特别脆

```ts

  const event = getInboundEvent(message.chatType, called);
  ...
```

cordis 的 `serial` 是一个个 `await`，中间没有 try（cordis 4.0.0-rc.12 `lib/index.js:754-760`，原文抄在 `src7/docs/骨架逐行/Cordis.json` 里）。所以任何一个排在 bots 前面的监听抛错，这条话就到不了 bots。

现在挂在这三个事件上、排在前面（`prepend: true`）的有：

| 插件 | 位置 | 自己兜没兜错 |
|---|---|---|
| approval | `approval/index.ts:456-461` | 只有目录授权查库那一处兜了（`Grants.ts:494-502`）。认批复的 `onChannelMessage`（`:502`）没兜 |
| channels 归档 | `channels/ArchiveListen.ts:47-49` | 兜了（`:32-45`） |
| memory 索引 | `memory/ChannelIndex.ts:653-655` | 兜了（`:639-651`） |

这三处 try/catch 的注释写的是同一句话：记不下只打日志，别挡别人认领。三个插件各自踩了一遍，才各自补上。

### 1.3 改法：协议出一个 `listenInbound`

放在 `channels/Message.ts`，挨着 `emitInbound`。“事件只在这一处写”是这个文件本来就有的说法（`:274`）：

```ts
/** 进来的话的三个事件。 */
const INBOUND_EVENTS = ['channel/direct', 'channel/mention', 'channel/listen'] as const;

/** 三个事件名之一。 */
type InboundEvent = (typeof INBOUND_EVENTS)[number];

/**
 * 旁听进来的话：三个事件一起挂，排在 bots 认领前面。
 * 处理出错只打日志，不往外抛。emitInbound 用 serial 挨个问，一个抛错，后面的 bots 就收不到这条话。
 * @param ctx 挂监听的插件的 ctx。
 * @param who 日志里写的插件名。
 * @param handle 处理一条话；event 说明是哪一种（approval 靠它区分“认批复”和“只过授权”）。
 * 副作用：登记三个监听。
 */
export function listenInbound(
  ctx: cordis.Context,
  who: string,
  handle: (message: ChannelMessage, control: ChannelMessageControl, event: InboundEvent) => unknown,
): void {
  for (const event of INBOUND_EVENTS) {
    const guarded = async (message: ChannelMessage, control: ChannelMessageControl): Promise<void> => {
      try {
        await handle(message, control, event);
      } catch (error) {
        //G 旁听的出错不挡认领：只打日志，这条话照常往下走。
        const reason = textModule.getErrorMessage(error);
        console.error(`${who}：处理进来的话出错，不挡认领：${reason}`);
      }
    };
    ctx.on(event, guarded, { prepend: true });
  }
}
```

### 1.4 规则和检查

- **规则**：往主路上加东西，测试里要有一条“原来那条路照旧走”的用例。这里的主路指入站事件、会话关口、通用 Hook、前缀解析。比如加一个旁听，就测它抛错时 bots 还能认领；加一个 Hook，就测没有 Provider 时还能渲染。
- **网页入口**：`web/Build.ts:24-30` 登记了 7 个入口，只有 `Main.tsx:41` 包了 `UiContext`。换版验收时，用 AOBB 把 7 个入口各开一次，教程再加开一次 `?canvas=`。这一条写进中控的换版清单就行，不用写代码。
- 这一条机器很难查，只能靠规则；第 1.3 节的结构改动，能把最容易出事的入站那段先兜住。
