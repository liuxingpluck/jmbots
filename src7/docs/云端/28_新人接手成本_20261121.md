改后：

`说明.md` 改前（`decision/说明.md:1-9`）：

### 2. 行号有工具了，工具却跳过 README（结论第 2 条）

**第二轮的问法和本地的选择**：第二轮问“长期文档还写不写行号”。从代码看，本地选了第二种：照旧写行号，把检查工具放进 git。`ztools/check-lines/` 进了 git，`package.json:16` 有 `check:lines`，0.7.80 的换版说明写着“Check_Lines 全仓 0 问题”（`Versions.json:24`）。

**可 README 还是错的**。我用脚本把 README 的 52 个代码链接逐个对了一遍：链接里有事件名就找事件名，没有就找函数名，看它在不在所指行前后 3 行内。结果错了 35 个。抽几个人工核过：

| README 写的 | 现在在哪 |
|---|---|
| `Sessions.ts:914` `Session.change` | `Sessions.ts:920` |
| `bots/index.ts:778` `Bots.channel` | `bots/index.ts:802` |
| `bots/index.ts:738` `Bots.send` | `bots/index.ts:761` |
| `approval/index.ts:975` `Approval.onChannelMessage` | `approval/index.ts:1093` |
| `feishu/Inbound.ts:717` `FeishuInbound.deliver` | `feishu/Inbound.ts:759` |
| `bots/FrontDesk.ts:257` `FrontDesk.handleChannelListen` | **这个函数没了**。0.7.70 起 `channel/listen` 由 `Bots.onChannelMessage` 接（`bots/index.ts:389`）。`bots/说明.md:250` 也还写着它 |

**为什么工具没拦住**：

1. `Check_Lines.ts:53-54` 定义了 `DOC_LINK`，把 `[文字](路径.ts#L行号)` 整段跳过，注释写着“ztools/doc-links 管”。可是 `ztools/doc-links/` 不在 git 里，README 的 52 个链接正好全是这种写法。
2. `Build_Src7.ts:250-255` 编版前只跑类型检查，不跑 `check:lines`。所以“全仓 0 问题”只代表当时手动跑的那一次、它管的那几类引用。

**改法**（两步，都小）：

1. `check-lines` 不再跳过 `#L` 链接。它已经会“相邻的反引号名字能在语法树里唯一定位，更新引用”（`ztools/check-lines/README.md`“--fix 的边界”第 2 条）。README 的链接本来就带着 `` `函数名` ``，直接走这条路，不用再要一个 doc-links。
2. 编版时跟着类型检查一起跑：

   改前（`scripts/Build_Src7.ts:250-255`）：

   ```ts
   const skipChecks = getOption('skip_checks', 'no');
   if (skipChecks !== 'yes') {
     const startedAt = Date.now();
     step('类型检查', ['x', 'tsc', '-p', 'tsconfig.json']);
     console.log(`检查一共 ${seconds(startedAt)} 秒`);
   }
   ```

   改后：

   ```ts
   const skipChecks = getOption('skip_checks', 'no');
   if (skipChecks !== 'yes') {
     const startedAt = Date.now();
     step('类型检查', ['x', 'tsc', '-p', 'tsconfig.json']);

     //M 教程、README、说明.md 里的行号和代码对一遍；对不上就不编，免得换版说明写“0 问题”而实际是错的。
     step('行号检查', ['ztools/check-lines/Check_Lines.ts']);
     console.log(`检查一共 ${seconds(startedAt)} 秒`);
   }
   ```

   `check-lines` 退出码 1 表示“有确定的问题”，正好让编版停下（`ztools/check-lines/README.md`“换版中控接入”）。它在 git 里，命令审核里放不放行，要本地看 `isProjectCheck`（待核）。

**另一种更省的做法**：README 只写“文件 · 符号”，不写行号；要跳就在教程页现算。README 每次大改都要重对一遍 50 个链接，这种做法不用。可用户既然选了写行号，这里就只推荐上面两步。
