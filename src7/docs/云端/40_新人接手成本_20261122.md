**按第一性原理看**：新人要的只有两样，一是“现在是什么样”，二是“去哪找”。上一轮的病根是过去的事混进了现在的说明。这一轮又多了一层：**同一件事有两份，一份机器生成，一份人手抄**。函数清单有教程页现算的，也有说明.md 手抄的；插件清单有教程页 X 光现算的，也有地图上不知道哪天生成的。人手抄的那份一定会过期，而新人分不出该信哪一份。解法只有一条：**机器能算的，人就别抄；人只写机器算不出来的东西，也就是“为什么”和“什么时候用”**。

### 1. 说明.md 手抄代码位置（结论第 1 条）

| 内部函数 | 同上，点进文件就能看到 | 说明.md 的“内部函数”节，共 656 行 |

### 2. 知识、记忆、VGR、图谱（结论第 2 条）

**两套“知识库”，同一个目录**

| | `knowledge` 插件（积木知识库） | memory 插件里的“知识库” |
|---|---|---|
| 真源 | SQLite `kb_docs` 等表 | 磁盘上的 `.md`、`.txt` 文件 |
| 磁盘位置 | 镜像默认 `<运行时>/knowledge/YYYYMMDD/<id>_<标题>/content.md`（`knowledge/index.ts:75`、`DiskMirror.ts:4`） | `<运行时>/knowledge/` 和 `bots/<机器人>/knowledge/`（`memory/Store.ts:4`、`:154`） |
| 怎么收 | 每次改文档都重新导出一份 | 每 30 秒扫一遍 `**/*.{md,txt}`，把新的、改过的切片送进向量库（`memory/Store.ts:147-174`、`:258`） |
| 说明.md 怎么写 | `knowledge/说明.md:122`、`:127` 写了镜像的路径，没说 memory 会收 | `memory/说明.md` 一处“镜像”都没有 |

两边默认写的是同一个目录，所以 memory 会把知识库的每篇 `content.md` 再切一遍片。0.7.100 的“长期记忆条”面板发现了这件事，只好去嗅同目录有没有带 `id` 的 `meta.json`，把镜像文件挡在外面（`VgrAdmin.ts:327-338`、`:406-407`、`:421`）。但挡住的只是**列表和删除**，索引照收。

**搜索可能重复（待核）**：`GET /api/knowledge/search` 先查本地（`knowledge/Routes.ts:442`），再问 memory，默认来源是 `'knowledge,card,channel'`（`:48`），两份结果一起交回（`:455-462`）。memory 的 knowledge 来源里就有镜像的片段，所以同一篇文档可能本地命中一次、记忆又命中一次。我没法跑服务，命中里的 `ref` 是不是带镜像路径也没核（`knowledge/Types.ts:258`）。
