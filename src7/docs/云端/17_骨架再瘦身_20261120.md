### 1. 挂插件记账（结论第 1 条）

**现状**：`Main.ts:107-223` 是 Main 的后一半，88 行代码。一个插件一行状态，有 `mounted`、`started`、`missing`、`error` 四个字段，在 5 处写：

| 行 | 什么时候写 | 写哪几项 |
|---|---|---|
| `:109-121` `recordPluginFailure` | 失败时 | 四项全写 |
| `:128-135` 监听 `internal/status`，ACTIVE | 开工了 | 四项全写 |
| `:175-179` `fiber.await().then` | 首轮等待结束、还在等服务 | `mounted` |
| `:193-198` 超时 | 到点了 | `mounted`、`error` |
| `:214-223` ready 前 | 缺服务 | `missing` |

读的人有三处，各自把两个布尔值翻成人话：

- `Resources.ts:102-122` 的 `getPluginProblems`：给 `/api/health`（`http/index.ts:198`）；
- `tutorial/index.ts:727-736`：教程左栏；
- `tutorial/Boot.ts:557-564`、`:573-574`：教程的启动流程。

另外 `bots/index.ts:327` 读 `memory?.started`。

**改后**：每行只留 `state` 和 `reason` 两项。开工、失败都只听 Cordis 的 `internal/status`；到 ready 还在 `starting` 的，再分成缺服务和起得慢两种。

```ts
// Resources.ts，改后
/** 一个插件这次启动的结果。Main.ts 写，健康检查和教程读。 */
export interface PluginStatus {
  /** 配置里的插件名。 */
  name: string;
  /** 它声明要的服务。 */
  inject: string[];
  /** starting 正在起；ok 开工了；slow 超时了，还在后台起；waiting 缺服务；failed 没挂上。 */
  state: 'starting' | 'ok' | 'slow' | 'waiting' | 'failed';
  /** 不是 ok 时，给人看的一句原因。 */
  reason: string;
}

/** 没开工的插件各一句话，给 /api/health 的 problems 和教程。 */
export function getPluginProblems(status: PluginStatus[]): string[] {
  const problems: string[] = [];
  for (const item of status) {
    if (item.state === 'ok') continue;

    problems.push(`插件 ${item.name}：${item.reason}`);
  }
  return problems;
}
```

### 3. 热更新只做了一半（结论第 3 条）

0.7.62 的更新说明（`Versions.json:63`）写的是：“改 config.yaml 里的供应商和密钥不用重启”。实际做的是把整份配置都换掉：

|---|---|---|
| `providers`（地址、密钥） | 马上 | `Resources.updateProviders`，鉴权回调每次读当前配置（`Resources.ts:368-376`） |
| `default_model`、`models.thinking`、`models.retry`、`session_cache_max` | 马上 | `Sessions` 每次用时现读 `resources.config`（`Sessions.ts:345`、`:422`、`:518`） |
| `bots` 名单 | 马上（只是名单） | 13 个插件现读 `raw['bots']`；但 bots 插件里的机器人对象只在启动时建（`bots/index.ts:319-321`） |
| 各插件自己的 `config` | 重启 | 挂载时一次性传进 `apply` |
| `plugins` 名单、`plugin_mount_timeout_ms` | 重启 | 只在启动时用 |

可是：

// Resources.ts，改后
/** 校验并换上新快照；不过就保持原配置，写明原因。 */
private reloadConfig(file: string): void {
  try {
    const next = readConfig(file);
    //G 内容没变（保存一次会来好几次文件通知）→ 不换。
    if (util.isDeepStrictEqual(this.raw, next.raw)) return;

    //M 先换 pi 的供应商，再换快照；读 config、raw 的地方，下一次读到的就是新的。
    this.updateProviders(next.config.providers, this.config.providers);
    this.current = next;
  } catch (error) {
    const reason = textModule.getErrorMessage(error);
    console.error(`config.yaml 重读失败，继续使用原配置：${reason}`);
  }
}
