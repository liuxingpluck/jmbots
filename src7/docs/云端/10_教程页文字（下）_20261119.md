### 1.2 改法：规矩

写进 CLAUDE.md“代码约定”里讲 `说明.md` 的那一条（建议的原话）：

> `说明.md` 标题下第一句只写这个插件管什么，和 `index.ts` 文件头第一句一样，改版时不动。这一版改了什么写进 `src7/utils/Versions.json`，不写进说明。

这样写不额外增加工作：0.7.58 在 `Versions.json` 里已经写了“‘结果不确定’统一成一处判断”，12 份说明的第 3 行等于把同一件事又抄了 12 遍。journal、relay 末尾已有的 `## 改版记录` 可以留着，教程页会把它放进「补充」，不影响概要。

### 1.3 改法：检查（两种做法）

| | A：第一句和文件头第一句一样 | B：查第一段里有没有改动记录的样子 |
|---|---|---|
| 怎么查 | 取 `说明.md` 第一个 `##` 之前的第一句，再取 `index.ts` 文件头第一句（教程页已有 `getHeadBlock`、`getFirstSentence`，`Source.ts:415`、`:429`），两句不一样就报 | 第一段里出现版本号 `\d+\.\d+\.\d+`，或者“保留、不再、改成、统一、已并入、未获回执”这类词就报 |
| 好处 | 一定查得准；同一句话还能同时给启动画布、插件地图摘要列、「概要」用，只维护一处 | 不用改任何现有的文件头 |
| 代价 | 31 个 `index.ts` 文件头第一句要先定稿（第 5 节本来就要改） | 0.7.58 写的那 12 句都不带版本号，词表要一直补；会误报正常的句子 |

推荐 A。示意（CLAUDE.md 写法）：

```js
//M 查一个插件：说明.md 的开头和 index.ts 文件头第一句一样，二级标题教程页都认得。
function checkPlugin(dir) {
  const problems = [];
  const readmeText = fs.readFileSync(path.join(dir, '说明.md'), 'utf8');
  const sourceText = fs.readFileSync(path.join(dir, 'index.ts'), 'utf8');

  //M 开头第一句要和文件头第一句逐字一样。
  const introSentence = getIntroSentence(readmeText);
  const headSentence = getHeadSentence(sourceText);
  if (introSentence !== headSentence) {
    problems.push(`开头是“${introSentence}”，文件头是“${headSentence}”`);
  }

  //M 二级标题：教程认得的、以“补充：”开头的、设计要点和改版记录，别的都报。
  for (const title of getTitles(readmeText)) {
    if (KNOWN_TITLES.has(title)) continue;
    if (title.startsWith('补充：')) continue;

    problems.push(`标题“${title}”教程页认不出，会落进「补充」`);
  }

  return problems;
}
```

`KNOWN_TITLES` 就是 `ReadmeTabs.tsx:121-159` 那 9 个，再加“设计要点”“改版记录”。发版前和插件地图生成脚本一起跑。
