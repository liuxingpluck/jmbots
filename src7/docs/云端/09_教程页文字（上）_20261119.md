## 一页结论

### 1.2 统一的开头写法

```markdown
# <插件名> v<版本>

<一句话：它管什么，30 字以内>

<一到三行：一条消息或一次调用怎么经过它，带上它听、发的主要事件>

<一行：什么不归它管，或者它和谁分工>（可省）
```

细节一律挪进对应的二级标题。实在放不进去的，写成 `## 补充：<题目>`，教程页会单独开一个「补充」标签。

### 1.3 改前改后：cli

改前（`cli/说明.md:3`，一句 310 字）：

> 把命令行文字通过统一事件 `channel/message` 发给指定或首个机器人（role owner、`routing.autoFinal`：前台一轮里 `channel_reply` 几次就逐条打几行，一次没调就打最后的话；`registerTextReply` 挂入 `getTargetAddress` 自认本机聊天；收尾 `channel/settled` 没回成时红字、退出码 1），在所有会话空闲后退出；`History.ts`（`CliHistory`）监听 `channel/history` 读 `channels/cli/*.jsonl` 回传 `channel/history-result`。

改后：

```markdown
命令行渠道：把命令行里带的那句话发给机器人，打印回话，等所有会话都停下就退出。

- 发：先把这句话存进 `channels/cli/<日期>.jsonl`，再发 `channel/message`，说话人算本人。
- 回：模型每调一次 `channel_reply` 打一行；一次都没调，就打这一轮最后那句话。没回成，红字打出原因，退出码记 1。
- 查历史：听 `channel/history`，读同一批 jsonl 回给模型。
- 不读键盘输入；要一问一答，另写一个插件。
```

### 1.6 改前改后：approval 的卡片三行

改前（`approval/说明.md:9-14`）：六行长句，第 1 条里套着“（1.1.6：`askDecision` 带 `want: ['what']`，`decision/judge-result` 回的 `what`，决策模型拿不准、往下走时才用得上）”。

改后（放进 `## 补充：待确认卡片写什么`）：


## 5. 函数表不再手写行号

### 5.1 为什么

- 行号坏得很快。说明里的“核验快照”是 11-18 00:47，到 0.7.57 一天半，脚本抽查 290 行“名字 + 位置”，189 行在上下 15 行里找不到这个名字（粗算，有误差；逐份情况见 3.3）。坏的行号在教程页上是能点的链接，点过去落在别的函数上，比不写还糟。
- 位置教程页自己就能算：对外函数从源码抽（`Code.ts:4`），骨架的函数表也是现抽的（`Skeleton.ts:643-680`）。说明里再抄一遍，就有了两份会打架的数据。
- 抄来的位置把人话挤没了。feishu 第 99 行有一格 793 字，全是 `src7/plugins/feishu/Media.ts:255`、`:298`……这样的调用方列表；http 第 101 行一格 200 字，写的是 `isGuarded` 在 1.1.4 修 bug 的经过。

### 5.2 两种做法

| | A：只写名字，位置交给教程页 | B：照旧写行号，加自动检查 |
|---|---|---|
| 说明.md 怎么写 | 对外函数：`名字 \| 参数 \| 作用`；内部函数：`名字 \| 什么时候调`。都不写文件:行号 | 照旧 |
| 要动的代码 | 教程页把表里的 `Cli.start` 这类名字认成链接，按名字去插件文件夹里找定义（`Source.ts` 已经有按文件读源码、取注释的能力，待核能不能按名字找） | 在 `ztools/` 加一个检查脚本，照 `check-abs-paths` 的样子：每个 `文件:行号` 那一行要包含表格里写的名字，不包含就报 |
| 好处 | 永远不会过时；说明短六分之一以上 | 结构不变，用户熟悉的“点了就跳”照旧 |
| 代价 | 改一处前端；同名方法要带类名（`Cli.start`），现在大部分已经这么写了 | 每次发版前多跑一道检查；修行号是机械活，还得有人去修 |
| 最强的反对意见 | “按名字找”遇到重载、同名私有函数会找错 | 检查只能发现“行号不对”，发现不了“这句话说的已经不是现在的逻辑”（cli 的 `Cli.send` 就是这种：函数都没了） |

**推荐 A。** 现在新写、重写的几份（base-bridge、context-fit、exec、decision-map）已经自己走到了这条路上：它们的函数表里只写文件名不写行号，或者干脆没有函数表，读起来明显顺。B 管得住数字，管不住意思。

A 下面，`说明.md` 留下来的就是 CLAUDE.md 要求的那几样（干什么、依赖、听和发的事件、对外函数的参数和作用、内部函数什么时候调、数据表每一列、配置），再加「补充：设计要点」。
