## 二、第 1 条：收费插件在公开仓库里

### 2.1 事实

| 事 | 在哪 |
|---|---|
| 用户的路线：收费插件“放在仓库外面单独编译” | `src7/docs/云端任务.md:20`（#161） |
| `external/wechat/` 0.7.76 加进来（`b48e7ec`），之后又改过两次 | `git log -- external/` |

| 授权：本地公钥验签，校验产品、机器指纹、功能位、到期 | `external/wechat/说明.md:18-21` |
| 测试版的编法 | `external/wechat/Build.ts:7`、`:67-68` |
| 仓库可见性：public，0 个复刻，1 个星标 | GitHub 搜索接口，11-21 查 |

### 2.2 为什么这次不一样

- 14、26 号讲仓库私有，理由都是“安全说明书”。用户没定，可以理解为用户觉得公开的代价可以接受；
- 这次的理由是**用户自己的生意**：收费插件的源码和授权逻辑都公开，谁都能自己编一份。这和 #161 的“放在仓库外面”正面冲突；
- 另外，这个插件读的是用户自己的微信库。解密办法放在用户名下的公开仓库里，会不会招来平台投诉、下架，**待核**，不在本文范围。

本文只写“在哪、和哪句话冲突”，没写怎么绕开授权。

### 2.3 两种做法

| | A. 整个仓库私有 | B. `external/` 单独私有 |
|---|---|---|
| 动作 | GitHub 设置里改一项 | 新建私有仓库，挪走 `external/`，主仓库删掉 |
| 主仓库 | 私有 | 照旧公开 |
| 历史 | 一起变私有 | 主仓库的历史里还有 `external/wechat/` 的旧版本，要么接受，要么另开干净仓库 |
| 云端顾问 | 照常读写（GitHub 应用授权） | 照常读写主仓库；看不到 `external/`，正好 |
| 适合 | 现在还不打算开源 | 想要“主程序开源、插件收费” |

### 2.4 反方意见

- **“公开仓库方便云端、方便别人看。”** 云端会话靠 GitHub 应用读私有仓库，不受影响。“别人”现在是 0 个复刻。
- **“发布那天再说。”** 公开的东西收不回来，被人拷走的那份永远在。而外置插件本来就设计成单独编译（`说明.md:3`“零跨目录 `src7/` 或 `web/` 源码耦合”），挪出去不用改代码。
