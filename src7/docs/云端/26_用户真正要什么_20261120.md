## 二、第 1 条：外网这条路上的三层判断

### 2.1 一条外网请求要过哪几道

`http/index.ts:398-444` 的 `check`，按顺序：

1. `checkExternal`（`WebAuth.ts:341-361`）：带了 `X-External-Proxy: 1`、又配了 `web_auth` 的，才走登录。**没带这个头，就当它不是外网**（`:348`）；
2. `isLocal`（`index.ts:364-368`）：socket 地址是 127.x 或 ::1 的，算本机，免令牌，记成“已核验”；
3. `:423`：路径不用令牌、登记过免查，**或者一个令牌都没配**，放行；
4. 令牌对了，放行，记成“已核验”（`:432-436`）；
5. 来源在 `trusted_ips` 里，放行，但不算已核验（`:437-439`）；
6. 剩下的回 401。

放行以后，网页发来的话由 web-api 收下，写进回话地址的是 `owner: true`，不管核没核验（`web-api/index.ts:546`）：

```ts
const address: Record<string, unknown> = { messageId: id, customer: 'http:本机', owner: true, verifiedOwner };
```

`verifiedOwner` 只在少数几处起作用：提醒（`assist/Reminders.ts:92`）、审批（`approval/index.ts:1076`、`:1110`）。会话给什么工具，看的是 `isOwnerTurn`（`channels/Message.ts:399-412`），而 `owner: true` 就是本人。

### 2.2 哪一层出错，落到哪

| 出错的情形 | 落到哪一步 | 结果 |
|---|---|---|
| 隧道落在本机、Nginx 某一处漏了那个头 | 第 2 步：地址是 127.0.0.1 | 本人，已核验（24 号第 2 条讲的就是这个） |
| 隧道不落在本机（比如端口转发），Nginx 漏了头，**一个令牌都没配** | 第 3 步：`tokens.none()` | 放行。网页发的话照样 `owner: true` |
| 照 24 号第一步改完（带代理头的都不算本机），**一个令牌都没配** | 第 3 步 | 同上，还是放行 |

所以 24 号第一步只关了第一层。第二层在零令牌时开着，第三层什么时候都开着。

`config.example.yaml:77` 的 `token` 默认是空的，`Notify.ts:57` 也专门判了“令牌为空”，可见零令牌是正常配置。用户那台机器上配没配，云端看不到（待核）。

### 2.3 改前、改后

**① 零令牌不再对暴露在公网的机器放行**（`http/index.ts:422-423`）

改前：

```ts
    //G 免查路径或未配置任何令牌时照常放行，远程请求没有身份标记。
    if (!guarded || this.open.has(route) || this.tokens.none()) return undefined;
```

改后：

```ts
    //G 免查路径、登记过不用令牌的，照常放行。
    if (!guarded || this.open.has(route)) return undefined;

    //G 一个令牌都没配：只在没开外网登录时放行（局域网开发照旧）。
    //G 开了外网登录，说明这台机器从公网摸得到，远程请求没令牌就不放。
    const exposed = this.webAuth.isEnabled();
    if (this.tokens.none() && !exposed) return undefined;
```

`isEnabled` 是给 `WebAuth` 新加的一行取值（`return this.spec !== undefined;`）。现成有没有能读的开关，待核。

开了外网登录、零令牌时，130 上的中控就落到第 4、5 步：要么带令牌，要么把它的地址写进 `server.trusted_ips`（第 5 步放行）。这一点要先核（一页结论第 1 条的风险）。

**② 公网链接不带主令牌**（`work-decision/Notify.ts:53-61`）

改前：

```ts
  const url = new URL(notice.url);
  const server = ctx.resources.raw['server'];
  //M 用当前服务令牌生成手机可打开的链接。
  const token = utils.getStringField(server, 'token');
  if (token !== '') {
    //M 仅把登录令牌交给配置的收件地址，返回值和日志只带发送结果。
    url.searchParams.set('token', token);
  }
  const text = `工作决策有 ${String(pending)} 件等你定\n${url.href}`;
```

改后：

```ts
  //M 链接不带令牌：手机从公网打开时走登录（Cookie），令牌只留在 config.yaml 里，
  //M 不进飞书聊天记录，也不进代理的访问日志（查询串默认会记进去）。
  const url = new URL(notice.url);
  const text = `工作决策有 ${String(pending)} 件等你定\n${url.href}`;
```

为什么能删：配了 `web_auth` 以后，带头的外网请求在 `checkExternal` 里只认 Cookie，没 Cookie 就 401（`WebAuth.ts:351-358`），根本走不到令牌那一步。手机在家里连 Wi-Fi、开局域网地址（`config.example.yaml:241` 的示例就是局域网地址）的，本来就要令牌，这种部署可以把 `public_url` 写成带令牌的完整地址，配置里写一次就行，代码不再替它拼。

**③ CLAUDE.md `:36-37` 加一句**

```markdown
- **本机来的请求不查令牌，令牌固定写在 config.yaml**（……原话不动）：
  - 只有别的机器来的请求，才要带 `server.token`；
  - 从公网进来的（反向代理、隧道）不算本机，也不按“别的机器”放行：只认网页登录。判断它靠“从哪个口进来”，不靠请求头。
```

`:35` 的“不要为此加防护”说的是局域网。这一句不加任何限制，只把公网这条路单独说清楚。

### 2.4 待核：隧道落在哪

仓库里搜不到 Nginx 和隧道的配置。危险程度取决于外网请求到家里时的 socket 地址：

| 隧道怎么接 | 后端看到的地址 | 漏了头会怎样 |
|---|---|---|
| frp、`ssh -R` 这类，落在 Windows 本机 | 127.0.0.1 | 第 2 步：本人，已核验。最危险 |
| 路由器端口转发，Nginx 直接连家里公网 IP | 阿里云那台的 IP | 第 3 步：零令牌时放行；有令牌时 401 |
| VPN（WireGuard 一类） | VPN 内网地址 | 同上 |

前两种情况，①都管用；第一种还要 24 号第 2 条才能关严。

### 2.5 反方意见

- **“外网地址只有我知道。”**
  - 公网扫描器扫端口很快；
  - 公开仓库里写着用的是阿里云 Nginx、请求头叫什么（`WebAuth.ts:2`、`:18-19`），见第 3 条。
- **“漏了头，我会发现的。”**
  - 漏了头的时候，页面不出登录框，直接就能用，看起来还更顺；
  - 失败的样子和成功一模一样，所以没人会发现。
- **“开发阶段不加限制。”**
  - ①只在开了外网登录时生效，局域网开发一切照旧；
  - ②删的是一个在公网路上不起作用的参数。

### 3.3 反方意见

- **“手机工作台、四象限是用户点名要的。”**
  - 有可能，云端看不到用户的原话（待核）；
  - 第 2 条不删网页，它做的是让“拍板”不再依赖网页。网页要不要接着长，变成一个单独的选择，留给用户定（一页结论第 2 件）。

## 四、第 3 条：仓库公开，加上服务上了公网

### 4.1 事实

- 11-20 用 GitHub 的搜索接口查了，这个仓库的 visibility 仍是 `public`；
- 14 号说过的那些还在：CLAUDE.md 里的内网地址、SSH 端口、几台机器的分工；`src7/` 和 CLAUDE.md 里一共 40 处带 `192.168.` 的地址；提交作者的个人邮箱；
- 0.7.76 以后多了：
  - 外网登录的整套判法：请求头名、Cookie 名、连错 10 次冷却 60 秒（`WebAuth.ts:18-31`）；
  - 反代用的是哪家（`WebAuth.ts:2`）；
  - `Versions.json:33` 写出了外网登录的账号名（本文不重复写它）。
- 没找到的：公网地址、密码、密钥。`config.example.yaml:241` 的 `public_url` 示例是局域网地址。

### 4.2 为什么现在更急

14 号那时，服务只在局域网里，公开仓库泄露的是“家里怎么布置的”。现在服务在公网上，公开仓库给出的是：入口用的哪家代理、靠什么判外网、账号叫什么、限速多少。离能撞开那道门，只差公网地址和密码两样。

### 4.3 改法

- **推荐**：改成私有。云端会话经 GitHub 应用授权，私有仓库一样能读、能推；
- **不改的话，至少**：`Versions.json:33` 那条删掉账号名。可 git 历史里还在，所以这只是“至少”。
