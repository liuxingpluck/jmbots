### 2.3 根因

CLAUDE.md 第 191 行：“同目录写 `说明.md`，以版本号开头”。本意应当是标题行带版本号（16 份的标题都写了 `# 名字 vX.Y.Z`，而且都和 `index.ts` 的 `version` 一致，这一点做得好）。可写说明的 AI 读成了“每个版本开一段”，于是：

1. 每改一次，就在开头插一段“x.y.z 改了什么”；
2. 跨插件的批量改动，在每个受影响的说明开头各插一句（套话、“不确定”那句都是这么来的）；
3. 改动记录本来已经有两份：git 提交说明，和 `src7/utils/Versions.json` 每版的 `changes`。说明里这一份是第三份，也是最先过时的一份：channels 标题写 v1.8.2，开头最新一段是 1.8.1。

它还违反同一份 CLAUDE.md 第 209 行：“写文档按最终状态写，不留改版痕迹。”

### 2.4 改法

**规矩（要用户点头）**：CLAUDE.md 第 191 行改成：

```markdown
- 同目录写 `说明.md`：标题行写 `# <插件名> v<版本>`，下面三行说清它管什么、一条消息怎么经过它、什么不归它管；
  再写这几样：依赖、听和发的事件、对外函数（参数、作用）、内部函数（什么时候调）、数据表每列、配置。
  改了什么写进提交说明和 `Versions.json`；说明里只改对应那一节的句子，不在开头加改动记录。
```

**检查**：check-lines 本来就扫 `src7/plugins/*/说明.md`，在它的提示里加两条，不另起工具：

- 标题和第一个 `##` 之间出现 `^\d+\.\d+\.\d+ ` 开头的段落；
- 标题和第一个 `##` 之间超过 12 行。

**第一屏的写法**（和上一轮一样，这次附上可以直接替换的原文）：

```markdown
# <插件名> v<版本>

<一句话：它管什么，30 字以内>

- <一条消息或一次调用怎么经过它，带上听、发的主要事件，一到三行>
- 不归它管：<和谁分工>（可省）
```

### 4.3 改法（示意，待核）

在 `getHints` 拿不到名字时，退到“这是表格行，就用第一格”：

```ts
/**
 * 表格行里取名字：函数表的第一格就是这一行讲的函数。
 * @param line 引用所在的那行。
 * @returns 第一格里像名字的那段；不是表格行回 undefined。
 */
function getRowName(line: string): string | undefined {
  //G 不是表格行就不管。
  if (!line.startsWith('|')) return undefined;

  //M 取第一格，去掉反引号和括号里的参数。
  const cells = line.split('|');
  const first = cells[1] ?? '';
  const noTicks = first.replace(/`/gu, '');
  const noArgs = noTicks.replace(/\(.*$/u, '');
  return getHintName(noArgs.trim());
}
```

`getHints` 里只改一行：

```ts
  //M 左边紧挨着的优先，没有再看右边，都没有再看表格第一格。
  const near = getHintName(before?.[1]) ?? getHintName(after?.[1]);
  const primary = near ?? getRowName(line);
```

“定义及生产调用位置”一格里除了定义，还有调用处；调用处那一行也会出现这个名字（调它总得写它的名字），所以同一个名字可以核整格的引用。`--fix` 本来就会按名字在语法树里找唯一定义（`check-lines/README.md` 的“--fix 的边界”第 2 条），有了名字，多数能自动修。
