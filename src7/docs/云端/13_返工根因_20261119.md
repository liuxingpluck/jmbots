服务端在读 JSON 时现场补上行号和原文。放在 `Source.ts` 里，挨着 `getLineIndex`：

```ts
/**
 * 把一块的锚点换成现在的起止行和代码原文。
 * @param lines 那个骨架文件，一行一项。
 * @param code 块里写的文件和首尾两段代码。
 * @returns 起止行（从 1 起）和原文；找不到时写明是哪一段没找到。
 */
export function getAnchoredBlock(lines: string[], code: BlockAnchor): AnchoredBlock {
  //G 开头那段找不到，说明代码改过了，照实标出来，不猜。
  const start = getLineIndex(lines, code.from);
  if (start < 0) return { missing: `找不到开头：${code.from}` };

  //M 结尾从开头往后找，同一段代码在前面出现过也不会认错。
  const rest = lines.slice(start);
  const offset = getLineIndex(rest, code.to);
  if (offset < 0) return { missing: `找不到结尾：${code.to}` };

  //M 起止行从 1 起算，原文现场切出来。
  const end = start + offset;
  const text = lines.slice(start, end + 1).join('\n');
  return { from: start + 1, to: end + 1, text };
}
```

网页照旧显示“L1–L27”和带行号的原文，也照旧能点进 VS Code，只是这些数字不再由人写。

说明.md 和组块阅读照 `云端/09` 第 5 节的 A 方案：函数表只写 `Cli.start` 这样的名字，教程页按名字去找。正文里要指代码时，写成“`Session.loop`（`Sessions.ts`）”。

### 2.3 一次性转换

281 块的 `title`、`body` 里都有 `Lxx–Lyy`。转换脚本的做法：

1. 按旧行号取当时那一行；
2. 用当时的源码（`git show 358e7fa:src7/Sessions.ts`）找出开头那一行里最短、又在全文唯一的一段，结尾同样处理；
3. 写进 `code.from`、`code.to`，删掉标题里的 `Lxx–Lyy` 和正文里的“### 代码原文”那一段。

拿不准的块标出来，交人工看。

### 2.4 最强的反对意见（方法 F）

- **“锚点也会坏。”** 会坏，但坏法不同。行号漂了不会报错，点过去落在别的函数上；锚点坏了会写“找不到开头：xxx”。错能被看见，才修得掉。
- **“`/**` 这种锚点不唯一。”** 开头取第一处，结尾从开头往后找，这就够了。真重复的，转换脚本会挑更长的一段。
- **“块的意思变了，锚点照样找得到。”** 对。锚点只管得住位置，管不住意思（`云端/09` 第 5.2 节也这么说）。但这样一来，改骨架时只需要想“意思变没变”，不用再机械地挪 101 行数字。

扫 `骨架逐行/*.json`、`plugins/*/说明.md`、`docs/组块阅读/*.md`：

- 见到 `L数字` 或 `.ts:数字` 就报；

```ts
  }
}
```

设置路径照同样的办法查：网页里 `path={['engine', …]}` 一出现就报；`['plugins', 'x', 'config', …]` 要在 `PLUGIN_FIELDS` 里。

### 4.2 为什么 lint 没挡住

- `eslint.config.mjs:8-20` 的 `structureRules` 只有 `no-nested-ternary`，不管单层三目，也不管 else、switch；
- `jmbots/require-blocks`（`:22-62`）甚至专门检查 else 分支有没有大括号（`:53-56`），等于默认了 else 可以写；
- `getSrc7Rules`（`:71-94`）先把 `structureRules` 并进去（`:73`），再把除 `src7Errors`（`:68`）以外的 error 全降成 warn。所以在 src7 里，连 `no-nested-ternary` 也只是警告。

### 4.3 改法

在 `eslint.config.mjs` 加一条自定义规则，挂在已有的 `jmbots` 插件下（`:159`）：

```js
/** 用户定的分支写法：不写 else、不用 switch、不用三目（CLAUDE.md「代码约定」）。 */
const flatBranches = {
  meta: {
    schema: [],
    messages: {
      else: '不写 else：每种情况一个 if，处理完就 return。',
      switch: '不用 switch：每种情况一个 if。',
      ternary: '不用三目：先用 if 算出来，放进有名字的变量。',
    },
  },
  create(context) {
    return {
      IfStatement(node) {
        //G 没有 else 的 if 不管。
        if (node.alternate === null) return;

        context.report({ node: node.alternate, messageId: 'else' });
      },
      SwitchStatement(node) {
        context.report({ node, messageId: 'switch' });
      },
      ConditionalExpression(node) {
        context.report({ node, messageId: 'ternary' });
      },
    };
  },
};
```

再把它加进 `src7Errors`，免得被降级：

```js
const src7Errors = ['preserve-caught-error', '@typescript-eslint/no-floating-promises', 'jmbots/flat-branches'];
```

- TS 的条件类型（`RequestEvent.ts:41-48` 的 `T extends U ? X : Y`）在语法树上是 `TSConditionalType`，不是 `ConditionalExpression`，不会被误报。
- 测试文件（`src7/tests/**`、`*.test.ts`）里的 else 和三目很多（`Cards_Test.ts:28`、`Batch1_Test.ts:27` 等）。推荐对测试关掉这条，用户读的是正文代码。
- 0.7.68 刚加的“长函数大块用等号框”也能半自动查：函数体超过 60 行，又一个 `//====` 都没有，就给警告。这条写起来约 15 行，可以等用户觉得有必要再加。

## 五、根因四：照字面改过了头

三件事的共同点：拿一条规矩或一个决定，套到了它本来不管的范围上。

| 事 | 版本 | 套过了头的地方 | 后来怎么定的 |
|---|---|---|---|
| 打码 | 0.7.10、0.7.12 运行时变量全打码；0.7.13 调试页撤掉；0.7.18 演示打码改默认关 | “不让外人看到隐私”被套到了用户自己看的调试页上 | CLAUDE.md 现在写明“防的是外人”“用户自己的界面一律不打码” |

| 左栏“正在做的事” | `e2d312a`（0.7.20～0.7.42 之间）给 `Api.progress(bot)` 加了 `if (!bot.trim()) return Promise.resolve([]);`；左栏调的是 `api.progress('')`，意思是“全部机器人”，从此什么都取不到；0.7.52（`90c084e`）才恢复 | 往内部函数里加了一个“防御性检查”，CLAUDE.md 第一条原则（“内部直接使用，不重复检查”）本来就不许这么做 | 0.7.52 把 `progress()` 改成不带参数，守卫删了 |

这一类自动检查很难做，只能靠规则。规则要写得具体，不写“要谨慎”：

- **删掉或收窄看得见的功能**：先挂决策图，写清“删哪几个按钮、哪几条路、留哪些”，用户点了再删。第一版用配置藏起来，第二版再删代码；
- **照一条规矩改东西之前**：在任务书或提交说明里写一句“它防的是谁、管到哪”，对不上就不套；
- **审代码时**：新出现的 `return []`、`return Promise.resolve([])`、`return undefined` 这类“空输入就返回空”的守卫，要问一句“空在这里是不是有意思的值”。

**最强的反对意见（方法 F）**：教程页那 53 条里有不少是用户看了以后自己提的新要求（0.7.59～0.7.61 的排法、展开方式），CLAUDE.md 也写着“边改边优化，不必死守用户或之前的说法”。这些是探索，不该算浪费，所以第 4 条只管“删除和收窄”。至于“骨架逐行 4 个小时改 7 版”，真正能省下来的是每版跟着挪的行号（根因一），版式本身的变化不在这一条里。

## 八、可以加进 CLAUDE.md 的规则（成稿）

照 CLAUDE.md 的口气写，每条一段，可以直接贴进“编码原则”或“代码约定”：

1. **代码的位置写锚点，不写行号、不抄原文**：说明.md、骨架逐行、组块阅读引用代码，写“文件 + 那一行里一定有的一段代码”（如 `Sessions.ts` 的 `async loop(`），行号和原文由教程插件现场算。行号会漂，锚点坏了会报“找不到”。云端报告、进度留底是快照，不在此列。
2. **改名两头清零**：改插件名、配置键、接口路径、事件名的那一版，全仓（含 `web/`）搜旧名，0 处才算改完。搬走的旧配置键，启动时报错写明搬到哪，不静默不读。
3. **能让机器查的规矩写进 lint**：新定一条代码写法，同一版在 `eslint.config.mjs` 加检查、设成 error；CLAUDE.md 只写一句为什么。
4. **删功能先挂决策图**：删掉或收窄用户看得见的功能，先在决策图写清删哪几样、留哪几样，用户点了再删；第一版用配置藏起来，下一版再删代码。照一条规矩改东西前，先写一句它防的是谁、管到哪。
5. **第二份就合**：写第二个同类的东西（第二个长列表、第二处等回执、第二个差不多的插件）之前，先把第一份改成公用的。
