## 一、根因一：一条线两把尺

### 1.1 820 量的是什么

`scripts/Check_Skeleton.ts` 是全仓唯一写着 820 的代码：

```ts
// scripts/Check_Skeleton.ts:5-7
/** 主线行数只计这四份源码。 */
const main = new Set(['Main.ts', 'Resources.ts', 'Sessions.ts', 'Tools.ts']);
const budget = 820;
```

- 它数的是“有语法 token 的行”，注释、JSDoc、空行都不算（`:11-42` 的 `countCode`）。
- `utils/` 单算一个数，不进主线（`:127-131`）。
- 超了只打印一句提醒，退出码照样是 0（`:186-188`）。上一版第 2.1 节说过，这次没改。

各提交的数（子代理用同样的规则复算，和版本说明里的 804、798 对得上）：

| 提交 | 主线合计（四个文件） | 其中 Sessions | Sessions 物理行 | SessionHelpers 物理行 | utils 代码行 |
|---|---|---|---|---|---|
| `ca03af3`（0.7.77）～`ecf6cf7`（0.7.80） | 804 | 368 | 922 | - | 1,161 |
| `92144f5`（0.7.81）～`d491cfa`（0.7.89） | 810 | 374 | 928 | - | 1,247 |
| `4e04a8e`（0.7.90）～`b2b478d` | 740 | 304 | 798 | 222 | 1,349～1,409 |

- 0.7.81 的版本说明写“严守骨架 820 行预算的前提下”给 Sessions 加留痕，用的是脚本的口径：810，没超。
- 0.7.90 写“Sessions.ts 从 928 行优雅瘦身回 798 行（回归 ≤820 硬红线）”（`Versions.json:57`），用的是物理行。可 Sessions 的物理行在 0.7.77 就已经是 922 了，那时脚本报的是 804，0.7.74 的说明还写着“进 820 预算内”（`Versions.json:202`）。同一个数字，两版用了两种量法。
- 搬去的 `utils/SessionHelpers.ts` 文件头写着“调用方只有 src7/Sessions.ts”（`:1-4`）。按 CLAUDE.md，骨架是 `src7/` 下 `plugins/` 以外的文件，所以它还是骨架。
- 搬完以后，Sessions 少了 70 行代码，SessionHelpers 有 102 行代码（我和子代理各算一遍，都是这个数；正负几行待核）。也就是说，骨架多了 32 行。整个骨架（`plugins/` 以外的 `.ts`，不算测试）的物理行，从 `ca03af3` 的 4,197 涨到 `b2b478d` 的 4,563。
- 这一搬的代价：0.7.90 改了 30 份文档和教程文件，其中 252 行只是数字变了，另外还有 DevMap、竖线全景的全部锚点。

### 1.2 同一类：量错了，修错了地方

CPU 读数：`programs/ResourceProbe.ts` 从 `3b654cf`（0.7.44 前后，资源守卫上线那版）起，把 `user+nice+sys+irq+idle` 加起来当总时长。可 Windows 的 `sys` 已经含了 `irq`，中断时间算了两遍，0.7.93 才修（`sumCpuTimes`，补了两个用例：`ResourceProbe.test.ts` 里“Windows 的 irq 已含在 sys 里不重复计”“Linux 的 irq 单独一栏要计入”）。中间隔了 47 版左右。

同一版，CPU 门槛按用户 #442/#444 整个关掉了。门槛老拦人，是不是因为读数不准？**待核**。如果是，用户关掉的是一道本来没问题的门（见“要用户定”第 3 件）。

两件事放在一起看：**量的人和定线的人用的不是同一把尺子，或者尺子本身就偏，后面的动作就全错了。**

### 1.3 改法

`Check_Skeleton.ts` 改三处：

```ts
/**
 * 主线行数计这几份：四个骨架模块，加上只给它们用的 utils（文件头写着“调用方只有 src7/…”的那种）。
 * 搬进 utils 不算瘦身。
 */
const main = new Set(['Main.ts', 'Resources.ts', 'Sessions.ts', 'Tools.ts', 'utils/SessionHelpers.ts']);

/** 主线预算，单位是 countCode 数出来的“有代码的行”，不是物理行。版本说明里的骨架行数照抄本脚本的输出。 */
const budget = 820;
```

```ts
//G 超预算不出包：先把东西挪进插件，再编版。
if (totals.main > budget) {
  console.error(`骨架主线 ${String(totals.main)} 行，超过 ${String(budget)} 行预算`);
  process.exit(1);
}
```

`Build_Src7.ts:251-257` 的检查步骤加一行（上一版第 2.3 节提过，这次只剩这一行没做）：

```ts
    step('骨架预算', ['scripts/Check_Skeleton.ts']);
```

- SessionHelpers 在 utils 那个数里照旧也会算一次，不影响。
- 加进主线以后是 842 行，构建会被挡住，所以要先定“要用户定”的第 1 件，再加这一行。

### 1.4 规则

**一条线只有一个脚本说了算。** 预算、上限、门槛，写明单位，由一个脚本量；文档、版本说明、任务书里的数字照抄脚本的输出，不另外数。量法有疑问，先改脚本，再动代码。

### 3.2 改法：`web/src/components/MountPage.tsx`

```tsx
/** 网页入口的统一壳：首帧写主题变量，套上换版防白屏和外网登录，挂到 #root。9 个 *Main.tsx 都走这里。 */
import * as reactDomClient from 'react-dom/client';
import type { ReactNode } from 'react';
import * as authGate from './AuthGate.tsx';
import * as chunkError from './ChunkErrorBoundary.tsx';
import * as theme from '../ThemePalette.ts';

/**
 * 挂一个页面。
 * @param page 页面根组件；要额外 Provider 的（主网页的 UiContext）自己包好再传进来。
 * 副作用：改 documentElement 的 CSS 变量，渲染进 #root。
 */
export function mountPage(page: ReactNode): void {
  //M 读用户选过的主题（没选过是深色），首帧写进根节点，免得闪白。
  const themeName = theme.loadThemeName(window.localStorage);
  const spec = theme.THEMES[themeName];
  theme.applyTheme(document.documentElement, spec);

  //G 页面里没有 #root 就不挂。
  const root = document.getElementById('root');
  if (root === null) return;

  const app = reactDomClient.createRoot(root);
  app.render(
    <chunkError.ChunkErrorBoundary>
      <authGate.AuthGate>{page}</authGate.AuthGate>
    </chunkError.ChunkErrorBoundary>,
  );
}
```
