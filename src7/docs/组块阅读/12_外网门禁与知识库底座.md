# 第十二块：外网门禁、frpc 隧道和知识库底座

读完这一块，你能说清楚：

1. 为什么在家（`127.0.0.1`）和内网虚拟机打开网页什么都不用登，从外网手机打开却先看到登录页；
2. 登录后那块 Cookie 是什么、能用多久、为什么脚本偷不走；
3. frpc 隧道为什么交给托盘自己管，jmbots 换版时外网不断；为什么 `30086` 的映射只能填 `192.168.200.1`；
4. 知识库的三张表、磁盘镜像、专题挂载各干什么，机器人怎么用 `kb_search` 查资料。

这一块不依赖骨架的新概念，只要知道第六块的“配置只校验一次”和第四块的“一问一答”（`requestEvent`）。行号对的是 0.7.82 的源码。

## 概念一：外网门禁——只拦带“外网头”的请求

**一句话**：阿里云上的 Nginx 给每个经它进来的请求加一个头 `X-External-Proxy: 1`。jmbots 的 http 插件只认这个头：有它、而且配置了 `web_auth`，就要先登录；没有它（家里、内网虚拟机直连），一切照旧，免登录、零打扰。

**代码里**：判定只有一行，`isExternalProxyRequest`（`src7/plugins/http/WebAuth.ts:103`）看这个头是不是 `'1'`。拦不拦在 `WebAuth.checkExternal`：

```ts
// src7/plugins/http/WebAuth.ts
347	    //G 未配 web_auth 或未带 X-External-Proxy: 1 时，不启用外网拦截，交回原有本机/内网逻辑。
348	    if (this.spec === undefined || !isExternalProxyRequest(request)) return 'not_external';
349	
350	    //M 携带有效签名 Cookie 时放行并标记已核验身份，手机/PC 无需额外传 ?token=。
351	    if (this.readAuthenticatedUser(request) !== undefined) return 'pass_verified';
352	
353	    //M 未登录时放行健康检查、登录状态/提交接口与全部前端静态资源，让浏览器加载出 React 登录页。
354	    if (!guarded || PUBLIC_API_ROUTES.has(route)) return 'pass_unverified';
355	
356	    //G 其余受保护接口一律返回 401，引导前端渲染 AuthGate 登录界面。
357	    await reply.code(401).send({ error: '请先登录', code: 'unauthorized' });
358	    return 'blocked';
```

“没登录也放行”的只有静态网页和四个接口（`PUBLIC_API_ROUTES`，`src7/plugins/http/WebAuth.ts:34`：健康检查、查登录状态、登录、退出），好让浏览器先把登录页加载出来。

它挂在 http 插件的总钩子 `check` 的最前面，比“本机免令牌”还先：

```ts
// src7/plugins/http/index.ts
427	    //G 外网代理（X-External-Proxy: 1）且配了 web_auth 时优先走会话 Cookie 鉴权；本机与内网无此头不受影响。
428	    const external = await this.webAuth.checkExternal(request, reply, route, guarded);
429	    if (external === 'blocked') return reply;

433	    }
434	    if (external === 'pass_unverified') return undefined;

437	    const local = this.isLocal(request);

440	      return undefined;
441	    }
```

还有一层保险：`isLocal`（`src7/plugins/http/index.ts:364`）看到外网头直接答“不是本机”。所以哪怕外网流量从本机地址进来，也不会被当成本机放行。

**前端**：网页外面套了一层 `AuthGate`（`web/src/components/AuthGate.tsx:108`，在 `web/src/Main.tsx:40` 包住整个应用）。它先问一次 `GET /api/auth/status`：`required: false` 就直接放行子页面；要登录又没登录，就显示深色登录页。

**类比**：医院大门的门卫。院内职工（家里、内网）走员工通道，不查证；从正门进来的（外网）先在门卫室登记、领一张 30 天的出入证。门卫只看“是不是走正门进来的”这一个标记。

## 概念二：出入证——30 天 `HttpOnly` Cookie

**一句话**：登录成功后，服务端签一张带 HMAC-SHA256 签名的 Cookie，30 天有效。`HttpOnly` 让网页脚本读不到它；经 HTTPS 进来时再加 `Secure`，只走加密连接。签名用的种子存在运行时 `data/` 里，主站重启、换版后 30 天内不用重登。

**代码里**：

```ts
// src7/plugins/http/WebAuth.ts
302	function formatSessionCookie(value: string, maxAge: number, secure: boolean): string {
303	  let cookie = `${SESSION_COOKIE_NAME}=${value}; HttpOnly; SameSite=Lax; Path=/; Max-Age=${String(maxAge)}`;
304	  if (secure) {
305	    cookie += '; Secure';
306	  }
307	  return cookie;
308	}
```

密码可以写 `password_scrypt`、`password_sha256` 或 `password` 三选一，比对一律用常量时间（`timingSafeEqual`）。同一个 IP 连错 10 次，冷却 60 秒，回 429。配置写在 `config.yaml` 的 `server.web_auth`（或 http 插件的 `web_auth`），不配就整个门禁不开。

**类比**：出入证上有防伪钢印（签名），证件夹在你兜里拿不出来给别人看（`HttpOnly`），只在正规通道刷（`Secure`）。

## 概念三：frpc 隧道——托盘自己保活，jmbots 只是遥控器

**一句话**：`frpc.exe` 把家里的 `30086` 映射到外网。它不是 jmbots 的子进程，由一个托盘脚本（`frpc-tray.ps1`，经 `start-tray.vbs` 无窗拉起）常驻看着。jmbots 的 frpc 插件只做遥控：看状态、启停、改映射、读日志，网页在 `/frpc/`。基地换 jmbots 版本时 jmbots 会退出，frpc 不跟着退，外网就不断。

**代码里**：插件拉起外部进程一律“分离、无窗、不等”：

```ts
// src7/plugins/frpc/Process.ts
309	function spawnDetachedHidden(command: string, args: string[], cwd: string): void {
310	  const child = childProcess.spawn(command, args, {
311	    cwd,
312	    windowsHide: true,
313	    detached: true,
314	    stdio: 'ignore',
315	  });
316	  child.on('error', () => undefined);
317	  child.unref();
318	}
```

`detached` 加 `unref`，jmbots 退出时这个进程照样活着。

**为什么 `30086` 只能填 `192.168.200.1`**：隧道如果连 `127.0.0.1:30086`，jmbots 看到的来源就是本机。概念一里的 `isLocal` 虽然认外网头，但万一有人绕过 Nginx 直连 frps 端口，请求不带外网头，又是本机来源，就会被当成主人直接放行。填局域网地址，来源就不是 `127.x`，拿不到“本机”的待遇。改映射时校验当场拒掉：主站端口（30086，或 `server.port` 改成的那个）只许填标准写法的非回环 IPv4（`isAllowedServerMapIp`，`src7/plugins/frpc/Toml.ts:377`），`::ffff:127.0.0.1`、`0x7f.0.0.1`、整数 IP 这些绕过写法一律拒：

```ts
// src7/plugins/frpc/Toml.ts
496	    //G 安全铁律：主站端口映射强制走严格 IPv4 非回环白名单，防止外网流量变成 isLocal 免登录请求。
497	    const unsafe = isUnsafeGuardedProxy(localIP, localPort, guardedPort);
498	    if (unsafe) {
499	      throw new failureModule.Failure(400, LOOPBACK_30086_ERROR);
500	    }
```

**改映射不丢密钥**：`PUT /api/frpc/proxies` 先把原文件备份成 `frpc.toml.bak`，再只替换 `[[proxies]]` 那几段，头部注释、`auth.token`、TLS、日志配置一个字不动（`rewriteFrpcTomlProxies`，`src7/plugins/frpc/Toml.ts:571`）：

```ts
// src7/plugins/frpc/index.ts
266	    //M 写入前先备份 frpc.toml.bak，再原子替换新内容，100% 保留头部注释与 token 配置。
267	    const originalToml = fs.readFileSync(tomlPath, 'utf8');
268	    const nextToml = tomlModule.rewriteFrpcTomlProxies(originalToml, proxies);
269	    const bakPath = path.join(dir, 'frpc.toml.bak');
270	    filesModule.writeTextAtomic(bakPath, originalToml, true);
271	    filesModule.writeTextAtomic(tomlPath, nextToml, false);
```

另外两样：状态接口从不返回 `auth.token` 明文，只给 `hasAuthToken`；读日志前先过一遍脱敏（`redactLogLine`，`src7/plugins/frpc/Toml.ts:694`）。所有写接口先过 `requireVerified`（`src7/plugins/frpc/index.ts:132`）：外网没登录的、远程没令牌的，一律 403。

**类比**：医院和外面之间有一条专用通道，由保安亭（托盘）看守。院长办公室（jmbots）有一个遥控面板，可以开关通道、改通道去向；但院长办公室搬家（换版）时，保安亭照常值班。通道的终点只能接到“正门”（局域网地址），不能接进员工通道（本机地址），不然外面的人会被当成职工。

## 概念四：知识库底座——三张表、一份镜像、一个工具

**一句话**：`knowledge` 插件把资料存进主库的三组表：目录 `kb_dirs`、文档 `kb_docs`、标签 `kb_tags` 加关联表 `kb_doc_tags`。每次改文档都导出一份到磁盘，方便人直接翻。文档可以挂到工作决策台的某个专题上（`topic_id`）。机器人用只读工具 `kb_search` 查。

**代码里**：建表语句在 `SCHEMA_SQL`（`src7/plugins/knowledge/Store.ts:24`）。`kb_dirs` 在第 25 行，`kb_docs` 在第 35 行，`kb_tags` 在第 51 行，`kb_doc_tags` 在第 57 行。插件入口很短：

几样要记住的：

- **删目录不删文档**：子目录上提到原来的父目录，目录里的文档变成“未归类”（`dir_id` 置空）。
- **磁盘镜像**：`DiskMirror.writeDoc`（`src7/plugins/knowledge/DiskMirror.ts:129`）写到 `<运行时>/knowledge/<日期>/<id>_<标题>/`，里面是 `content.md` 和 `meta.json`，原子写入。
- **搜索两路合一**：`GET /api/knowledge/search`（`src7/plugins/knowledge/Routes.ts:418`）先在本库按标题、别名、标签、摘要、正文加权查，再经 `searchMemoryBridge`（`src7/plugins/knowledge/Routes.ts:44`）发 `memory/request` 向记忆插件要片段。没挂 memory 就安静退回空结果，不报错：


- **模型工具**：`registerKbSearchTool`（`src7/plugins/knowledge/Tools.ts:64`）登记 `kb_search`，前台、后台都能用。不带条件给总览，带关键词、专题、标签或目录给摘要索引（有关键词时也顺带问一声记忆插件），带 `docId` 给全文。
- **别名与本地同步（1.2.0）**：文档可带别名，搜索、`[[双链]]`（唯一别名才连）和消歧接口 `kb_disambiguate` 都认它；`FolderSync.ts` 把配置的本机目录里的 `.md`、`.txt` 只读导进来，按路径和内容哈希去重，细节见 `src7/plugins/knowledge/说明.md`。
- 写接口（建、改、删）都要 `isVerified`，没核验回 403；读接口不拦。

**类比**：医院档案室。档案柜（目录）、病历（文档）、彩色标签（标签）；每份病历还复印一份放在走廊书架上（磁盘镜像），谁都能翻。医生（机器人）查档案用前台的查询机（`kb_search`），只能看、不能改；查询机顺便问一声隔壁的“记忆科”有没有相关记录，那边不在也不耽误。

## 常见踩坑和可以理顺的地方

1. **知识库的建表方式**。早期版本曾在 `apply` 里经 `ctx.get('db')` 迁一次、又在 `KnowledgeStore` 构造时 `db.exec(SCHEMA_SQL)` 建一次；现已删去前者，统一由 `KnowledgeStore` 构造函数幂等建表（`src7/plugins/knowledge/Store.ts`）。将来如需演进列结构，再统一接入迁移账本。
2. **知识库搜记忆时掐了 4 秒表**（`src7/plugins/knowledge/Routes.ts:57`）。项目从 0.7.73 起的约定是“本机一问一答不掐表、只报警，走网络的那层自己限时”。memory 是本机插件，它背后的记忆服务要是真慢，应该由 memory 自己限时。这里要不要留，请定一下。
3. **frpc 有两处带“这台机器”的痕迹**。默认目录是从运行时目录往上数两级、三级去猜 works/frp-clients/windows 这个目录（`src7/plugins/frpc/index.ts:97–100`）；开机自启文件名写死成 `LeonFRPS-Tray.vbs`（`src7/plugins/frpc/Process.ts:81`）。将来给别人用，前者应该要求在配置里写 `dir`，后者改成不带人名的文件名。

## 读完自测

1. 你在家用浏览器开 `http://127.0.0.1:30086/`，和在外面用手机开公网域名，http 插件各走 `check` 的哪一条路？
2. 登录后的 Cookie 为什么能防脚本偷？jmbots 换版重启后手机要不要重新登录？
3. 有人在 `/frpc/` 页面把 `30086` 的映射改成 `127.0.0.1`，会发生什么？为什么要这样拦？
4. 机器人在对话里调 `kb_search` 搜“论文”，结果从哪几处来？memory 插件没挂时会报错吗？

<details>
<summary>答案</summary>

1. 家里：没有外网头，`checkExternal` 回 `not_external`，接着 `isLocal` 认出本机，直接放行并算已核验。手机：Nginx 加了外网头；没 Cookie 时访问 `/api/` 回 401，前端 `AuthGate` 显示登录页；登录后带 Cookie，回 `pass_verified` 放行。
2. `HttpOnly` 让网页里的脚本读不到这个 Cookie，只有浏览器发请求时自动带上。签名种子存在运行时 `data/` 里，换版不变，30 天内不用重登。
3. `PUT /api/frpc/proxies` 校验时直接回 400，提示改填 `192.168.200.1`，文件不动。如果连的是本机地址，绕过 Nginx 的请求不带外网头，又是本机来源，会被当成主人放行，门禁就形同虚设。
4. 两处：先 `searchLocal` 查本库的标题、标签、摘要、正文；有关键词时再经 `searchMemoryBridge` 问记忆插件的公共知识库，最多补 4 条，前面标 `M1.`、`M2.`（`src7/plugins/knowledge/Tools.ts:147`）。memory 没挂时 `requestEvent` 回“没人接”（`unhandled`），只返回本库结果，不报错。

</details>
