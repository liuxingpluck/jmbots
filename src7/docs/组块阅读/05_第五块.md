# 第五块：把关和审批

读完这一块，你能说清楚：会话每一步有哪四个关口，插件怎么在关口上“不让做”；`deny`（只拦这一个）和 `stop`（这一轮停下）有什么区别；外人（群里的朋友、客户）怎么被限制只能用一部分工具；以及一条命令要执行，怎么经过“程序规则 → 决策模型 → 审核小会话 → 问用户”四档，最后用户点头才跑。

只讲 5 个概念。要先懂第一块的“挨个问（`ctx.serial`）”、第三块的 `approval/request` ↔ `approval/result` 一问一答，和第四块的小会话。

## 概念一：四个关口——每一步的四个“检查站”

**一句话**：会话循环每一步有四个位置，骨架会在那里停下来，把当前数据交给插件挨个看（`ctx.serial`，照插件挂上去的先后一个个 `await`），看完才往下走：

| 关口 | 事件 | 位置 | 能做什么 |
|---|---|---|---|
| 一 | `session/request` | 调模型之前 | 改提示词、改工具清单、改对话 |
| 二 | `session/after-model` | 模型回来、回答接进对话之前 | 改回答 |
| 三 | `session/before-tool` | 执行一个工具之前 | `deny` 拦这一个 |
| 四 | `session/after-tool` | 工具执行完、结果接进对话之前 | 改结果 |

四个关口的数据都带 `session` 和 `stop?`（`SessionGate`，`Sessions.ts:138` 起）。监听函数不许有返回值：有了返回值，Cordis 就不再问后面的人了。

**代码里**：发关口的四处

```ts
552	      await this.ctx.serial('session/request', request);
584	      await this.ctx.serial('session/after-model', answered);
614	        await this.ctx.serial('session/after-tool', done);
```

第三个关口在 `src7/Tools.ts`（因为是执行工具的地方）：

```ts
147	    await this.ctx.serial('session/before-tool', gate);
```

**类比**：机场安检，一个旅客要过四个检查站：进候机楼前、登机前、上传送带前、行李出来后。每个检查站的工作人员一个接一个看，谁都可以拦。

## 概念二：`deny` 和 `stop`——拦一个，还是整轮停

**一句话**：在关口上写两种“不让”：

- `gate.deny = '理由'`（只有关口三有）：只不让执行**这一个工具**，理由当成工具结果给模型看（“未执行：……”），会话接着走，模型可以换个办法。
- `xxx.stop = '理由'`（四个关口都有）：整场这一轮停在这里。骨架调 `session.stop(理由)`，状态变成 `stopped`，不往下走，理由写进 `reply`。

**代码里**：`src7/Tools.ts` 的 `execute`

```ts
150	    if (gate.stop !== undefined) {
151	      session.stop(gate.stop);
152	      return { text: `未执行：${gate.stop}`, isError: true };
153	    }

156	    if (gate.deny !== undefined) return { text: `未执行：${gate.deny}`, isError: true };
```

`stop` 先判、`deny` 后判。关口一、二、四的 `stop` 在 `Sessions.ts:556`、`588`、`636`。

要注意两点：第一，关口二写了 `stop`，这次回答连同里面要的工具都不要了；关口四写了 `stop`，结果仍然会接进对话（要和工具调用配对），但这一批后面的工具不再执行。第二，现在代码里**实际在用的是 `deny`**（`approval` 的把关），`stop` 是预留给“整轮要停”的插件的（我在 `src7/` 里搜了 `gate.stop =`、`request.stop =`、`done.stop =`，没找到插件在写）。

**类比**：安检员发现你带了打火机，有两种处理：只没收打火机、让你继续登机（`deny`）；或者把你整个人拦下来不让登机（`stop`）。

## 概念三：外人只能用一部分工具——两道防线

**一句话**：群里的朋友、客户（回话地址里 `role` 是 `guest` 或 `builder`）不能拿本人的全部能力。`approval` 插件在两个关口上限制他们：

1. **关口一（`session/request`）**：把这一档用不到的工具从工具清单里拿掉，模型根本看不到；
2. **关口三（`session/before-tool`）**：兜底。工具清单是这一步开头定的，会话转到一半换了说话人时，执行前再按现在的说话人检查一遍，不在名单里的 `deny`。

## 概念四：命令审批的四档——一档比一档慢，一档比一档贵

**一句话**：模型要在用户电脑上执行一条命令（`exec` 工具），不是直接跑，先审。`Approval.review` 按四档往下走，**哪一档能定，就在哪一档结束**：

1. **程序规则**（最快，不花钱）：碰了密钥文件直接拒绝；项目自己的检查（如 `typecheck`）直接放行；执行目录和命令里的路径都在“可信目录”里直接放行；删系统文件、删注册表这类必问（`mustAsk`）的直接跳到第四档；
2. **决策模型**：发请求事件 `decision/judge`，只用来放行“只读、低风险”的；拿不准往下走。20 秒不回当拿不准；
3. **审核小会话**：开一场不带工具的小会话（`kind: exec-review`，第四块），让模型看命令、目录、脚本内容，只回一段 JSON，`safe: true` 才放行；
4. **问用户**：拼一张卡片（要做什么 / 动哪些 / 为什么问你），登记成“待确认”，**不等**，马上交回“已经去问了”。

**类比**：公司报销。金额小的、规定好能报的，财务系统自动过（规则）；中等的先让部门助理看一眼（决策模型、审核小会话）；金额大、或者助理拿不准的，才送到老板桌上签字（问用户）。

## 概念五：`approval/request` ↔ `approval/result` 和“用户定了”的回头通知

**一句话**：`exec` 插件自己不审命令，它发请求事件 `approval/request`（`action: 'review'`），等回执 `approval/result`，这正是第三块的一问一答。**没人接、超时（65 秒）、会话喊停、出错，一律当拒绝**：没有审核就不让跑命令。

`exec` 拿到结论后怎么办（`src7/plugins/exec/index.ts`，`onTool`）：

- `reject`：回给模型“未执行：原因”；
- `asked`：回“已提交给用户确认，还没执行”，模型先别等，做别的；

“问用户”这条路是**异步**的：`approval` 把待确认写进库（`approval_pending` 表），发通知 `approval/asked`；用户点同意或说“同意 3”后，`decide` 改表、发通知 `approval/decided`（`index.ts:692`）。`approval` 自己**不执行任何东西**，谁提的谁听 `approval/decided`：`exec` 的 `onDecided`（`exec/index.ts:307` 起）同意就真跑，把结果当成一句新的话塞回那场会话、推它再转一轮；拒绝就告诉它“没执行”。

**类比**：把一张单子放进老板的待办箱。你不站在旁边等；老板签了字，单子自己回到你桌上，你按签的结果办。

## 读完自测

1. 一个插件想“这个工具这一次不让执行，但让模型换个办法”，该写 `deny` 还是 `stop`？写在哪个事件上？模型会看到什么？
2. 群里的朋友说话的这一轮，为什么既要在 `session/request` 里拿掉工具，又要在 `session/before-tool` 里再拦一次？
3. 命令审批的四档里，哪一种命令永远不会被决策模型或审核小会话直接放行？审核服务没启动（没人接 `approval/request`）时，命令会怎样？

<details>
<summary>答案</summary>

1. 写 `gate.deny`，在 `session/before-tool` 上。`Tools.execute` 会回 `未执行：<理由>`（`isError: true`），会话接着走，模型据此换办法（`Tools.ts:156`）。写 `stop` 会整轮停下。
2. 工具清单是这一步开头定的；群里换了说话人时，同一场会话转到一半，清单还是旧的。所以执行前要再按“现在”的说话人检查一次（兜底，`index.ts:408` 注释；`index.ts:409` 起）。
3. 命中 `mustAsk` 的（删系统级文件或目录、删注册表、删数据、格式化），直接跳到第四档问用户（`index.ts:459` 起；审核小会话即使 `safe` 也要 `danger === undefined` 才放行，第 510 行）。没人接 `approval/request`：`requestEvent` 立刻走 `onFallback('unhandled')`，`getRejected` 回拒绝，“没有审核就不跑命令”（`Runs.ts:108–114`）。
