# 第五块：把关和审批

读完这一块，你能说清楚：插件怎么在关口上“不让做”；`deny`（只拦这一个）和 `stop`（这一轮停下）有什么区别；外人（群里的朋友、客户）怎么被限制只能用一部分工具；以及一条命令要执行，怎么经过“程序规则 → 决策模型 → 审核小会话 → 问用户”四档，最后用户点头才跑。

只讲 4 个新概念。要先懂第一块的“挨个问（`ctx.serial`）”和四个关口、第三块的小会话、第四块的一问一答（这里用的是 `approval/request` ↔ `approval/result`）。

> **先回顾（不算新概念）**：会话循环每一步有四个关口，骨架会在那里停下来，把当前数据交给插件挨个看（照插件挂上去的先后一个个 `await`），看完才往下走。第一块概念三讲过它们在哪几行。
>
> | 关口 | 事件 | 位置 | 能做什么 | 看诊里 |
> |---|---|---|---|---|
> | 一 | `session/before-model` | 调模型之前 | 改提示词、改工具清单、改对话 | 问医生之前（护士先整理病历、补一句过敏史） |
> | 二 | `session/after-model` | 模型回来、回答接进对话之前 | 改回答 | 医生说完之后、记进病历之前 |
> | 三 | `session/before-tool` | 执行一个工具之前 | `deny` 拦这一个 | 做检查之前 |
> | 四 | `session/after-tool` | 工具执行完、结果接进对话之前 | 改结果 | 检查结果出来、交回医生之前 |
>
> 四个关口的数据都带 `session` 和 `stop?`（`SessionGate`，`Sessions.ts:161` 起）。监听函数不许有返回值：有了返回值，Cordis 就不再问后面的人了。

## 概念一：`deny` 和 `stop`——拦一个，还是整轮停

**一句话**：在关口上写两种“不让”：

- `gate.deny = '理由'`（只有关口三有）：只不让执行**这一个工具**，理由当成工具结果给模型看（“未执行：……”），会话接着走，模型可以换个办法。
- `xxx.stop = '理由'`（四个关口都有）：整场这一轮停在这里。骨架调 `session.stop(理由)`，状态变成 `stopped`，不往下走，理由写进 `reply`。

**代码里**：`src7/Tools.ts` 的 `execute`

```ts
// src7/Tools.ts
194	    if (gate.stop !== undefined) {
195	      session.stop(gate.stop);
196	      return { text: `未执行：${gate.stop}`, isError: true };
197	    }
198	
199	    //G 有插件不让执行这一个 → 理由给模型看，会话接着走。
200	    if (gate.deny !== undefined) return { text: `未执行：${gate.deny}`, isError: true };
```

`stop` 先判、`deny` 后判。关口一、二、四的 `stop` 在 `Sessions.ts:693`、`725`、`638`。

要注意两点：第一，关口二写了 `stop`，这次回答连同里面要的工具都不要了；关口四写了 `stop`，结果仍然会接进对话（要和工具调用配对），但这一批后面的工具不再执行。第二，现在代码里**实际在用的是 `deny`**（`approval` 的把关），`stop` 是预留给“整轮要停”的插件的（11-19 搜过：只有测试 `src7/tests/Session_Gates.test.ts`、`src7/plugins/screen/Screen.test.ts` 在写）。

**类比**：做检查之前，发现这项检查不能做（`deny`），医生换一项接着看；或者今天这次看诊到此为止（`stop`）。

## 概念二：外人只能用一部分工具——两道防线

**一句话**：群里的朋友、客户（回话地址里 `role` 是 `guest` 或 `builder`）不能拿本人的全部能力。`approval` 插件在两个关口上限制他们：

1. **关口一（`session/before-model`）**：把这一档用不到的工具从工具清单里拿掉，模型根本看不到；
2. **关口三（`session/before-tool`）**：兜底。工具清单是这一步开头定的，会话转到一半换了说话人时，执行前再按现在的说话人检查一遍，不在名单里的 `deny`。

**类比**：探视的人只能进病房和大厅；会话中途换了人，每扇门口再刷一次证（兜底那一道）。

## 概念三：命令审批的四档——一档比一档慢，一档比一档贵

**一句话**：模型要在用户电脑上执行一条命令（`exec` 工具），不是直接跑，先审。`Approval.review` 按四档往下走，**哪一档能定，就在哪一档结束**：

1. **程序规则**（最快，不花钱）：碰了密钥文件直接拒绝；项目自己的检查（如 `typecheck`）直接放行；执行目录和命令里的路径都在“可信目录”里直接放行；删系统文件、删注册表这类必问（`mustAsk`）的：不看可信目录、不问决策模型；审核小会话照样开，但只用它写卡片上的“要做什么、风险在哪”，它说安全也不放行，最后一定问用户；
2. **决策模型**：发请求事件 `decision/judge`，只用来放行“只读、低风险”的；拿不准往下走（decision 每个模型自己限时，等满 20 秒只报警，`DECISION_WARN_MS`，第 60 行）；
3. **审核小会话**：开一场不带工具的小会话（`kind: exec-review`，第三块），让模型看命令、目录、脚本内容，只回一段 JSON，`safe: true` 才放行；
4. **问用户**：拼一张卡片（要做什么 / 动哪些 / 为什么问你），登记成“待确认”，**不等**，马上交回“已经去问了”。

## 概念四：`approval/request` ↔ `approval/result` 和“用户定了”的回头通知

**一句话**：`exec` 插件自己不审命令，它发请求事件 `approval/request`（`action: 'review'`），等回执 `approval/result`，这正是第四块的一问一答。**没人接、超时（65 秒）、会话喊停、出错，一律当拒绝**：没有审核就不让跑命令。

`exec` 拿到结论后怎么办（`src7/plugins/exec/index.ts`，`onTool`）：

- `reject`：回给模型“未执行：原因”；
- `asked`：回“已提交给用户确认，还没执行”，模型先别等，做别的；
- `pass`：真去跑。

“问用户”这条路是**异步**的：`approval` 把待确认写进库（`approval_pending` 表），发通知 `approval/asked`；用户点同意或说“同意 3”后，`decide`（`index.ts:814`）改表、发通知 `approval/decided`（第 991 行）。`approval` 自己**不执行任何东西**，谁提的谁听 `approval/decided`：`exec` 的 `onDecided`（`exec/index.ts:312` 起）同意就真跑，把结果当成一句新的话塞回那场会话、推它再转一轮；拒绝就告诉它“没执行”。

注意：一问一答的退回本来只是提问方不等了（第四块概念四）。命令审批多做了一步：exec 把一个自己的停止信号一起交给审批（`Runs.ts` 第 84–97 行），没拿到结论时就用它叫停审批那边（第 107 行）；审批在审核小会话回来后、登记待确认后各看一次这个信号（`approval/index.ts` 第 642–644 行、第 670–675 行），已经截止的不放行、不弹卡片，已经登记的那张作废。所以超时拒绝以后，命令不会再因为用户点了同意而跑。

**类比**：知情同意书放到病人床头，医生不站着等；病人签了，单子回到医生手里，医生照签的结果办。

## 读完自测

1. 一个插件想“这个工具这一次不让执行，但让模型换个办法”，该写 `deny` 还是 `stop`？写在哪个事件上？模型会看到什么？
2. 群里的朋友说话的这一轮，为什么既要在 `session/before-model` 里拿掉工具，又要在 `session/before-tool` 里再拦一次？
3. 命令审批的四档里，哪一种命令永远不会被决策模型或审核小会话直接放行？审核服务没启动（没人接 `approval/request`）时，命令会怎样？

<details>
<summary>答案</summary>

1. 写 `gate.deny`，在 `session/before-tool` 上。`Tools.execute` 会回 `未执行：<理由>`（`isError: true`），会话接着走，模型据此换办法（`Tools.ts:200`）。写 `stop` 会整轮停下。
2. 工具清单是这一步开头定的；群里换了说话人时，同一场会话转到一半，清单还是旧的。所以执行前要再按“现在”的说话人检查一次（兜底，`index.ts:506` 注释；`index.ts:477` 起）。
3. 命中 `mustAsk` 的（删系统级文件或目录、删注册表、删数据、格式化）：跳过可信目录和决策模型（`index.ts:572、614`），审核小会话照开但不能放行（第 646 行），最后到第四档问用户（第 667–677 行）。没人接 `approval/request`：`requestEvent` 立刻返回 `why: 'unhandled'`，`requestReview` 回拒绝，“没有审核就不跑命令”（`Runs.ts:105–115`）。
