# 第八块：工作决策工作台（分主题看进度、直达中控、30 秒无感刷新）

读完这一篇，你能讲清三件事：

1. 在 `/work-decision/`（特别是手机竖屏出门在外时）怎么**分主题看进度、一键拍板**，同时保留全局思维导图总览；
2. 页面上的**常驻输入框**怎么带着子主题上下文直达中控（走同源 `relay` 收件与回信回显），并且怎么保证刷新或切视图**绝不丢草稿**；
3. 为什么不用 SSE / WebSocket 长连接，而用**每 30 秒一次约 50 字节的普通 `GET` 探针**完成无感数据合并与安全换版提醒。

---

## 一、双视图：专题目录看细节，思维导图看全局

工作台（页面代码在 `web/src/DecisionMap/`，后端插件在 `src7/plugins/work-decision/`）把同一棵工作区决策树做成互补的两类看法：

| 看法 | 适合什么时候用 | 界面怎么摆 |
|---|---|---|
| **专题目录**（默认） | 手机竖屏出门看进度、逐个专题拍板、查子任务进展 | **桌面三栏**：左栏顶层子主题目录树（如 AOBB、微信插件、前端精简）｜中栏专题阅读区｜右栏常驻直达中控。<br>**手机竖屏单栏**：顶部专题切换条与抽屉菜单 → 中间单栏顺畅滚动 → 底部悬浮直达中控输入栏 |
| **思维导图 / 按日期 / 放射 / 表格 / 清单** | 在大屏俯瞰整棵目标树的主线、依赖与先后关系 | 中间画布（支持「只看这棵子树」聚焦），右侧（手机底部）同样挂着常驻直达中控输入栏；点任意节点还能点「进专题」一键跳进对应专题 |

点进任一子主题后，中栏按从重到轻排成三段：

1. **专题背景说明**：展示这个子主题的一句话背景（`summary`）、Markdown 正文（`body`）和关联出处。
2. **待拍板置顶区**：只要本专题下还有待你定的问题（`pending + open`），一律置顶红框醒目列出。直接点选项就能拍板；如果输入框里先写了一句补充说明再点选项，说明和选项会一并发给中控。
3. **四态子任务清单**：本专题下的子任务统一按 **`待拍板` / `进行中` / `已定` / `已完成`** 四种状态挂徽章，顶部可按四态一键筛选；点开任一子项即可改状态、加子项，或把输入框锁定到该子项。

## 二、常驻输入框：直达中控（走 `relay` 自动收发回显）+ 草稿永不丢

无论在「专题目录」还是「思维导图」总览，页面都带着一个常驻的**直达中控输入框**（`web/src/DecisionMap/Composer.tsx`）：

1. **自动挂上下文胶囊**：
   - 胶囊明确写出 `发往：<目标标题>`。
   - 没单点具体子任务时，自动挂在**当前子主题根节点**（总览页挂在项目根节点）；点了某个子任务或某条留言上的 `@节点名` 标签，胶囊立刻切过去；点 `× 回本专题` 一键退回本专题根。
2. **同源 `relay` 闭环收发与原位回显**：
   - 点「发给中控」复用 `POST /api/work-decision/note`：留言先原子写入 `decision_notes` 表（状态显示 `等中控回`），再由 `work-decision` 发 `work-decision/note` 事件投进同源 `relay` 收件箱唤醒中控。
   - 中控处理完运行 `Decision_Map.mjs reply` 或经 `relay` 回信时，回话写回同一节点的 `notes`，原留言自动变成 `中控已回`，中控的回复紧跟在下方往来留言流里展示，形成完整闭环。
3. **按节点 `localStorage` 草稿持久化**（`web/src/DecisionMap/Drafts.ts`）：
   - 你每打一个字，都会按节点号实时存进浏览器的 `jmbots.decision-map.drafts`。
   - 中途切去别的子主题、切去思维导图、关掉节点侧栏、甚至关掉网页重新打开，回到这个节点时刚打了一半的话原封不动还在；只有服务端确认发送成功才会清空该节点的草稿。

## 三、30 秒无感自动刷新：只用普通 `GET`，不用长连接

手机切后台、走移动网络或过反向代理时，SSE / WebSocket 长连接容易假死、重连耗电。工作台统一采用极简的普通 `GET` 探针闭环：

1. **后端轻量版本探针**：`GET /api/work-decision/version`（`src7/plugins/work-decision/Routes.ts`）只返回两个数字，约 50 字节：
   - `appStartedAt`：当前后端路由挂载时刻（毫秒时间戳），只有后端换版重启才会变；
   - `dataRev`：工作决策库的最新变化序号，中控改了节点、回了话或确认收到时递增。
2. **前端触发时机**（`web/src/DecisionMap/DecisionMapPage.tsx`）：
   - 页面在前台可见时**每 30 秒**发一次 `GET /api/work-decision/version`；
   - 手机从锁屏或别的 App **切回前台**（`visibilitychange`）时立即检查一次；
   - 顶栏右侧随时可点 **「刷新」** 按钮立即同步。
3. **分级无感更新**：
   - **只有 `dataRev` 变了**（中控更新了进度或刚回了你的话）：前端静默拉一次 `/api/work-decision/graph` 在内存里合并节点和留言——**不整页刷新、不清空任何草稿、绝不抢走你正在打字的输入框焦点**。
   - **`appStartedAt` 变了**（后台刚部署了新版本）：如果当前页面空闲且没有任何未发草稿，自动刷新换上新前端；如果你正在输入框打字或还有未发草稿，**绝不强行刷新**，只在顶栏亮起温和提示条 **「有新版本，发完点此刷新」**，等你发完点一下再刷新（就算直接点，草稿也存在 `localStorage` 里不会丢）。

## 自测：三句话核对闭环

1. 出门在手机打开 `/work-decision/`，先看到哪个看法？怎么看清还剩几件事要拍板？（默认进「专题目录」，看顶部专题条的 `★` 数字和专题内的「待拍板置顶区」。）
2. 在子主题里打了一半字切去思维导图，或者后台中控刚回了一条留言，你正在打的字会丢吗？（不会：草稿按节点存在 `localStorage`，30 秒探针发现 `dataRev` 变化只做内存静默合并，不动输入框。）
3. 后台刚换版重启（`appStartedAt` 变了），而你手里还有半句草稿没发，页面会怎么处理？（不自动整页刷新，顶栏显示「有新版本，发完点此刷新」，等你发完自己点。）
