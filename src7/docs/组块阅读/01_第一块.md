# 第一块：骨架怎么转起来

读完这一块，你能说清楚：程序启动时先挂哪三样、插件怎么接进来，一场会话怎么一步步“调模型 → 执行工具”转下去，插件在哪几个地方插手。

只讲 4 个概念。别的（渠道、机器人、前台、审批、插件之间一问一答）都在后面几块，这一块先不管。

这 6 块的类比是同一条线：**看诊**。一场会话是一次就诊，后面几块会接着往下用（对照表在 `00_总览.md`）。

## 概念一：骨架和插件

**一句话**：骨架只有三样服务——资源、工具、会话，只管“一场会话怎么跑”；机器人、渠道、提示词这些全是插件，照 `config.yaml` 的 `plugins` 段一个个挂上去。

**代码里**：`src7/Main.ts` 的 `main`



渠道协议不在骨架里，在 `src7/plugins/channels/`。它是个不挂服务的协议插件：不进自带名单、不跑，写着事件名、标准消息格式和几个纯函数，渠道插件和 bots 都直接 import 它。第二块细讲。

一个插件就是导出 `name`、`inject`、`apply` 三样，比如 `src7/plugins/fake-model/index.ts`：

```ts

```

**类比**：骨架是医院的楼、挂号系统和病历室；插件是一个个科室。医院不管科室具体看什么病，只按名单（`config.yaml`）把科室安排进来。

## 概念二：会话 = 一份记录 + 一个循环

**一句话**：一场会话就是一份记录（`SessionRow`：会话号、种类、模型、状态、回话、整场对话），加上一个循环：调一次模型，模型要工具就执行，结果接进对话，再调模型，直到模型不再要工具。

```ts

757	      if (calls.length === 0) {
```

插件把话交给会话只要两步：`Session.queueUserMessage(text)` 再 `Session.run()`（都在 `Sessions.ts` 的 `Session` 里）。会话正在转时再 `queueUserMessage`，话先放在 `inbox` 里，下一步开头才接进对话（`loop` 开头那几行）。第二块的前台队列是 bots 在这之外又排的一层。每接一条话、每改一次状态都存库（`Session.save`）。

**类比**：会话就是一次就诊：病历加上看诊流程。病历记着病人是谁、说过什么；看诊就是“问医生 → 医生开检查 → 拿结果回来再问医生”，直到医生说“好了”。

## 概念三：事件分两种——挨个问和通知

**一句话**：骨架在会话循环里留了四个“关口”，用“挨个问”（`ctx.serial`）把同一份数据依次交给每个插件，插件可以改它、拦它、写 `stop` 叫停；别的地方只“通知”（`ctx.emit`），告诉大家发生了什么，不等、不许改流程。

“挨个问”是按监听注册的先后逐个 await：先挂的插件先被问，返回第一个不是 undefined、null、false 的值就停，后面的不再问；插件按 config.yaml 的先后挂，所以问的先后就是配置里的先后。源码在 node_modules/cordis/lib/index.js 第 754–760 行（serial）和第 692–694 行（isBailed）。

**代码里**：四个关口

```ts
// src7/Sessions.ts
813	      await this.ctx.serial('session/before-model', request);
```

（`Sessions.ts:813` 调模型前；`Sessions.ts:844` `session/after-model` 模型回来后；`Tools.ts:187` `session/before-tool` 执行工具前；`Sessions.ts:769` `session/after-tool` 工具执行后）

```ts
// src7/Sessions.ts
```


**类比**：挨个问像病历在科室之间传阅签字，每个科室都能补一笔、能批“不行”，后一个科室看得到前一个写了什么；通知像院内广播，“3 号诊室看完了”，说完就完，没人需要回话。

## 概念四：工具——登记、报清单、执行

**一句话**：插件用 `ctx.tools.register` 登记工具，写明给哪几种会话（`kinds`）用；会话每一步按自己的种类拿清单给模型看；模型点名要哪个，`Tools.execute` 先过关口、再校验参数、再执行，出错也不往外抛，而是当成结果交给模型。

## 读完自测

1. 启动时为什么骨架三样要“挂一个等一个”，先后不能换？
2. 一场会话这一轮什么时候算做完？还有哪几种情况会提前结束？
3. 一个插件想在每次调模型前往系统提示词里加一句话，该听哪个事件？为什么不能用通知？

<details>
<summary>答案</summary>

1. 后面的要用前面的：`Sessions` 声明了 `static inject = ['resources', 'tools']`（`Sessions.ts:249`），建表要用 `resources.db`，每一步要用 `tools.listToolsForSessionKind`。所以先资源、再工具、最后会话（`Main.ts:85–87`）。
2. 模型的回答里没有工具调用时，这一轮就做完了，状态改成 `done`，最后那句话存进 `row.reply`（`Sessions.ts:602–605`）。提前结束的有三种：有人喊停（`session.stop`）、某个关口上有插件写了 `stop`，这两种状态是 `stopped`；模型请求出错，状态是 `failed`。
3. 听 `session/before-model`，往 `request.system` 里 push。它是“挨个问”（`ctx.serial`），骨架会等每个插件改完才去调模型；通知（`ctx.emit`）不等，改了也来不及、而且不许靠它改流程。

</details>
