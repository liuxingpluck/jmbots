# 骨架组块阅读：总览

人一次只记得住 3～5 样东西，所以拆成 7 块，每块只讲 4～5 个新概念：前 6 块讲骨架，第 7 块讲进程插件。读懂一块再读下一块。每块一份文件，开头说读完能讲清什么，结尾有自测题。

| 块 | 标题 | 概念 |
|---|---|---|
| 1 | 骨架怎么转起来 | 骨架和插件；会话 = 一份记录 + 一个循环；事件分两种：挨个问和通知；工具：登记、报清单、执行 |
| 2 | 一条消息从渠道进来、回到渠道 | `channel/direct`、`channel/mention`、`channel/listen`（渠道经 `emitInbound` 发）；机器人认领和 `bot/receive` 的截走 / 改道；前台会话；回复和回执（`channel/reply` ↔ `channel/replied`） |
| 3 | 前台、后台和小会话 | 会话种类 `kind`；派后台；小会话 `sessions.ask`；喊停 `stop` |
| 4 | 插件之间一问一答 | 请求事件和回执事件；`requestId` 配对；`handled` 接单；退回（没人接、超时、中止、出错）；`requestEvent` / `onRequestEvent` |
| 5 | 把关和审批 | （先回顾四个关口）`gate.deny` 和 `stop`；外人两道防线；命令审批四档；`approval/request` ↔ `approval/result` 和回头通知 |
| 6 | 资源、存库和看路 | `config.yaml` 只校验一次；`ctx.resources.raw`；`sessions` 表；跟踪点 `trace`（打印、记库、泳道图） |
| 7 | 进程插件 | 为什么不装进主进程；`programs` 拉起、认人、看住、重启、请它退出；主程序调它；它带密钥回调主程序；只发二进制防破解（实例：外置微信） |
| 8 | 工作决策工作台 | `/work-decision/` 专题目录与总览导图双视图（4 态子任务 + 待拍板置顶）；常驻输入框直达中控（经 `relay` 收发回显 + `localStorage` 草稿防丢）；每 30 秒普通 `GET` 探针无感刷新 |
| 9 | 渠道插件全家桶 | `channels` 总接线板；`feishu` 私聊/群三档 `listen`/`judge_helper`/发件箱；`wechat` 客服与外置进程边界；`relay` 前缀与决策页留言闭环 |
| 10 | 机器人插件 `bots` | 多机器人配置隔离；认领去重 `claimKey`；群三模式与攒批小会话；前台派后台与 `DispatchResults` / `stop` 守卫；主人与外人安全边界 |
| 11 | 一条最简单的网页消息从头到尾 | 跟着一句 `8+9等于几` 走完：`web-api` 收话发 `channel/direct`；bots 认领进前台、`run`；关口一里 `model-catalog` 代调模型；零次回复走 `autoFinal` 经 `channel/reply` 回网页；网页 1.5 秒轮询拿回话（对照 `/tutorial/?canvas=596`） |
| 12 | 外网门禁、frpc 隧道和知识库底座 | 带 `X-External-Proxy: 1` 且配了 `web_auth` 才拦（前端 `AuthGate` 登录页）；30 天 `HttpOnly` 签名 Cookie；frpc 托盘独立保活、`30086` 只许映射局域网地址、`[[proxies]]` 无损回写；知识库 `kb_dirs` / `kb_docs` / `kb_tags`、磁盘镜像、`topicId` 挂专题、`kb_search` |
| 13 | 记忆、人员与上下文压缩全家桶 | 聊天归档与外置记忆服务（`:30087`）；按人按群隔离与 `channel_search` 权限；`people` 人员身份绑定；`context-fit` 总结→压缩→裁剪三段顺序；`db` 迁移账本 |
| 14 | 安全审批与进程插件全链 | `exec` 65 秒期限与 `approval` 四档把关；可信目录 / 临时授权 `grants` / 符号链接解开与超时作废；`programs` 资源守卫（CPU/内存/显存三线迟滞降载）与双向 `x-jmbots-key` 密钥隔离 |
| 15 | 语音真双工、录屏讲解与定时提醒 | `voice` WebSocket 16k PCM、本地/云端 ASR 与 TTS 主备、真双工 `barge_in` 打断与回声过滤；`screen` 基地截图流式讲解与副屏浮窗；`assist` 定时提醒原子占位、本人确认卡与错过补发 |

| 17 | 教程与流水账可观测全链 | `journal` 与 `tutorial` 经 `journal/request` 解耦通信；`FACT_KEYS` 脱敏实测留痕；`Lanes` 泳道、`DataFlow` `#1→#N` 实测/结构融合数据流转图、`Source` 精准作用域调用链与 `#调试` `WeakMap` 复用快照 |

第 3 块接着第 2 块讲“前台 → 后台 → 小会话”，只依赖第 1、2 块。“插件之间一问一答”（`src7/utils/RequestEvent.ts`）在**第 4 块**，它要先懂第 1 块的“挨个问和通知”、第 2 块的回复和回执；第 5 块的审批同时用到第 3 块的小会话和第 4 块的一问一答。第 7 块讲收费插件怎么作为独立进程接进来，要先懂第 2 块的渠道消息和第 4 块的请求、回执。

## 词表（读的时候随时回头查）

| 词 | 意思 |
|---|---|
| 前台 | `kind: front` 的会话，直接面对用户；一个机器人对一个聊天一场 |
| 后台 | `kind: work` 的会话，前台用 `hand_session` 派出去干活，结果回前台 |
| 小会话 | `sessions.ask` 开的一次性会话（审批、压缩、总结……），没有渠道、没有工具 |
| 关口 | 会话每一步里用 `ctx.serial` 挨个问插件的四个位置 |
| 挨个问 | `ctx.serial`：照挂上去的先后一个个 `await`，能改、能拦 |
| 通知 | `ctx.emit`：说一声，不等、不许改流程 |
| 认领 | bots 给每个机器人记一次（去重键 `claimKey`）；`bot/receive` 里别的插件写 `handled` 或填 `event.session` 叫截走 / 改道 |
| 接单 | 请求事件的办事方把 `handled` 标成 `true` |
| 回执 | 办事方办完 `emit` 的结果事件，带同一个 `requestId` |
| 退回 | 拿不到回执时提问方自己写的结果：没人接、超时、中止、出错 |

## 类比：一条“看诊”主线

| 骨架概念 | 看诊里是什么 |
|---|---|
| 会话 | 一次就诊：病历 + 看诊流程 |
| 关口一 `session/before-model` | 问医生之前（护士先整理病历、补一句过敏史） |
| 关口二 `session/after-model` | 医生说完之后、记进病历之前 |
| 关口三 `session/before-tool` | 做检查之前（这项检查不能做 = `deny`） |
| 关口四 `session/after-tool` | 检查结果出来、交回医生之前 |
| `stop` | 今天这次看诊到此为止 |
| 前台 / 后台 | 门诊医生 / 住院部（门诊开单转过去，结果回门诊） |
| 小会话 | 会诊：请另一位医生看一眼就走 |
| 工具 `kinds` | 哪些检查只有门诊能开 |
| 挨个问 / 通知 | 病历在科室间传阅签字 / 院内广播 |

渠道这类医院里没有的（收发室、挂号信），保留原来的类比。
