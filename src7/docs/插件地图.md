## 骨架配套

- **bots**｜机器人名单，收消息时问“进哪场会话”，会话中途先说一句｜服务 `ctx.bots`：add、get、list、route、say、channel、receive、saveFile；会话字段 bot、channel、address、customer｜发 `bot/receive`（serial）、`bot/say`｜inject resources、sessions；本服务听 `bot/say`、`session/change`，按渠道名调登记的 send｜无
  - 渠道向 `ctx.bots.channel(name, send)` 登记发送函数；收话调 `ctx.bots.receive`，附件调 `ctx.bots.saveFile`；`route` 把 `address.customer` 抄到 `row.customer`。它 `serial('bot/receive')` 让分派插件填 `event.session`，排前面的可以写 `handled` 拦掉。`say` 发 `bot/say`，本服务按会话渠道名找到登记的 send 发出去。
- **prompt**｜每一步给请求拼系统提示词｜无｜无｜inject resources、bots；听 `session/request`｜无
  - 顺序：`prompts/00_base_dsh.md` → `10_jmbots.<语言>.md` → 会话种类提示词 → 机器人记忆和公共记忆。没有文件用内置的（`utils/Embedded.ts`）。
- **summary**｜每场干活的会话做完一轮写一句总结｜会话字段 summary｜无｜inject sessions；听 `session/change`｜无
  - 开一场 kind 是 summary 的小会话跑同一个循环；前台的 list_sessions 靠这句认会话。
- **compress**｜会话太长时把前面压成摘要｜无｜无｜inject resources、sessions；听 `session/request`｜无
  - 开一场 kind 是 compress 的小会话写摘要，存自己的表；原对话不动，以后每步先套摘要。
- **fake-model**｜假模型，模型名 `fake/` 开头的会话直接给固定回答｜无｜无｜无 inject；听 `session/request`｜无
  - 在 `session/request` 里填 `request.answer`，骨架就不调模型；“调用 工具名 {JSON}”会去调那个工具，离线能测交办。

## HTTP 底座和网页

- **http**｜整个程序唯一的 Fastify，监听 0.0.0.0，管令牌｜服务 `ctx.http`：app（Fastify 实例）、isLocal、allow｜无｜inject resources；听 `ready`｜`/api/health`、`/api/tokens*`
  - 别的插件在 apply 里往 `ctx.http.app` 登记路径，`ready` 后才开始监听。本机来的不查令牌，别的机器的 `/api/`、`/files/` 要带（`Tokens.ts`）。
- **web**｜托管网页 `dist/web`（单页应用）和插件页面｜无｜无｜inject http｜`/*` 兜底；`/<名字>/` 插件页面（如 `/memory/`）
  - `/api` 开头又没人认领的回 404。读网页文件在 `Assets.ts`（源码读磁盘，编译版读内嵌）。

## 渠道

- **cli**｜命令行渠道：把命令行带的一句话发给机器人，会话都停了就退出｜继承渠道基类｜无｜inject resources、bots、sessions；听 `ready`、`session/change`｜无
  - 用法 `bun src7/Main.ts [--bot 机器人] 你好`；不读键盘。
- **web-api**｜HTTP 渠道（渠道名 http）加网页要的核心接口｜继承渠道基类｜`web-api/status`（serial，各渠道往 list 里报连接状态）、`web-api/received`、`web-api/replied`、`web-api/model`｜inject resources、bots、sessions、http；听 `bot/receive`、`bot/say`、`session/change`；可选 approval、journal、modelCatalog、progress、usage｜`/api/message`、`/api/messages*`、`/api/sessions*`、`/api/ui/*`、`/api/bots`、`/api/search`
  - POST /api/message 收话记进 `web_messages`，消息号当回话地址；网页轮询 GET /api/messages。别的渠道的消息也记一份给右栏。文件：index.ts、Timeline.ts（收件表、时间线）、Trace.ts（步骤、追溯）。
- **feishu**｜飞书的全部：渠道收发、确认和进度卡片、云文档工具、发件箱｜继承渠道基类；工具 feishu_doc、feishu_doc_delete、feishu_send_file｜无｜inject resources、bots、sessions、tools；听 `ready`（发件箱）、`web-api/status`、`approval/asked`、`approval/decided`、`progress/update`；可选 approval、progress（`ctx.inject`）｜无
  - 一个飞书应用一条长连接，回话地址带 appId 和 customer。子文件夹：cards/（卡片）、doc/（云文档）、outbox/（扫 `integrations/feishu/outbox/` 发出去）、Media.ts（收发文件）。
- **wechat**（对外名 wechat-kefu）｜微信客服：读消息、交给机器人、回话发送、客服页面｜继承渠道基类；会话字段 customer｜无（只发 trace）｜inject resources、bots、sessions、http；听 `ready`、`bot/receive`（排最前）、`web-api/status`；可选 approval（`ctx.inject`，听 `approval/decided`）｜`/wechat-kefu/`（`/wechat/` 跳过去）、`/api/wechat-kefu/*`
  - 每隔 interval_ms 用只读引擎同步重点会话，新消息存表；私聊和群里 @我 的交给机器人，客户号 `wechat:<username>`。回话进发件表：开了自动发就发，不然登记待确认，没挂 approval 就留草稿。子文件夹 read/、send/、page/。
  - 已知限制：图片缩略图要微信 V2 图片密钥，现在只显示［图片］；AI 只看得到图片、语音的文字描述（看不到图本身、听不到声音）；语音在页面上不能播放。

## 前台和分派

- **bot-front-desk**｜每个机器人一场前台对话，所有消息先到这儿，复杂的交给后台会话｜工具 history、history_search、history_get、list_sessions、hand_session、stop_session｜无｜inject resources、sessions、tools、bots；memory 有就用（`ctx.inject`）；听 `bot/receive`、`bot/say`、`session/change`、`session/message`、`session/request`｜无
  - 答 `bot/receive`：按客户号进前台对话，没有就开。往来每句记一条，前台每步的上下文 = 最近 N 条往来 + 这一轮。记历史、搜历史调 `ctx.memory`。
- **relay**｜不调模型的转话机器人，把话转给外部助手（jm开发），等回信再回给用户｜工具 relay_send｜无｜inject resources、tools、sessions、bots；听 `ready`、`bot/receive`、`session/change`、`session/request`；可选 http｜`/api/relay/inbox`、`/api/relay/reply`
  - direct 模式：写 inbox.jsonl，当场回“已转给…”；回信（replies.jsonl 或 POST /api/relay/reply）来了再推那场会话，在 `session/request` 填 `request.answer`。model 模式：模型用 relay_send 转话。

## 审核和流程

- **approval**｜审命令和待确认｜服务 `ctx.approval`：review、ask、decide、close、recent、list｜`approval/asked`、`approval/decided`｜inject resources、bots、sessions；听 `bot/receive`（排最前，认“同意 3”）、`session/request`；可选 decision、http｜`/api/approvals*`
  - review 顺序：程序规则（Rules.ts）→ decision → 审核小会话 → 问用户。decide 只改表、发事件，谁提的谁听 `approval/decided` 自己去做。
- **decision**｜决策模型：一道是非题交给一个或几个模型打分，交回 allow/deny/unsure｜服务 `ctx.decision`：judge｜无｜inject resources、sessions、bots｜无
  - 对话模型开 kind decision 的小会话回 JSON；也认分类器模型。谁要判断谁调。
- **progress**｜进度和限时：每轮一项进度，长跑发卡片问要不要停｜服务 `ctx.progress`：list、act、actById；会话字段 progress｜`progress/update`｜inject resources、bots、sessions；听 `approval/decided`、`session/change`、`session/message`、`session/request`；可选 approval、decision、modelCatalog、http｜`/api/progress*`
  - 跑满 15 分钟发待确认卡片；配了限时才到点判断。停下后写收尾，做太久的记 `data/overtime.jsonl`。
- **review**｜复盘：空闲时挑一件做太久的事，写“慢在哪”，问用户要不要记进公共记忆｜会话字段 reviewedAt｜无｜inject resources、bots、sessions、progress、approval；听 `approval/decided`；可选 modelCatalog｜无
  - 启动 5 分钟后看第一次，以后每 10 分钟；同意了写进 `memory/复盘/`。
- **runs**｜命令窗口：外面不经过模型直接跑命令｜无｜无｜inject resources、http、approval、exec；听 `approval/decided`｜`/api/run`、`/api/runs*`
  - 先 approval 审，放行交给 exec；输出攒内存，跑完存表 runs。
- **notify**｜把待确认、长任务结束转到基地右下角 toast｜服务 `ctx.notify`：send；工具 notify_user｜无｜inject resources、tools；听 `approval/asked`、`progress/update`｜无
  - POST 到配置的地址（默认 engine.index_url + /notify），基地没开就静默跳过。
