# 插件地图

- 写的人：jm开发。2026-11-17 照 `src7/plugins/Index.ts` 和各插件的 `说明.md` 整理（`inject`、`ctx.on`、`ctx.emit/serial`、`ctx.get`、`ctx.http.app` 上登记的路径）。插件代码改了，这份跟着改；细节以各插件的 `说明.md` 为准。
- 共 30 个文件夹，`Index.ts` 静态 import 30 个模块。`BUILT_IN` 里 31 个名字：`wechat` 登记了两个名字，`wechat-kefu`（对外名）和 `wechat`（别名）。
- 不写 `plugins` 段时挂 `workspaces`、`bots`、`cli`、`file-tools`、`context-fit` 五个（`utils/Checks.ts` 的 `DEFAULT_PLUGINS`）。
- 每个插件一行：干什么｜提供｜发的事件｜用了谁｜HTTP。下面几句是怎么实现的。版本号照各插件 `index.ts` 的 `version`。
- “用了谁”里：`inject` 是必须先挂好的服务；“听”是 `ctx.on` 的事件；“可选”是用到时 `ctx.get('名字')` 或 `ctx.inject([...])` 现取，没挂也能跑。
- 骨架自带的服务：`resources`、`sessions`、`tools`；骨架的事件：`ready`、`session/request`、`session/after-model`、`session/before-tool`、`session/after-tool`（这四个是会话每一步的关口，挨个问，能改、能写 `stop` 喊停）、`session/message`、`session/change`、`model/failed`、`trace`、`internal/dispatch`（Cordis 自带）。
- 插件之间要用对方，只走服务和事件，不 import 对方的代码（`import type` 可以）。互引检查见最后一节。

## 分类一览

| 类 | 插件 |
|---|---|
| 骨架配套 | workspaces、bots、fake-model |
| HTTP 底座和网页 | http、web |
| 渠道（消息从哪进出） | cli、web-api、feishu、wechat（wechat-kefu） |
| 分派（答 bot/receive） | relay（前台在 bots 里） |
| 给模型的工具 | file-tools、exec、web-search、image-gen、assist |
| 审核和流程 | approval、decision、progress |
| 模型与上下文 | model-catalog、context-fit、model-notes |
| 记忆和知识 | memory、skills |
| 管理接口（给网页、基地用） | settings、files-api、base-bridge、desktop |
| 记录和调试 | tutorial、journal、usage |

合计 3 + 2 + 4 + 1 + 5 + 3 + 3 + 2 + 4 + 3 = 30。http、web 不是渠道，单列“HTTP 底座和网页”；relay 是答 `bot/receive` 的转话机器人，单列“分派”；前台、派后台、系统提示词、reply 工具是 bots 的一部分，写在骨架配套里；基地通知听的是待确认和进度，它在 base-bridge 里，开关在 base-bridge 的配置。

## 骨架配套

- **workspaces**（v1.0.0）｜机器人的工作区：一个机器人可以有好几个，名字可以重复，各有唯一 ID；谁能看、能用按范围分（本人看全部，外人只看自己范围）｜服务 `ctx.workspaces`：getAccess、create、get、list、rename、archive、resolve、ensureDefault；工具 workspace（只给前台；create、rename、archive 只给本人）；表 workspaces｜`workspaces/changed`｜inject resources、tools｜无
  - 已有目录原地登记，不搬不删：`bots/<机器人>/workspace/` 是 private 默认工作区，机器人配置 `workspaces` 里的目录登记成 private 工作区；新建的放在 `bots/<机器人>/workspaces/<ID>/`。前台派后台（`hand_session`）按 ID 选工作区，ID 绑在后台会话的 `row.workspaceId` 上，解析出的目录写进后台回话地址的 `workspace`。plugins 段要写在 bots 前面。
- **bots**（v1.4.0）｜机器人名单，收消息时问“谁认领”，没人认领的进前台；每个机器人一场前台对话（按客户分），复杂的交给后台会话；系统提示词；会话中途先说一句｜服务 `ctx.bots`：add、get、list、route、say、send、channel、receive、saveFile；服务 `ctx.frontDesk`（`Dispatch.ts`）：receive、acceptResult；前台工具 history、history_search、history_get（`FrontDesk.ts`）、list_sessions、hand_session、stop_session（`Dispatch.ts`）；渠道工具 channel_reply、channel_history、channel_mentions、channel_visible_history（`ChannelTools.ts`）；工具 reply（`ReplyTool.ts`，`reply_tool: true` 才登记）；会话字段 bot、channel、address、customer、quiet、sourceScope、sourceClaims、activeSourceSnapshot、frontTask、workspaceId、resultQueue、activeKey｜发 `bot/receive`（serial）、`channel/reply`（serial）、`channel/history`（serial）、`bot/say`、`bot/judged`｜inject resources、sessions、tools、workspaces；memory 有就用（`ctx.inject`）；可选 decision、modelCatalog、modelNotes（`ctx.get`）；Bots 听 `channel/message`、`bot/say`、`session/change`；FrontDesk 听 `session/request`、`session/message`、`session/change`、`bot/say`、`channel/reply`、`channel/replied`；Dispatch 听 `session/request`、`session/change`、`ready`；ChannelTools 听 `session/before-tool`、`session/after-tool`、`session/request`；Prompt 听 `session/request`；不听 `bot/receive`｜无
  - 渠道发 `channel/message`，按消息上的 `deliveryMode` 分两路：`channel_tool`（飞书）由 `Dispatch.claimChannelMessage` 按 `claimKey` 去重后压进这个机器人的前台会话，模型用 `channel_reply` 经 `channel/reply` ↔ `channel/replied` 回话；`legacy_auto`（命令行、网页、微信）照 `Bot.receive` 的路交 `Dispatch.receive`，一轮结束由 `session/change` 自动把 `row.reply` 发回原渠道。
  - 渠道向 `ctx.bots.channel(name, send)` 登记发送函数；收话调 `ctx.bots.receive`，附件调 `ctx.bots.saveFile`；`route` 把 `address.customer` 抄到 `row.customer`。`say` 发 `bot/say`，本服务按会话渠道名找到登记的 send 发出去。
  - `Bot.receive` 先 `serial('bot/receive')` 问一圈，别的插件可以填 `event.session` 认领，或写 `handled` 拦掉；问完调 `ctx.frontDesk.receive`：没人认领的进前台（`FrontDesk.onReceive`：按客户号进前台对话，没有就开），前台正在整理后台结果就先排着（`Dispatch.hold`）。
  - 前台往来每句记一条，前台每步的上下文 = 最近 N 条往来（`front.recent`，默认 50）+ 这一轮。记历史、搜历史调 `ctx.memory`。派后台用 `hand_session`，后台每轮结果交回前台整理后发回原渠道；外部 AI 交回的结果走 `ctx.frontDesk.acceptResult`。
  - 系统提示词（`Prompt.ts`，`prompt` 不写或 true 时建）：`prompts/00_base_dsh.md` → `10_jmbots.<语言>.md` → 会话种类提示词 → `bots/<机器人>/persona.md` 人设 → 机器人记忆和公共记忆。没有文件用内置的（`utils/Embedded.ts`）。
  - 挂载先后：bots 写在 plugins 段前面（`tutorial`、`workspaces` 之后），五个对象照 Bots → FrontDesk → Dispatch → ChannelTools → Prompt 挂监听，所以 `session/request` 上前台拼上下文最先，接着 Dispatch、ChannelTools、Prompt，都排在 relay、memory、file-tools、approval、progress、context-fit、skills、model-catalog 这些后挂的插件前面。
- **fake-model**（v1.0.1）｜假模型，模型名 `fake/` 开头的会话直接给固定回答｜无｜无｜无 inject；听 `session/request`｜无
  - 在 `session/request` 里填 `request.answer`，骨架就不调模型；“调用 工具名 {JSON}”会去调那个工具，离线能测交办。

## HTTP 底座和网页

- **http**（v1.1.1）｜整个程序唯一的 Fastify，监听 0.0.0.0，管令牌｜服务 `ctx.http`：app（Fastify 实例）、isLocal、allow｜无｜inject resources；听 `ready`｜`/api/health`、`/api/tokens*`
  - 别的插件在 apply 里往 `ctx.http.app` 登记路径，`ready` 后才开始监听。本机来的不查令牌，别的机器的 `/api/`、`/files/` 要带（`Tokens.ts`）。
- **web**（v1.0.0）｜托管网页 `dist/web`（单页应用）和插件页面｜无｜无｜inject http、resources｜`/*` 兜底；`/<名字>/` 插件页面（如 `/memory/`、`/tutorial/`）
  - `/api` 开头又没人认领的回 404。读网页文件在 `Assets.ts`（源码读磁盘，编译版读内嵌）。

## 渠道

四个渠道都不继承基类：向 `ctx.bots.channel` 登记发送函数，收到的话发 `channel/message`（命令行、网页、微信写 `deliveryMode: 'legacy_auto'`，飞书是 `channel_tool`），听 `channel/reply` 发回话、发 `channel/replied` 报回执。

- **cli**（v1.1.1）｜命令行渠道：把命令行带的一句话发给机器人，会话都停了就退出｜无｜`channel/message`、`channel/replied`｜inject resources、bots、sessions；听 `ready`、`session/change`、`channel/reply`｜无
  - 用法 `bun src7/Main.ts [--bot 机器人] 你好`；不读键盘。
- **web-api**（v1.1.1）｜HTTP 渠道（渠道名 http）加网页要的核心接口｜无｜`channel/message`、`channel/replied`、`web-api/status`（serial，各渠道往 list 里报连接状态）、`web-api/received`、`web-api/replied`、`web-api/model`｜inject resources、bots、sessions、http；听 `bot/receive`、`bot/say`、`session/change`、`channel/reply`；可选 approval、base、flow、journal、modelCatalog、progress、usage｜`/api/message`、`/api/messages*`、`/api/sessions*`、`/api/ui/*`、`/api/bots`、`/api/search`
  - POST /api/message 收话记进 `web_messages`，消息号当回话地址；网页轮询 GET /api/messages。别的渠道的消息也记一份给右栏。文件：index.ts、Timeline.ts（收件表、时间线）、Trace.ts（步骤、追溯）。
- **feishu**（v1.1.1）｜飞书的全部：渠道收发、渠道历史、确认和进度卡片、云文档工具、发件箱｜工具 feishu_doc、feishu_doc_delete、feishu_send_file｜`channel/message`（serial）、`channel/replied`、`channel/history-result`｜inject resources、bots、sessions、tools；听 `ready`（发件箱）、`bot/judged`、`web-api/status`、`channel/reply`、`channel/history`、`approval/asked`、`approval/decided`、`progress/update`；可选 approval、progress（`ctx.inject`）、http｜`/api/feishu/contacts`
  - 一个飞书应用一条长连接，回话地址带 appId 和 customer。子文件夹：cards/（卡片）、doc/（云文档）、outbox/（扫 `integrations/feishu/outbox/` 发出去）、Media.ts（收发文件）。
- **wechat**（v1.1.1，对外名 wechat-kefu）｜微信客服：读消息、交给机器人、回话发送、客服页面｜会话字段 customer｜`channel/message`、`channel/replied`｜inject resources、bots、sessions、http、tools；听 `ready`、`bot/receive`（排最前）、`session/request`、`web-api/status`、`channel/reply`；可选 approval（`ctx.inject`，听 `approval/decided`）｜`/wechat-kefu/`（`/wechat/` 跳过去）、`/api/wechat-kefu/*`
  - 每隔 interval_ms 用只读引擎同步重点会话，新消息存表；私聊和群里 @我 的交给机器人，客户号 `wechat:<username>`。回话进发件表：开了自动发就发，不然登记待确认，没挂 approval 就留草稿。子文件夹 read/、send/、page/。
  - 已知限制：图片缩略图要微信 V2 图片密钥，现在只显示［图片］；AI 只看得到图片、语音的文字描述（看不到图本身、听不到声音）；语音在页面上不能播放。

## 分派

- **relay**（v1.1.0）｜外部助手的交办、收件、回信，三样：转话（不调模型的转话机器人，把话转给外部助手 jm开发，等回信再回给用户）；外部 AI 任务通道（grokbots、DSH 来领活、交结果）；给 Claude 留言｜工具 relay_send、agent_task、note_claude｜无（只发 trace）｜inject resources、tools、sessions、bots；听 `ready`、`bot/receive`、`session/change`、`session/request`；可选 http、frontDesk（任务通道要它）、feishu、flow｜`/api/relay/inbox`、`/api/relay/reply`、`/api/agents*`（7 个）
  - 转话（`index.ts` 的 Relay，配置写了 `helpers` 才挂）：direct 模式写 inbox.jsonl，当场回“已转给…”；回信（replies.jsonl 或 POST /api/relay/reply）来了再推那场会话，在 `session/request` 填 `request.answer`。model 模式：模型用 relay_send 转话。回信带文件、原渠道是飞书时用 `ctx.get('feishu').sendFile`。
  - 外部 AI 任务通道（`AgentTasks.ts`、`TaskRoutes.ts`、`TaskProtocol.ts`，http 和 frontDesk 都在才挂）：外部 AI 打招呼、领活、下载附件、交回结果；任务和登记存库；新协议 v1 每件写明模型、思考档、子代理、交回物，领取带 claimKey；交回经 `ctx.frontDesk.acceptResult` 排进派活会话的结果队列。
  - 给 Claude 留言（`NoteClaude.ts`，一直挂）：在 `integrations/claude/inbox/` 写一个 md，文件名以 20 位时刻开头。三样各管各的状态，不共用表和目录。

## 审核和流程

- **approval**（v1.0.1）｜审命令和待确认｜服务 `ctx.approval`：review、ask、decide、close、recent、list｜`approval/asked`、`approval/decided`｜inject resources、bots、sessions；听 `channel/message`（排最前，消息级“同意 3”只消费一次）、`bot/receive`（排最前，认“同意 3”）、`session/request`、`session/before-tool`（执行前按这一轮的说话人再拦一次，写 `gate.deny`）；可选 decision、http｜`/api/approvals*`
  - review 顺序：程序规则（Rules.ts）→ decision → 审核小会话 → 问用户。decide 只改表、发事件，谁提的谁听 `approval/decided` 自己去做。
- **decision**（v1.0.1）｜决策模型：一道是非题交给一个或几个模型打分，交回 allow/deny/unsure｜服务 `ctx.decision`：judge｜无｜inject resources、sessions、bots｜无
  - 对话模型开 kind decision 的小会话回 JSON；也认分类器模型。谁要判断谁调。
- **progress**（v1.1.1）｜进度和限时：每轮一项进度，长跑发卡片问要不要停；空闲时挑一件做太久的事写复盘｜服务 `ctx.progress`：list、act、actById；会话字段 progress、reviewedAt｜`progress/update`｜inject resources、bots、sessions；听 `approval/decided`、`session/change`、`session/message`、`session/request`；可选 approval、decision、filesMirror、modelCatalog、http｜`/api/progress*`
  - 跑满 15 分钟发待确认卡片；配了限时才到点判断。停下后写收尾，做太久的记 `data/overtime.jsonl`。
  - 复盘（`Review.ts`，有 approval 且 `review` 不是 false 时开）：启动 5 分钟后看第一次，以后每 10 分钟；挑一条超时记录，读 `对话.md` 末尾，写“慢在哪”，问用户要不要记进公共记忆，同意了写进 `memory/复盘/`。

## 模型与上下文

- **model-catalog**（v1.1.0）｜模型清单：拉每家供应商的 /models，和手写的合成一张表；调模型：限流、超长时换备选，按模型、供应商排队｜服务 `ctx.modelCatalog`：find、list、reconnect、probe｜`model/fallback`、`model/cooldown`｜inject resources、sessions；听 `model/cooldown`、`session/request`（排最后）、`model/failed`；可选 http｜`/api/models`、`/api/models/reconnect`、`/api/ui/provider-models`
  - 拉不到先用手写的，每 60 秒再试；冷却中的模型带 limitedUntil。
  - 换模型（`Fallback.ts`，`fallback` 不是 false 时挂）：在 `session/request` 上自己调骨架的 `chat()` 把回答填进 `request.answer`，所以要写在 plugins 段最后；限流的模型进冷却（`model/cooldown`，同插件的目录收到），并发名额在 `Queue.ts`。
- **context-fit**（v1.1.0）｜会话上下文：写总结、压摘要、调模型前按上下文窗口裁剪｜会话字段 summary；表 compress_log｜无｜inject resources、sessions；听 `session/change`、`session/request`；可选 modelCatalog｜无
  - 总结（`Summary.ts`，`summary` 不是 false 时）：干活的会话做完一轮，开 kind 是 summary 的小会话写一两句，写进 `row.summary`；前台的 list_sessions 靠这句认会话。
  - 压缩（`Compress.ts`，`compress` 不是 false 时，默认 `{ at: 200000, keep: 6 }`）：上一步总 token 到 `compress.at`，开 kind 是 compress 的小会话把旧对话压成摘要，存 `compress_log`；原对话不动，以后每步先套摘要。
  - 裁剪（`index.ts`，紧接压缩之后）：估 token，装不下先省略旧工具结果、再丢最早的段；只改 `request.messages` 副本。
- **model-notes**（v1.1.0）｜模型介绍和人工评价存成 Markdown，按会话汇总评分，给派活参考｜服务 `ctx.modelNotes`｜无｜inject resources、http、sessions｜`/model-notes/`、`/api/model-notes`、`/api/model-notes/rate`
  - bots 的前台在本人的轮次可选地带上模型介绍和能用的思考档。
