## Q7 2026-11-16 15:10 EST：审 relay 多助手、Rules 白名单（任务书 20261116_relay多助手和runs编译.md 第 1 步）

只审，没改你的代码。整体没问题：代码里没写死助手名/机器人名，插件间只有 `import type`，旧库补栏、helper 筛选、署名都照收件的助手来；我补的离线测试 4 条全过（见 `任务/进度.md`）。下面几条意见，按要紧排：

1. **Rules.ts 白名单里 `Build_Src7.ts --out` 的值能写到任意目录。** 正则放行 `:`、`\`、`..`，所以 `--out F:\aidata\AIJMBots\jmbotsData` 这类也直接放行，经 `/api/run` 不审就能往正式目录写 `jmbots-server.exe`。建议 `--out` 只许相对路径、不许 `..`，最好限定 `cache\` 开头。另外 `--skip_checks yes` 也在放行范围（`Rules.test.ts` 就这么写的），等于能跳过检查直接出包，是有意的吗？
2. **旧库补栏不是一步完成的。** `ALTER TABLE … ADD COLUMN helper DEFAULT ''` 之后才 `UPDATE`；两句之间崩了，下次启动栏已经在，不会再补，旧收件 `helper` 是空串，回信会署成“：收到”。建议每次启动都跑一次 `UPDATE relay_items SET helper = ? WHERE helper = ''`（很便宜），或者两句包进一个事务。
3. **给了 `id` 又给 `helper` 对不上时不报错。** `accept` 只查 `helper` 在不在名单里；给 `id` 时照收件的助手署名，传进来的 `helper` 被悄悄忽略。建议对不上就 400，或者在用法文档写明“给 id 时不看 helper”（我在 relay_用法.md 里先没写这句，等你定）。
4. **前缀按 helpers 先后取第一个匹配的。** 一个助手的前缀是另一个的开头时（如 `c` 和 `cc `）前面的会截走。现在要配的 `jm `/`jm开发`/`cc `/`CC ` 不冲突，不急；要防的话 `apply` 里查前缀互相包含就报错，或者取最长的。
5. **转出的话不去前缀。** inbox 和 webhook 里的 `text` 是带 `cc ` 的原话。单助手时就这样，确认是有意的就行。
6. 少见情况：relay 会话按“机器人+客户”一场，几个助手共用。同一步里排着 `jm x`、`cc y` 两句会合成一条收件，归第一句的助手。记下即可。
7. 小：`index.ts:835` `const list =(` 少个空格。

## Q4 2026-11-14 15:36 EST：memsvc / vgr 的 --host 默认 0.0.0.0，我有不同意见
