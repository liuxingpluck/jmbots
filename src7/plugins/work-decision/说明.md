在 `/work-decision/` 汇总需要主人点选的事。项目沿用机器人下登记的工作区。未绑定工作区的事项列在对应机器人下。左栏切换项目，思维导图、放射图、表格和清单使用同一批节点。旧 `/decision-map/` 书签会跳到新页面并保留查询参数。

## 提问和回送

- 后台会话用 `ask_owner` 提交标题、一句话背景、选项和可选的 Markdown 正文。工具从当前会话取机器人、工作区和回送地址，立即交回节点号和页面链接。
- 外部助手用 `POST /api/work-decision/ask` 登记一件事项。主人点选后，原会话从结果队列接着跑一轮，外部助手从 relay 收件箱取结果。项目由工作区 ID 确定，工作区改名后页面显示新名称。
- 主人的选择和留言先入库。未确认送达时可从变化接口补查，同一次选择按原节点键补投。中控确认收到后页面显示已确认。relay 按原收件记下的节点号和可选留言号回信，写入时用持久回信号去重。
- 配好通知目标（`owner_target` 或 `owner_targets`）时，新开待定项后按节点归属机器人匹配目标，经 `channel/reply` 给主人私聊发件数和入口。中控可手动提醒并可选指定 `bot`。

## 查决策图（work_topics）

前台、后台会话都能调，只读不改图。外人会话（`isOwnerTurn` 判为非本人，如飞书群里的 guest、客户）直接报错，不吐任何节点。参数都可选，已照 schema 校验：

| 参数 | 说明 |
| --- | --- |
| `nodeId` | 看单个节点：标题、状态和类别、项目、上级和下级（都带 `topicId`）、摘要、选项（★ 推荐、✓ 已选）、谁在何时定的、正文（超过 2000 字截断）、最近 5 条留言。没有这个节点时返回提示文字。 |
| `status` | 按状态筛，取值同 `Types.ts` 的 `STATUSES`：`open` 待定、`working` 进行中、`decided` 已定、`done` 已完成、`dropped` 已放弃。 |
| `query` | 关键词，大小写不敏感，比节点号、标题、摘要、正文。 |
| `limit` | 最多列几条，1–40，默认 15；没列完时提示还剩几个。 |

不传 `status`、`query` 时先给各状态计数。列表每行是 `- [topicId=<节点号>]〔状态〕标题 — 摘要（≤60 字）`，按待定、进行中、已定、已完成、已放弃排，同状态新建的在前。末尾提示可拿 `topicId` 调 `kb_search`、`kb_save`。实现在 `Tools.ts` 的 `registerWorkTopics`，读图只调 `Store.getPublicGraph`。

## 对外函数

### HTTP 接口

以下接口在 `/api/work-decision` 下。

- `GET /version` 返回 `{ appStartedAt, dataRev, tasksRev }`（约 60 字节），供网页每 30 秒后台轮询检查决策图与控制面任务账本变化及后端换版。
- `GET /graph` 返回版本、节点和项目；`GET /changes?since=<序号>` 可只读新增变化。
- `POST /ask` 为外部助手登记一件待定事项；`PUT /nodes` 批量创建或局部更新节点。
- `POST /child` 新建子项；`POST /status` 和 `PUT /status` 修改任务状态；`POST /quadrant` 和 `PUT /quadrant` 手动调整节点四象限（`q1~q4` 或 `null` 恢复自动归类）。
- `POST /choose` 记录选择；`POST /note` 保存留言，可带选项；`POST /reply` 写回留言；`POST /ack` 确认收到选择。
- `POST /notify` 通过配置的渠道发送待定件数；兼容无请求体/空请求体（优先走 `owner_target`，无默认且仅配一项 `owner_targets` 时自动使用该项），也支持可选 JSON `{ bot?: string }` 显式指定机器人触发提醒。
- `GET /tasks`（可选 `?status=`、`?lockTag=`、`?owner=`）返回 `ControlPlaneSnapshot`（`{ ok: true, revision, tasks, lists, counts, activeLocks, dispatchableIds }`）；`POST /tasks` 新建任务卡（未传 `status` 默认 `ready`，支持全部滴答原子字段）；`PATCH /tasks/:id`（兼容 `PUT`）更新任务与原子字段（`parentId` / `quadrant` / `dueDate` / `trashedAt` 传 `null` 显式清空，未进垃圾桶进入 `running` 撞锁回 `409`）；`POST /tasks/:id/events` 追加原则更新/范围调整/心跳事件并自动刷新 `lastHeartbeatAt`；`POST /tasks/:id/checkin` 切换习惯打卡日期（默认当天本地 `YYYY-MM-DD`，升序排序）；`DELETE /tasks/:id` 硬删除任务卡。其中 `POST /tasks`、`PATCH/PUT /tasks/:id` 与 `POST /tasks/:id/events` 均接受可选 `notifyHelper?: string`（单向唤醒目标 helper 的 relay 收件箱，空串或非字符串入口回 `400`）、`notifyBot?: string` 与 `broadcast?: boolean`（向配置 `broadcast_target` 发送无 `<at>` 纯文本战报，未配置温和返回 `{ ok: false, reason: '未配置 broadcast_target' }`），写盘后返回 `notifications?: { wakeup?, broadcast? }`，投递失败记日志且不影响主写入。
- 来源引用 `sourceRef`（`{ channel, bot?, chatId?, chatType?: 'p2p' | 'group', chatName?, sessionId?, relayId?: 正整数, messageId?, sender?, dedupeKey? }`）：
  - `POST /tasks` 可带 `sourceRef`，不对回 `400`；和没进垃圾桶的已有任务来源重复回 `409`，正文带已有任务的 `taskId`，不悄悄复用；`PATCH /tasks/:id` 可改 `sourceRef`，传 `null` 清空，换来源或从垃圾桶还原时撞上别的任务的来源也回 `409`。
  - 判重：先比去重键（显式 `dedupeKey` 去空白非空，否则 `relay:<channel>:<relayId>`，再否则 `msg:<channel>:<messageId>`），对不上再退到同渠道同 `relayId` 或 `messageId`（双方均显式写了不同非空 `dedupeKey` 时跳过退化合并，支持同消息拆多张任务）；都推不出的来源不判重。垃圾桶里的任务不参与。
  - `GET /tasks` 新增查询参数 `channel`、`bot`、`chatId`、`sessionId`、`relayId`（安全正整数，不对回 `400`）、`hasSource`（`true` / `false`，不对回 `400`），写了的维度都要相等。
- `POST /tasks/upsert`（`ControlTaskUpsertInput`）：`sourceRef` 必填，其余字段同 `POST /tasks`，另有 `eventText`（别名 `note`）和 `reopen`。
  - 没命中：补默认值后新建（标题取 `eventText` 第一行前 60 字，没有就写截断至 120 字的来源；摘要是 `eventText`；清单进收集箱；状态、优先级照 `POST /tasks` 默认），直接 `running` 照样查占坑锁、撞了回 `409`。
  - 命中：只补来源里没写的子字段（补完去重键变了就把原来的键钉成 `dedupeKey`），标题、摘要、负责人、优先级等一个不改；带了 `eventText` 追加一条 `note` 事件；`done` / `cancelled` 的默认保持原状态，传 `reopen: true` 才回到 `ready` 并记一条 `status` 事件；什么都没变时不写盘、不涨 `revision`。
  - 返回 `{ ok: true, created, deduplicated, revision, task, activeLocks, dispatchableIds, notifications? }`，同样接受 `notifyHelper`、`notifyBot`、`broadcast`。
- `POST /lists` 新建自定义清单 `{ id?, name, icon?, color?, sortOrder? }`（同名幂等返回）；`PATCH /lists/:id`（兼容 `PUT`）修改清单并同步把归属旧名称的任务 `list` 更新为新名称；`DELETE /lists/:id` 删除自定义清单（禁止删 `inbox`）并将其下任务归回 `收集箱`。

## 数据

- `decisions` 每行一个节点。 `id` 为节点号，`workspace_id`、`bot` 为归属，`parent` 为父项，`kind`、`status` 为类型和状态。 `title`、`summary`、`body` 是说明，`options`、`chosen`、`asker` 保存候选项、选择和提问方。 `main`、`quadrant`、`needs`、`sources`、`links`、`detail_path` 提供主线、四象限归类、依赖和来源。 `created_at`、`decided_at`、`decided_by`、`acknowledged_at`、`note` 保存创建、决定和确认记录。
- `decision_notes` 每行一条留言。 `decision_id` 和 `id` 唯一定位；`author`、`at`、`text` 为作者、时间和正文；`option`、`reply_to`、`replied_at`、`relay_reply_id` 为选项、回话关联和去重依据。
- `decision_changes` 每行一次变化。 `seq` 为序号，`at`、`actor`、`action` 记录时间、操作者和动作，`decision_ids`、`detail` 保存受影响节点和变化详情。
- `<runtime>/control-plane-tasks.json` 独立保存 `ControlPlaneFile`（`version`、递增 `revision`、任务列表 `tasks: ControlTask[]` 与清单定义 `lists: TaskListDef[]`），经 `Files.writeTextAtomic` 原子落盘，与 SQLite 决策图完全解耦；老文件缺 `lists` 时用默认 7 清单兜底并在首次写盘补齐，`ControlTask` 可选扩展字段包括 `kind`（`task | countdown | habit`）、`list`、`parentId`、`quadrant`、`dueDate`、`countdownMode`、`icon`、`tags`、`checkIns`、`trashedAt`、`sortOrder`、`sourceRef`（来源引用，没有来源的任务不写这个键），老任务无新字段时原样兼容保留。

旧 `data/decision-map/graph.json` 和 `history.jsonl` 由首次挂载在同一事务中导入，旧文件保留。导入标记存于序号 0，公开变化序号沿用旧快照。现有节点、留言和历史在正常写入时一起提交。

## 配置

在 `plugins` 中登记 `name: work-decision`，放在工作区和机器人初始化之后。可配置以下字段。

- `legacy_workspace_id` 是旧决策图首次导入时要归到的已有本人工作区。请在部署前填好。缺省时旧图留在未归类项目。
- `relay_helper` 是旧节点的选择、任务变化和留言默认交给的助手名。没有收件助手时可以读变化接口。
- `owner_target` 包含 `bot`、`channel`、`chat`，填默认通知主人的私聊目标（未命中 `owner_targets` 时回落使用）。
- `owner_targets` 可选数组，每项包含 `bot`、`channel`、`chat`（`bot` 不可重复），用于多机器人场景按待定节点归属的 `node.bot` 精准路由提醒。只要 `owner_target` 或非空 `owner_targets` 任一存在，`public_url`（不含账号密码的 HTTP/HTTPS 工作决策完整地址）即必填。
- `broadcast_target` 可选对象，包含 `channel`（可选，默认 `feishu`）、`bot`（负责向作战室发战报的机器人名）与 `chat_id`（作战室群或聊天 ID）；未配置时 `broadcast: true` 温和降级返回未配置原因，不要求 `public_url`。
- `helper_bots` 可选对象（`Record<string, string>`），将外部助手名（如 `Claude`、`HanXin`）映射为对应目标机器人名；单向唤醒时按请求 `notifyBot` > `helper_bots[notifyHelper]` > `broadcast_target.bot` > `owner_target` / 单项 `owner_targets` 顺序解析目标机器人。

## 补充：工作台分主题进度、直达中控与 30 秒轮询刷新

1. **专题目录 + 总览导图双视图（PC 与手机自适应）**：默认打开「专题目录」看法（PC 左栏展示顶层子主题树，手机竖屏收起为顶部切换条与抽屉菜单），点进子主题即可单栏查看背景说明、`待拍板置顶区` 和 4 态子任务清单（`待拍板` / `进行中` / `已定` / `已完成`）；顶栏可一键切回思维导图、按日期、放射、表格、清单。
2. **常驻直达中控输入框**：总览和专题页都常驻输入框，自动挂当前子主题或选中节点的上下文胶囊，按节点在浏览器 `localStorage` 实时保存草稿（刷新或切换看法不丢草稿）。发送直接走 `POST /api/work-decision/note` 进同源 `relay` 收件箱，中控回信写回节点 `notes` 原位回显。
3. **30 秒普通 `GET` 后台轮询刷新**：不使用 SSE 或 WebSocket，前台每 30 秒及切回可见时请求一次 `GET /api/work-decision/version`；仅 `dataRev` 变化时静默拉 `/graph` 合并数据（不整页刷新、不抢输入焦点）；`appStartedAt` 变化时若空闲无草稿自动刷新，若正在打字或有草稿则在顶栏提示「有新版本，发完点此刷新」。
