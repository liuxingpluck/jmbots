# journal v1.2.0

把函数跟踪与 Cordis 事件存入 `journal_lines` 流水表，并统一托管完整会话文件镜像 `FilesMirror`（原 `files-mirror` 已并入，保留 `ctx.filesMirror` 服务；若配置 `mirror: false` 则回退由 `Markdown.ts` 写简版会话 Markdown）。

“跟踪行整理成步骤”只在本插件的 `Trail.ts` 写一份：教程页的轨迹（`trail`）和聊天页回话追溯要的行（`reply-lines`）都经 `journal/request` 从这里拿；tutorial 收启动轨迹时直接 import `Trail.ts` 的纯函数。

## 数据

### 数据库表

`journal_lines` 存储运行期每个 `trace` 跟踪点与 Cordis 内部事件派发记录，每行对应一条按 `id` 自增的时间顺序跟踪记录。

| 列名 | 类型 | 能不能空 | 意思 | 谁写、什么时候写 |
|---|---|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 否 | 流水全局自增顺序号 | SQLite 自增；`Journal.record` 每次插入生成 |
| `at` | INTEGER NOT NULL | 否 | 记录写入时的毫秒时间戳 | `Journal.record` 取 `Date.now()` 写入 |
| `kind` | TEXT NOT NULL | 否 | 行类型：`函数`（跟踪点）或 `事件`（Cordis dispatch） | `Journal.listen` 区分写入 |
| `name` | TEXT NOT NULL | 否 | 函数名（如 `Bot.receive`）或事件名（如 `session/message`） | `Journal.listen` 在回调时写入 |
| `mode` | TEXT NOT NULL | 否 | 事件派发模式（通知/串行）；函数行固定 `''` | `Journal.listen` 从 `traceUtils.dispatchLine` 获取或空串 |
| `listeners` | TEXT NOT NULL | 否 | 监听此事件的插件名列表 JSON 数组；函数行为 `'[]'` | `Journal.listen` 写入 |
| `text` | TEXT NOT NULL | 否 | 函数跟踪点人话说明（最多 2000 字）；事件行为 `''` | `Journal.record` 经 `Cut.chars` 截短写入 |
| `code` | TEXT NOT NULL | 否 | 函数跟踪点代码说明（最多 2000 字）；事件行为 `''` | `Journal.record` 经 `Cut.chars` 截短写入 |
| `site` | TEXT NOT NULL | 否 | 触发源文件路径与行号（调用栈跳过 `plugins/journal/`） | `Journal.listen` 调 `traceUtils.getCallSite` 写入 |
| `bot` | TEXT | 能 | 关联机器人名字 | `Journal.listen` 从 `vars['机器人']` 或 `dispatchLine.bot` 提取 |
| `session_id` | TEXT | 能 | 关联会话 ID | `Journal.listen` 从 `vars['会话']`/`vars['session']` 或 `dispatchLine.session` 提取 |
| `message_id` | INTEGER | 能 | 关联收件表 `web_messages` 消息号 | `Journal.listen` 从 `vars['消息号']` 或 `dispatchLine.messageId` 提取 |
| `vars` | TEXT NOT NULL | 否 | 关键上下文变量 JSON（单串限 2000 字，整条限 16000 字） | `Journal.record` 经 `shrink` 序列化写入 |

建表与索引：`src7/plugins/journal/index.ts:103-108`；写入与清理：`src7/plugins/journal/index.ts:172-186`。索引：`journal_lines_name (name, at)`、`journal_lines_session (session_id, at)`、`journal_lines_message (message_id)`。

### 文件

- `bots/<row.bot>/sessions/<row.id>/对话.md`：完整会话可读日志（默认由 `FilesMirror` 生成，无 `parent` 的会话以 68 个 `=` 分块追加，损坏或缺失自动按库重建；当配置 `mirror: false` 时由 `Markdown.ts` 写简版，不按 `parent` 过滤）。
- `bots/<row.bot>/sessions/<row.id>/session.json`：由 `FilesMirror.saveJson` 每会话 1 秒合并防抖原子写（`Files.writeTextAtomic(..., true)`），展开除 `messages` 外的会话字段，附 `messages` 总条数与 `file` 路径。

## 轨迹的形状（Trail.ts）

| 类型 | 字段 | 位置 |
|---|---|---|
| TrailLine | `id`、`at`、`kind`、`name`、`listeners`、`text`、`site`、`sessionId`、`messageId`、`vars`；启动轨迹另给 `node`（道）、`facts`（已挑好的关键值）、`docs`（函数注释） | `src7/plugins/journal/Trail.ts:23` |
| TrailRow | `t`（离开始几毫秒）、`gap`（到下一行）、`kind`、`name`、`text`、`listeners`（去掉 journal、tutorial、usage）、`site`、`facts`、`error` | `src7/plugins/journal/Trail.ts:44` |
| TrailStep | `no`、`node`、`title`、`t`、`ms`、`error`、`notified`（只听不说的插件）、`rows`、`docs` | `src7/plugins/journal/Trail.ts:67` |
| Trail | `message`（启动是 0）、`session`、`bot`、`channel`、`preview`、`at`、`ms`、`state`（running / done / failed / stopped / unknown）、`error`、`steps`、`notes`（英文键 → 中文解释） | `src7/plugins/journal/Trail.ts:90` |
| TrailDoc | `name`；tutorial 放进来的是 `tutorial/Source.ts` 的 CodeDoc，别的字段原样带给页面 | `src7/plugins/journal/Trail.ts:16` |

常量：`NOISE`（`web-api/status`、`trace`、`ready`，tutorial 拍快照也跳过）、`TRAIL_MAX_LINES`（800，一条请求最多取几行）、`FOLDERS`（插件名 → 文件夹名，tutorial/Boot.ts 找插件文件也用）。

两边挑法不一样，照旧各留一个函数：教程页要“这条请求从头到尾经过了谁”，跳过定时杂事件、看会话收尾；聊天页追溯要“到这句回话为止记了什么”，按回话涉及的会话和时刻截。

## 设计要点

- 记录是观察不是控制：跟踪点 trace 和 Cordis 非 internal 事件分两类落进 journal_lines，供追溯和教程读取。
- 保留事件发法、监听者、来源位置和可关联的会话/消息键，不伪造完整的父子因果链。
- 和 tutorial 共享跟踪拼装语义；filesMirror 缺席时写简版对话，保留清理策略以免日志无界。
