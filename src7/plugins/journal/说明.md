# journal v1.3.7

1.3.7 云端 31 第 1 条“旁听者不许拦正事”：`trace`、`internal/dispatch` 两个监听改经 `utils/Trace.ts` 的 `onTrace`、`onDispatch` 挂，写库出错只打一行 `[旁听异常:journal]` 日志，不再从发事件的那一行抛出、拦住业务监听；事件行（`buildDispatchLine`，一个值最多 200 字）和调用栈（`site`，跳过 `plugins/journal/`、`plugins/tutorial/`）和 tutorial 共用一份，同一次派发只算一次。

1.3.6 `Trail.ts` 放宽 `FACT_KEYS`，新增飞书入站（`type`、`chat`、`called`）、说话人（`personName`、`speakerRole`）、上下文裁剪（`tokensBefore`、`tokensAfter`、`trimmedCount`、`droppedCount`）、审批（`verdict`、`decidedBy`）与记忆召回（`skillCount`、`citationCount`）关键数值；`People.resolve` 的 `role` 映射为 `speakerRole` 免得与消息 `role` 重名，工具完整参数 `args` 仍不进 `facts`（由 `tutorial` 载荷卡展示）。

1.3.5 体检修复（第 17 块第 1、6 条）：`FilesMirror` 的 `written`（会话号 → 对话.md 写到第几条）最多记 `WRITTEN_MAX`（2000）场，满了丢最早那场，它再来消息时照库整份重写一次，7×24 跑着不再跟着会话数一直涨；`journal/request` 的 `trail` 改调 `Trail.getPickedTrail`，挑行只算一遍，交回的 `trail`、`picked` 和原来完全一样。

1.3.4 `journal_lines` 建表与 `source_id` 补列改由 `db` 插件迁移账本管理（`adoptColumn` 接管已有列），去掉启动时的手写 `PRAGMA table_info` 与 `ALTER TABLE`。

流水插件承担两部分职责。

- 把函数跟踪与 Cordis 事件存入 `journal_lines` 流水表。
- 托管完整会话文件镜像 `FilesMirror`。原 `files-mirror` 并入，保留 `ctx.filesMirror` 服务。配置 `mirror: false` 时，由 `Markdown.ts` 写简版会话 Markdown。

插件用 `journal/request` 与 `journal/result` 查询流水。`Trail.ts` 统一把跟踪行整理成步骤。

- 教程页通过 `journal/request` 取轨迹（`trail`）。
- 教程页启动轨迹：tutorial 把录下的启动行发 `journal/request`（`boot-trail`），journal 收成轨迹回给它。
- 聊天页通过 `journal/request` 取回话追溯的事件（`reply-lines`），`Trace.ts` 已把流水行换成网页的事件外壳。
- 轨迹和跟踪行的形状、`NOISE`、`FOLDERS` 放在 `src7/utils/Trail.ts`，journal、tutorial 共用；tutorial、web-api 都不 import journal，要数据只发 `journal/request`。

## 数据

### 数据库表

`journal_lines` 按 `id` 自增记录时间顺序。每行是下列之一。

- 运行期 `trace` 跟踪点
- Cordis 内部事件派发记录

| 列名 | 类型 | 能不能空 | 意思 | 谁写、什么时候写 |
|---|---|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 否 | 流水全局自增顺序号 | SQLite 自增；`Journal.record` 每次插入生成 |
| `at` | INTEGER NOT NULL | 否 | 记录写入时的毫秒时间戳 | `Journal.record` 取 `Date.now()` 写入 |
| `kind` | TEXT NOT NULL | 否 | 行类型：`函数`（跟踪点）或 `事件`（Cordis dispatch） | `Journal.listen` 区分写入 |
| `name` | TEXT NOT NULL | 否 | 函数名（如 `Bot.receive`）或事件名（如 `session/new-message`） | `Journal.listen` 在回调时写入 |
| `mode` | TEXT NOT NULL | 否 | 事件派发模式（通知/串行）；函数行固定 `''` | `Journal.listen` 从 `traceUtils.buildDispatchLine` 获取或空串 |
| `listeners` | TEXT NOT NULL | 否 | 监听此事件的插件名列表 JSON 数组；函数行为 `'[]'` | `Journal.listen` 写入 |
| `text` | TEXT NOT NULL | 否 | 函数跟踪点人话说明（最多 2000 字）；事件行为 `''` | `Journal.record` 经 `Cut.clipTextWithLength` 截短写入 |
| `code` | TEXT NOT NULL | 否 | 函数跟踪点代码说明（最多 2000 字）；事件行为 `''` | `Journal.record` 经 `Cut.clipTextWithLength` 截短写入 |
| `site` | TEXT NOT NULL | 否 | 触发源文件路径与行号（函数行跳过 `plugins/journal/`；事件行用 `onDispatch` 共用的 `site`，跳过 journal、tutorial 两个文件夹） | `Journal.listen` 调 `traceUtils.getCallSite`，或取 `SharedLine.site` |
| `bot` | TEXT | 能 | 关联机器人名字 | `Journal.listen` 从 `vars['机器人']` 或 `dispatchLine.bot` 提取 |
| `session_id` | TEXT | 能 | 关联会话 ID | `Journal.listen` 从 `vars['会话']`/`vars['session']` 或 `dispatchLine.session` 提取 |
| `message_id` | INTEGER | 能 | 关联收件表 `web_messages` 消息号 | `Journal.listen` 从 `vars['消息号']` 或 `dispatchLine.messageId` 提取 |
| `source_id` | TEXT | 能 | 标准消息号：渠道发来的 `JSON.stringify([渠道, 账号, 平台原消息号])`，一定以 `["` 开头；平台原消息号、提醒号不认 | `Journal.listen` 从 `vars['sourceId']`、字符串形式的 `vars['messageId']`（跟踪点），或 `dispatchLine.sourceId`（事件参数里的 `messageId`、`sourceId`，或其 `message` 里的这两项）提取。旧表没有这一列，建表时用 `ALTER TABLE` 补上，旧行是空 |
| `vars` | TEXT NOT NULL | 否 | 关键上下文变量 JSON（单串限 2000 字，整条限 16000 字） | `Journal.record` 经 `shrink` 序列化写入 |

建表与索引：`src7/plugins/journal/index.ts:198-211`；写入与清理：`src7/plugins/journal/index.ts:293-314`。索引：`journal_lines_name (name, at)`、`journal_lines_session (session_id, at)`、`journal_lines_message (message_id)`、`journal_lines_source (source_id)`。

轨迹按标准消息号串：渠道（飞书）收到的那几行（`Feishu.start`、去重、认 @、`channel/mention` 等入站渠道事件）只带标准消息号、没有收件号。`Timeline.insert` 的跟踪点同时带数字收件号和 `sourceId`，`Journal.request`（`trail`、`reply-lines`）靠这一行把两个号接上，从标准号第一次出现的那行起取：带本收件号的行，加上没有收件号、没有会话、带同一标准号的行，再加明确关联会话的行。同一条群消息给几个机器人时各有各的收件号，别的机器人的行不混进来。`GET /api/events` 加 `source` 参数按标准消息号查。

### 文件

- `bots/<row.bot>/sessions/<row.id>/对话.md` 是会话可读日志。
  - 默认由 `FilesMirror` 生成，无 `parent` 的会话以 68 个 `=` 分块追加，损坏或缺失时按库重建。
  - 配置 `mirror: false` 时由 `Markdown.ts` 写简版，所有 `parent` 情况均写。
- `bots/<row.bot>/sessions/<row.id>/session.json` 由 `FilesMirror.saveJson` 保存。
  - 每会话 1 秒合并防抖，使用 `Files.writeTextAtomic(..., true)` 原子写。
  - 展开除 `messages` 外的会话字段。
  - 附 `messages` 总条数与 `file` 路径。

## 设计要点

- 记录是观察不是控制：跟踪点 trace 和 Cordis 非 internal 事件分两类落进 journal_lines，供追溯和教程读取。
- 保留事件发法、监听者、来源位置和可关联的会话/消息键，不伪造完整的父子因果链。
- 和 tutorial 共享跟踪拼装语义；filesMirror 缺席时写简版对话，保留清理策略以免日志无界。
