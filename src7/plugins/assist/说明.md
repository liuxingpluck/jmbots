# assist v1.2.3

提醒发送上限由发件账的记录读取、渠道发送和记账余量合计。以下操作遇到超时、中止或监听异常时保留待核对状态。

- 确认卡登记
- 确认卡作废
- 提醒发送

网页的「待办」面板显示当前机器人的提醒及发送状态。助手提供以下工具。

- 表情
- 选项卡片
- 会话待办
- 定时提醒

### 模型工具

#### 提醒工具

| 工具 | 参数 | 作用 |
|---|---|---|
| `remind_add` | `{at, text}`。`at` 接当地 `YYYY-MM-DD HH:mm` 或 `YYYY-MM-DD`，仅传日期时使用早上默认时刻 | 在本轮聊天登记一条纯文本提醒，返回编号、时间和状态。同一轮的同一次工具调用重放时沿用已保存的提醒。 |
| `remind_list` | `{}` | 查看本轮聊天最多 100 条提醒及状态。外人只看到自己的提醒。 |
| `remind_cancel` | `{id}` | 取消相同机器人、渠道、账号和聊天下的待发提醒。外人只可取消自己登记的提醒。 |

提醒工具在 `front`、`work` 会话注册。

1. `session/request` 按配置时区给模型当前日期、时间和星期，供模型把「周六早上」换算成日期。
2. 工具检查输入是否为未来的有效时刻。

- 渠道、账号、聊天和发送者取当前轮的不可变来源快照。
- 审批允许访客调用工具，写入范围限制于提醒记录和本轮聊天。

提醒是否需要本人确认，取决于来源。

- 本人在飞书私聊或已核验的本机网页聊天建提醒时直接生效。
- 群聊和外人提交的提醒按以下顺序处理。
  1. 通过 `approval/request` 创建一次确认卡，批准前在待办面板标「等你确认」。
  2. `approval/decided` 更新状态，重启时查询持久审批结果恢复。
  3. 本人同意后提醒到点自动发送，确认时已晚于原定时间的提醒以补发处理。
- 登记结果不确定时保存待核对状态，只核对原卡。
- 取消提醒落盘后，单独报告卡片作废结果待核对的情况。

提醒到点按以下顺序发送。

1. `Reminders.start` 接入发送入口后找最早的已确认记录。
2. 到点时在 SQLite 里原子占位，以记录号请求 `approval/reminder-send`。
3. Outbound 通过 `assist/reminder-read` 取得冻结的发送目标、正文和确认状态。
4. 经 `channel/send` 与 `channel/sent` 运输并记账。
   - 飞书提醒发到原群或私聊。
   - 网页提醒记进原机器人的聊天时间线。

启动或重启时也按原记录核对。

- 启动时已经到期的已确认提醒补发一次，正文注明原定时间。
- 重启时以冻结的编号和正文把在途提醒再次交给 Outbound。
  - 尚未占用发送号的提醒可以继续发送。
  - 已有回执或在途状态的提醒按原号取得结果，避免重复提醒。

## 数据

### 数据库表

`assist_items` 保存协助工具产生的记录，一行是一项，挂在某条收件消息下。

- 点的表情（react）
- 问用户的卡片（ask）
- 待办（todo）

| 列名 | 类型 | 能不能空 | 意思 | 谁写、什么时候写 |
|---|---|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 否 | 记录号 | `Assist.add` 插入时自增 |
| `bot` | TEXT NOT NULL | 否 | 机器人 | `add`，模型调协助工具时 |
| `kind` | TEXT NOT NULL | 否 | `react` / `ask` / `todo` | `add` |
| `session_id` | TEXT NOT NULL | 否 | 产生这一项的会话 | `add` |
| `message_id` | INTEGER | 能 | 这个机器人最新一条 `web_messages.id`（挂在哪条消息下） | `add` |
| `data` | TEXT NOT NULL | 否 | 按 kind 存的 JSON；ask 答了以后多一个 `answer` | `add` 写；`POST /api/assist/asks/:id` 回答卡片时 UPDATE |
| `created_at` | INTEGER NOT NULL | 否 | 创建毫秒时刻 | `add` |
| `updated_at` | INTEGER NOT NULL | 否 | 最后改动毫秒时刻 | `add` 写；回答卡片时更新 |

删：`deleteTodos` 删指定会话的 todo 行。

依据：建表 `src7/plugins/assist/index.ts:51-53`；写 `:169`（`add`）、`:145`（回答 ask）、`:193`（`deleteTodos`）。

data 的 JSON 按用途存。

- react `{emoji}`
- ask `{question, options[], answer?}`（answer 由回答接口加）
- todo `{items: {text, status: todo|doing|done}[]}`

读别人的表：`web_messages`，取这个机器人最大的 id 挂这一项（`src7/plugins/assist/index.ts:165`）。

## 配置

`plugins` 中 `assist` 的 `config.reminders` 可配置本地日期和早上时刻。

- 省略 `time_zone` 时使用服务运行环境的 IANA 时区。
- 省略 `morning` 时使用 `09:00`。
- 输入时分采用 24 小时制。
- 夏令时跳过的本地时刻会被拒绝，重复时刻取先发生的那次。

```yaml
- name: assist
  config:
    reminders:
      time_zone: America/New_York
      morning: '09:00'
```
