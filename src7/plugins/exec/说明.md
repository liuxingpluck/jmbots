# exec v1.1.6

1.1.6 是不是本人改问 channels 协议插件的 `isOwnerTurn`（从 `utils/Workspace.ts` 挪过去的），判断不变。

1.1.5 确定命令的工作目录时，直接把本轮机器人名和回话地址交给 `getSessionWorkspace`。

1.1.4 只有外人（builder、按目录授权升成 builder 的人）那一轮的命令才带 `confined=cwd`（`isOwnerTurn` 判）；本人的后台在别的工作区、授权目录里跑，照本人的规则审（可信目录、授权目录直接放行，要问就出卡片，不再被当成 builder 直接拒）。用户 #301。

机器人名单和目录等只读值由 utils/Bots.ts 读取。

exec 提供以下入口。

- shell 命令执行服务 `ctx.exec.run`
- 经审核的 `exec` 模型工具
- HTTP 命令窗口 `Runs.ts`（`/api/run`、`/api/runs*`，原 `runs` 插件已并入）

审核通过请求事件 `approval/request`（action: review，契约 3.2 第 1 条）。

1. `Runs.ts` 的 `requestReview` 最多等 `approval/result` 65 秒。
2. 未挂 approval、超时、会话喊停或 approval 出错时拒绝。退回信号同时送给审批方，超时回执说明命令未执行。
3. 作废待确认时发 `approval/request`（action: decide，拒绝）。不带 requestId，发完即结束。

## 听的事件

| 事件 | 位置 | 收到后做什么 |
|---|---|---|
| approval/decided（exec） | `src7/plugins/exec/index.ts` | 处理 `kind==='exec'` 且带 `session` 的待确认：同意则执行并把结果交回会话，拒绝则写回未执行说明。卡片已作废时沿用本次审核的退回结果。 |
| approval/decided（run） | `src7/plugins/exec/Runs.ts` | 处理 `kind==='run'` 的待确认：仍为 `pending` 时，同意则调度 `exec.run` 启动命令，拒绝则标记 `rejected`。 |

## 发的事件

| 事件 | 位置 | 触发时机 | 携带内容 |
|---|---|---|---|
| trace | `src7/plugins/exec/index.ts` | 起进程前、工具审核后、用户定夺后交回会话时。 | `Exec.run`：`{命令,目录,超时毫秒}`；`Exec.onTool`：`{会话,结论,原因}`；`Exec.onDecided`：`{会话,号,结果}` |
| approval/request（请求，serial） | `src7/plugins/exec/Runs.ts` 的 `requestReview` | 工具 exec、`POST /api/run` 审命令。 | `{ action: 'review', input: { command, cwd, confined?, bot?, session?, kind: 'exec'\|'run', payload, ask?, signal? } }`；等 `approval/result` 的 `verdict` 65 秒 |
| approval/request（指令，serial，不等回执） | `src7/plugins/exec/Runs.ts` 的 `Runs.dismiss` | 命令窗口审核中或等用户时被停下。 | `{ action: 'decide', id, approve: false, by: '命令窗口：发命令的停下了' }` |

## 数据

### 数据库表（`ctx.resources.db`）

`runs` 记录命令窗口由接口发起的长命令，每次运行对应一行，由 `Runs.save` 用 INSERT OR REPLACE 整行写入。状态依次为

1. 审核
2. 等用户
3. 在跑
4. 结束

| 列名 | 类型 | 能不能空 | 意思 | 谁写、什么时候写 |
|---|---|---|---|---|
| `id` | TEXT PRIMARY KEY | 否（主键） | 20 位本地时刻 + 随机号 | `Runs.start` 新建时生成 |
| `command` | TEXT NOT NULL | 否 | 原始命令 | `start` |
| `cwd` | TEXT NOT NULL | 否 | 执行目录（不给用程序根目录） | `start` |
| `why` | TEXT NOT NULL | 否 | 发起原因 | `start` |
| `source` | TEXT NOT NULL | 否 | 谁发起的（对外叫 `from`，默认 api） | `start` |
| `timeout_sec` | INTEGER NOT NULL | 否 | 超时秒数，限在 1..3600 | `start` |
| `status` | TEXT NOT NULL | 否 | `pending` / `running` / `done` / `failed` / `rejected` / `stopped` | `start` 写 pending，审核不过改 rejected；`launch` 改 running，跑完 done 或 failed；`onDecided` 用户拒绝改 rejected；`stop` 改 stopped；重启时构造函数把 running 和没挂审批的 pending 改 failed |
| `review` | TEXT NOT NULL | 否 | 审核 JSON `{by, reason, ms}` | `start` 先写“审核中”，审核完更新 |
| `approval_id` | INTEGER | 能 | 等用户批的待确认号 | `start` 要问用户时写 |
| `created_at` | INTEGER NOT NULL | 否 | 创建毫秒时刻 | `start` |
| `started_at` | INTEGER | 能 | 开跑毫秒时刻 | `launch` |
| `ended_at` | INTEGER | 能 | 结束毫秒时刻 | `launch` 跑完、拒绝、`stop`、重启置失败时 |
| `code` | INTEGER | 能 | 退出码 | `launch` 跑完 |
| `timed_out` | INTEGER | 能 | 1 超时 / 0 没超时 | `launch` 跑完 |
| `error` | TEXT | 能 | 失败、停下、拒绝的说明；重启是“程序重启了，没跑完” | 同 status |
| `output` | TEXT | 能 | stdout/stderr 合在一起的完整输出（只有 `/log`、`Runs.read` 用） | `launch` 跑完 |

新建时顺手删掉最近 300 条以外、已结束的行。

依据：建表 `src7/plugins/exec/Runs.ts:89-91`；重启置失败 `:95`；写 `:327-331`（`save`，被 `start` `:107`、`launch` `:173`、`onDecided` `:215`、`stop` `:239` 调）；清旧 `:333`。

## 设计要点

- 执行和审核的分工
  - 通用起进程服务负责执行。
  - 模型工具需经过审批。
  - runs 复用 exec 的进程管理。
- 工具以当前授权工作区为 cwd，审批规则承担边界；cwd 本身不是操作系统沙箱。
- 执行时分别处理
  - 把停止信号和超时传到子进程树。
  - 收集完整输出。
  - 限制给模型的报告长度，控制上下文占用。
- runs 的命令窗口也走审批，入口独立于模型会话。
  - 重启时无审批承接的 pending/running 标失败。
  - 已在等用户的审批保留，等待原决定。
- runs 的输出和执行状态分开。等待和停止接口作用于本次命令。
  - 完整日志保留在内存和表里，大输出会增加占用。
  - 报告限长只约束报告，日志总量独立。
