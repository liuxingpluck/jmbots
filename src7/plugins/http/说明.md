#### GET /api/health

- 定义：`src7/plugins/http/index.ts:104`
- 返回：{ok:true,problems:string[]}
- 作用：健康检查，getPluginProblems(pluginStatus)给问题，插件问题不改ok

#### POST /api/service/stop

- 请求来源须满足以下条件。
  - 本机环回地址。
  - 请求无 `Origin`。
  - 带 `x-jmbots-window: 1`。
  - 来源或标记不满足返回 403，请求体不参与核对。
  
  [路由实现 · `Http.constructor` · index.ts:158](index.ts#L158)
- 进程须满足以下条件，否则返回 409。
  - 主站处于基地守护（`JMBOTS_SUPERVISED=1`）。
  - 尚未开始关停。
  - `x-jmbots-expected-pid` 与当前进程号一致。
  
  [进程核对 · `Http.constructor` · index.ts:158](index.ts#L158)
- 关停按以下顺序处理。
  1. 返回 202 和主站 PID，基地据此等待退出。
  2. 回执写出后，主站停止接收 HTTP 请求。
  3. 等待已挂载的 `programs` 关闭托管程序。
  4. 关闭数据库并以退出码 0 结束。
  - 202 表示已接受关停，实际退出由基地观察。
  
  [关停顺序 · `Http.shutdownForWindow` · index.ts:239](index.ts#L239)

## 设计要点

原有免令牌放行继续生效。身份核验标记仅保留在服务端当次请求，供程序界面代理使用。

- 本机访问有标记。
- 已通过令牌校验的远程请求有标记。
- 未配置令牌时，远程访问照常放行且无标记。
- 只靠 `server.trusted_ips` 放行的远程请求无标记。

- 单个 Fastify 按路径承载各业务插件，ready 后统一监听，所以插件可以先登记路由；业务路由属于各插件。
- HTTP 集中管理以下边界。
  - 访问令牌
  - 本地与可信 IP
  - 开放路由
  - 进程健康与插件 problems 分开，免得看门狗把插件失败当进程死亡。

当前边界：当前存在无令牌放行和可信 IP 等分支，不把它概括为所有远程请求都必需令牌。
