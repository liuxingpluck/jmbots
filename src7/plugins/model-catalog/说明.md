# model-catalog v1.1.1

拉取各供应商 `/models` 并合并手写参数提供可查内存模型清单，并在 `session/request` 末尾接管模型调用与限流/超长回退、冷却与并发排队（已并入原 `model-fallback`）。

## 依赖

| 服务 | 类型 | 用途 | 位置 |
|---|---|---|---|
| resources | 必需 | 读 providers（baseUrl/apiKey 与手写字段）、defaultModel、engine 回退设置与 concurrency 上限。 | `src7/plugins/model-catalog/index.ts:26` |
| sessions | 必需 | ModelFallback 排在末尾调 ctx.sessions.chat(request) 填 answer。 | `src7/plugins/model-catalog/index.ts:26` |
| http | 可选 | 就绪时经 ctx.inject(['http']) 登记三条模型 HTTP 接口；无 http 时目录与回退仍独立可用。 | `src7/plugins/model-catalog/index.ts:390` |

## 听的事件

| 事件 | 位置 | 收到后做什么 |
|---|---|---|
| model-catalog/request | `src7/plugins/model-catalog/index.ts:149` | `action: 'find'` 按 `model`（供应商/模型 ID）查当前清单。 |
| model/cooldown | `src7/plugins/model-catalog/index.ts:144` | 保存 info.model→info.until 到 cooling；list/find 读取时附 limitedUntil 并清除过期项。 |
| session/request | `src7/plugins/model-catalog/Fallback.ts:155` | ModelFallback.onRequest：request.answer 已有则跳过，否则排队调模型填 answer；应挂在请求链末尾。 |
| model/failed | `src7/plugins/model-catalog/Fallback.ts:237` | 每次 attempt 临时注册；只计同 Session 实例且同 model 的限流错误，超过 1 次重试即 abort 切下一模型；finally 解除。 |

### 共享会话字段

- 读取 `ChatRequest.model / signal / session / answer`（回填 `answer`；仅在浅拷贝 `asked` 上替换 `model / signal`，不改持久化 `session.row`）。

### 插件内存状态

- `tables: Map<provider, ModelInfo[]>`：当前内存模型表（`src7/plugins/model-catalog/index.ts:95`）。
- `pending: Set<provider>`、`warned: Set<provider>`：待重拉供应商与首次失败去重（`src7/plugins/model-catalog/index.ts:98`、`src7/plugins/model-catalog/index.ts:101`）。
- `cooling: Map<model, until>`：ModelCatalog 给 `ModelInfo` 附 `limitedUntil` 的限流截止时间（`src7/plugins/model-catalog/index.ts:104`）。
- `cooldowns: Map<model, { until, error }>`：ModelFallback 内存冷却表（`src7/plugins/model-catalog/Fallback.ts:138`）。
- `Queue.running / Queue.waiting`：按 `模型:<id>` 和 `供应商:<name>` 统计并发占用与 FIFO 等待队列（`src7/plugins/model-catalog/Queue.ts:22`、`src7/plugins/model-catalog/Queue.ts:25`）。
