## 数据

### 数据库表

- `model_usage`：每次成功回答和失败尝试的计量记录，字段与索引见下方“用量子功能”。

### 文件

- `models/<模型 ID 的 / 换成 __>.md`（目录可配 `notes.dir`，相对运行时目录；起来时没有就建）：一个模型一份。
  - 介绍部分
    1. 第一行写 `# <模型 ID>`。
    2. 到 `## 评价` 之前是人工写的介绍，原样读。
  - `## 评价` 下一行一条，到下一个 `#` 开头的行为止，解析不了的跳过。格式为 `- <YYYY-MM-DD HH:mm 时区缩写> · <by> · <1-5>/5 · 会话 <会话号>（<思考档>） · <一句话>`，思考档和一句话可省。旧任务评价行跳过。
  - 评分汇总
    1. 同一人对同一会话的评价只留最后一条。
    2. 会话数按会话号去重，对每场会话的评价者评分求均分。
    3. 对所有会话的均分求算术平均，保留一位小数。
  - 接口的 `task` 字段固定返回空串。
  - 写回沿用原文件的换行（CRLF/LF）；没有事务和并发锁。

### 共享会话字段

- 读取 `ChatRequest` 的字段
  - `model` 和 `signal` 仅在浅拷贝 `asked` 上替换，持久化 `session.row` 保持原样。
  - `session`
  - `answer` 会回填。

### 插件内存状态

- `tables: Map<provider, ModelInfo[]>`：当前内存模型表（`src7/plugins/model-catalog/index.ts`）。
- 拉取状态
  - `pending: Set<provider>` 保存待重拉的供应商（`src7/plugins/model-catalog/index.ts`）。
  - `warned: Set<provider>` 用于首次失败去重（`src7/plugins/model-catalog/index.ts`）。
- `cooling: Map<model, until>`：ModelCatalog 给 `ModelInfo` 附 `limitedUntil` 的限流截止时间（`src7/plugins/model-catalog/index.ts`）。
- `cooldowns: Map<model, { until, error }>`：ModelFallback 内存冷却表（`src7/plugins/model-catalog/Fallback.ts:138`）。
- 队列按 `模型:<id>` 和 `供应商:<name>` 统计
  - `Queue.running` 记录并发占用（`src7/plugins/model-catalog/Queue.ts:22`）。
  - `Queue.waiting` 记录 FIFO 等待队列（`src7/plugins/model-catalog/Queue.ts:25`）。

## 配置

回退设置从 `plugins[model-catalog].config.fallback` 读取。并发配置可沿用顶层 `concurrency`。

启用后，限流或额度耗尽会记冷却并切备用模型，上下文超长会选窗口更大的模型。上游返回 HTTP 400 且明确说明「服务信息找不到」或「service information not found」时，沿备用链换模型，无需等待冷却。普通参数错误和 401、403 鉴权错误原样返回，取消立即停止。候选用完后按尝试记录汇总报错。每次切换前在当前会话的流水留一行，教程和网页显示前后两个模型及原因。

## 思考档位

下文按本项目安装的 pi-ai 1.4.0 说明思考档与请求字段。映射和支持档位以加载后的模型配置为准。

### 通用 7 档

会话的 `thinking` 对应 pi 的 `ModelThinkingLevel`，包含以下七档（`node_modules/@earendil-works/pi-ai/dist/providers/model-schema.d.ts:8`）。

| 档位 | 一句话 |
|---|---|
| off | 不思考。怎么关要看接口，见下面的“每种接口发什么”。 |
| minimal | 最少思考，尽量快答。 |
| low | 轻量思考，适合简单任务。 |
| medium | 速度和推敲折中。 |
| high | 深入思考。 |
| xhigh | 比 high 更深，模型的 `thinkingLevelMap` 写明了才算支持。 |
| max | 最深一档，同样要映射里写明；不等于不限 token。 |

### 从会话到请求，一档怎么变成接口参数

1. `Sessions.chat()` 在会话选 `off` 时省略 `reasoning`，其余档位原样传给 pi。
2. `Resources` 读配置时校验模型的 `thinking`。列表如 `[off, low, high, max]` 使用同名接口值，对象如 `{ off: 'none', xhigh: 'very_high' }` 可以指定接口值。未列出的档和显式的 `null` 都标成不可用。
3. `Resources.getModel()` 优先使用配置的 `thinkingLevelMap`。省略 `thinking` 时，供应商名、模型 ID 和 API 都匹配的模型沿用 pi 内置映射和思考能力。请求地址与兼容设置仍取项目配置。
4. pi 的 `clampThinkingLevel` 为不支持的请求档位寻找替代档，先往深找，再往浅找。模型支持 `xhigh` 或 `max` 时，映射里能读到对应字符串。
5. 适配器按 `thinkingFormat` 组装请求。Magpie 默认走 `openai` 格式，也可由 `model_compat` 指定各模型的格式。OpenAI Completions 适配器在 `node_modules/@earendil-works/pi-ai/dist/api/openai-completions.js:625–727` 读取映射。

## 给外部 AI 的打分接口

只给你已核实完成表现的已有会话打分。用下面任一方式找原会话号，避免新建会话。

- 从主网页会话面板复制会话号。
- 查 `GET /api/sessions?bot=<机器人名>` 列表的 `id`。

本机地址 `POST http://127.0.0.1:30086/api/model-notes/rate`（端口以运行端为准），`Content-Type: application/json`：

```json
{"session":"EXISTING_SESSION_ID","by":"Codex","score":4,"note":"已核实的完成情况与不足"}
```

- 请求字段
  - `session` 非空，只许字母、数字、下划线和横杠。
  - `score` 为 1 到 5 的整数（数值）。
  - `by` 是非空标签，例如用户、Claude、Codex、Grok、Antigravity，不能含 `·` 和换行。
  - `note` 可省或为 `null`，写了不能换行。
- 不要传 `model`、`thinking`：服务端读这场会话当前的模型和思考档；多余的键忽略。
- 同一 `by` 给同一 `session` 再交一次就是改分；会话换过模型时，别的模型文件里同人同会话的旧行也清掉。
- 本机和配置的可信 IP 免令牌；别的机器带 `Authorization: Bearer <令牌>`。
- 返回
  - 成功为 200 `{ok:true,note}`。
  - 字段不对为 400，返回 `{error}`。
  - 会话打不开为 404，返回 `{error}`。
  - 文件读写等其他错误交 Fastify 默认处理（通常 500）。

##### GET /api/usage

参数和约束：

| 字段 | 类型、必填、默认及边界 |
|---|---|
| `query.by` | 可选；类型：string；默认：day；可选值：hour、day、week、month |
| `query.group` | 可选；类型：string；默认：model；可选值：provider、model、purpose、bot |
| `query.from` | 可选；类型：string转换Number；默认：to-7*24*60*60*1000；处理方式：Number值为0/NaN/空等falsy时回退；未限制负数和反向时间窗 |
| `query.to` | 可选；类型：string转换Number；默认：Date.now()；处理方式：同上；查询为at>=from且at<to |

- 定义：`src7/plugins/model-catalog/Usage.ts`
- 返回
  - 200
    - `by` 和 `group` 为实际使用的分组参数。
    - `from` 和 `to` 为数字。
    - `rows` 为分组结果。
      - `period` 按本地时区取 `strftime`：`hour` 为 `%Y-%m-%d %H:00`，`day` 为 `%Y-%m-%d`，`week` 为 `%Y-W%W`，`month` 为 `%Y-%m`。
      - `key` 为指定维度值，bot 空时为空串。
    - `rows` 的每行与 `totals` 都包含以下统计项。
      - `calls` 取 `COUNT(*)`。
      - `failures` 取 `SUM(1-ok)`。
      - `input` 取 `SUM(input)`。
      - `output` 取 `SUM(output)`。
      - `cacheRead` 取 `SUM(cache_read)`。
      - `cacheWrite` 取 `SUM(cache_write)`。
      - `cost` 取 `SUM(cost)`。
      - `ms` 取 `SUM(ms)`。
      - `hitRate` 取 `cacheRead/(input+cacheRead)`，分母为 0 时返回 0。
  - 400 返回 `error`。
    - `by` 要是 `hour`、`day`、`week` 或 `month`。
    - `group` 要是 `provider`、`model`、`purpose` 或 `bot`。
- 结构说明：Fastify仅Querystring TypeScript类型，无独立JSON Schema；以上为实际解析规则。
