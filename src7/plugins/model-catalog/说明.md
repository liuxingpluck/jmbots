# model-catalog v1.3.1

拉取各供应商 `/models` 并合并手写参数提供可查内存模型清单，并在 `session/request` 末尾接管模型调用与限流/超长回退、冷却与并发排队（已并入原 `model-fallback`），并记录模型用量与费用（`Usage.ts`，已并入原 `usage`）。

1.2.0（11-18）并入原 `model-notes`（`Notes.ts`）：模型介绍和人工评价存成 Markdown，按会话汇总评分；接口 `/api/model-notes*` 路径不变，页面 `/model-notes/` 照旧由 web 插件按文件名托管；事件 `model-catalog/request` 加 `action: 'prompt'`，一次交回派活用的模型介绍评价和能用的思考档（原来 bots/Dispatch.ts 自己拼）。

## 数据

### 数据库表

- `model_usage`：每次成功回答和失败尝试的计量记录，字段与索引见下方“用量子功能”。

### 文件

- `models/<模型 ID 的 / 换成 __>.md`（目录可配 `notes.dir`，相对运行时目录；起来时没有就建）：一个模型一份。
  - 第一行 `# <模型 ID>`；到 `## 评价` 之前是人写的介绍，原样读；
  - `## 评价` 下一行一条，到下一个 `#` 开头的行为止，解析不了的跳过：
    - 新行：`- <YYYY-MM-DD HH:mm 时区缩写> · <by> · <1-5>/5 · 会话 <会话号>（<思考档>） · <一句话>`，思考档、一句话可省；
    - 旧行：`- <时间> · <by> · <分>/5 · 任务：<任务> · <一句话>`，照读照算，不改写；
  - 同人同会话只留最后一条；会话数 N = 不同会话号数 + 每条旧行各 1；平均分 = 每场先对评价者求均分，再与旧行分数等权平均，保留一位小数；
  - 写回沿用原文件的换行（CRLF/LF）；没有事务和并发锁。

### 共享会话字段

- 读取 `ChatRequest.model / signal / session / answer`（回填 `answer`；仅在浅拷贝 `asked` 上替换 `model / signal`，不改持久化 `session.row`）。

### 插件内存状态

- `tables: Map<provider, ModelInfo[]>`：当前内存模型表（`src7/plugins/model-catalog/index.ts`）。
- `pending: Set<provider>`、`warned: Set<provider>`：待重拉供应商与首次失败去重（`src7/plugins/model-catalog/index.ts`、`src7/plugins/model-catalog/index.ts`）。
- `cooling: Map<model, until>`：ModelCatalog 给 `ModelInfo` 附 `limitedUntil` 的限流截止时间（`src7/plugins/model-catalog/index.ts`）。
- `cooldowns: Map<model, { until, error }>`：ModelFallback 内存冷却表（`src7/plugins/model-catalog/Fallback.ts:138`）。
- `Queue.running / Queue.waiting`：按 `模型:<id>` 和 `供应商:<name>` 统计并发占用与 FIFO 等待队列（`src7/plugins/model-catalog/Queue.ts:22`、`src7/plugins/model-catalog/Queue.ts:25`）。

## 给外部 AI 的打分接口

只给你已核实完成表现的已有会话打分。会话号从主网页会话面板复制，或查 `GET /api/sessions?bot=<机器人名>` 列表的 `id`；不要新建会话代替原会话。

本机地址 `POST http://127.0.0.1:30086/api/model-notes/rate`（端口以运行端为准），`Content-Type: application/json`：

```json
{"session":"EXISTING_SESSION_ID","by":"Codex","score":4,"note":"已核实的完成情况与不足"}
```

- `session`：非空，只许字母、数字、下划线、横杠；`score`：1 到 5 的整数（数值，不是字符串）；`by`：非空标签（用户、Claude、Codex、Grok、Antigravity 等），不能含 `·` 和换行；`note` 可省或 null，写了不能换行。
- 不要传 `model`、`thinking`：服务端读这场会话当前的模型和思考档；多余的键忽略。
- 同一 `by` 给同一 `session` 再交一次就是改分；会话换过模型时，别的模型文件里同人同会话的旧行也清掉。
- 本机和配置的可信 IP 免令牌；别的机器带 `Authorization: Bearer <令牌>`。
- 成功 200 `{ok:true,note}`；字段不对 400、会话打不开 404，都是 `{error}`；读写文件等别的错交 Fastify 默认处理（通常 500）。

##### GET /api/usage

参数和约束：

| 字段 | 类型、必填、默认及边界 |
|---|---|
| `query.by` | 可选；类型：string；默认：day；可选值：hour、day、week、month |
| `query.group` | 可选；类型：string；默认：model；可选值：provider、model、purpose、bot |
| `query.from` | 可选；类型：string转换Number；默认：to-7*24*60*60*1000；处理方式：Number值为0/NaN/空等falsy时回退；未限制负数和反向时间窗 |

- 返回：200：by：实际by；group：实际group；from：number；to：number；rows：period：按本地时区strftime：hour %Y-%m-%d %H:00；day %Y-%m-%d；week %Y-W%W；month %Y-%m；key：指定维度值，bot空时为空串；calls：COUNT(*)；failures：SUM(1-ok)；input：SUM(input)；output：SUM(output)；cacheRead：SUM(cache_read)；cacheWrite：SUM(cache_write)；cost：SUM(cost)；ms：SUM(ms)；hitRate：cacheRead/(input+cacheRead)，分母0返回0；totals：calls：COUNT(*)；failures：SUM(1-ok)；input：SUM(input)；output：SUM(output)；cacheRead：SUM(cache_read)；cacheWrite：SUM(cache_write)；cost：SUM(cost)；ms：SUM(ms)；hitRate：cacheRead/(input+cacheRead)，分母0返回0；400：error：by 要是 hour、day、week、month；group 要是 provider、model、purpose、bot

### 数据

#### 数据库表

`model_usage` 存每一次模型调用的用量和花费；一行是一次调用（重试的每一次各一行，失败也记）。整行由 `Usage.add` 写。

| 列名 | 类型 | 能不能空 | 意思 | 谁写、什么时候写 |
|---|---|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 否 | 自增号 | `add` 插入时 |
| `at` | INTEGER NOT NULL | 否 | 写入毫秒时刻 | `add`：`session/message` 接进模型回答时记成功；`model/failed` 时记失败 |
| `provider` | TEXT NOT NULL | 否 | 供应商（模型 ID 斜杠前那段） | `add` |
| `model` | TEXT NOT NULL | 否 | 完整模型 ID `供应商/模型` | `add` |
| `kind` | TEXT NOT NULL | 否 | 固定 `chat` | `add` |
| `purpose` | TEXT NOT NULL | 否 | 用途：work→session、front→dispatch、compress→compact，其余照会话种类 | `add` 照 `PURPOSES` 映射 |
| `bot` | TEXT | 能 | 机器人 | `add` |
| `session_id` | TEXT | 能 | 会话号 | `add` |
| `input` | INTEGER NOT NULL | 否 | 输入 token | `add`；失败记 0 |
| `output` | INTEGER NOT NULL | 否 | 输出 token | 同上 |
| `cache_read` | INTEGER NOT NULL | 否 | 缓存读 token | 同上 |
| `cache_write` | INTEGER NOT NULL | 否 | 缓存写 token | 同上 |
| `cost` | REAL NOT NULL | 否 | 美元花费（model-catalog 价格算；查不到价格记 0） | `add` |
| `ms` | INTEGER NOT NULL | 否 | 调用用时毫秒 | `add` |
| `ok` | INTEGER NOT NULL | 否 | 1 成功 / 0 失败 | `add` |
| `error` | TEXT | 能 | 失败原因（最多 300 字） | `add`，只有失败时 |

依据：`Usage.ts`的构造函数建表；`add`收到事件时取时间、查价后插入，表结构与原usage一致。

索引：`model_usage_at (at)`、`model_usage_session (session_id, at)`。本插件不清理旧行。

#### 固定数据类型

- **UsageRecord**
  - **字段**
    - at：写入时Date.now毫秒时间戳
    - provider：完整模型ID第一个/前的供应商
    - model：完整供应商/模型ID
    - kind：固定chat
    - purpose：work→session，front→dispatch，compress→compact，其余会话kind原样
    - bot：会话row.bot，可选
    - sessionId：session.id，可选
    - input：pi usage.input原值；失败0
    - output：pi usage.output原值；失败0
    - cacheRead：pi usage.cacheRead原值；失败0
    - cacheWrite：pi usage.cacheWrite原值；失败0
    - cost：按四类token分别乘对应单价再除1e6；price不存在时0；input/output沿用输入输出单价，缓存单价缺省0
    - ms：成功回答durationMs或0；失败info.ms
    - ok：数据库ok===1
    - error：失败原因，可选；成功无此字段
  - 来源：`src7/plugins/model-catalog/Usage.ts`
- **Bucket**
  - **字段**
    - calls：COUNT(*)
    - failures：SUM(1-ok)
    - input：SUM(input)
    - output：SUM(output)
    - cacheRead：SUM(cache_read)
    - cacheWrite：SUM(cache_write)
    - cost：SUM(cost)
    - ms：SUM(ms)
    - hitRate：cacheRead/(input+cacheRead)，分母0返回0
  - 来源：`src7/plugins/model-catalog/Usage.ts`

### 配置

`plugins[model-catalog].config.usage`：可省略或写`{}`；原usage没有子配置项，因此非法类型或非空对象在入口拒绝。配置不写时仍启用计量，不新增开关或默认值。

补充：记录的是回答事件与失败尝试，不包含静态分析未证实的嵌入/生图计量。；Usage.list用BETWEEN包含两端；report聚合用左闭右开；不能把二者写成相同时间窗。；报告时区来自SQLite localtime，不是model-notes的America/New_York设置。；输入和缓存读费用按当前公式分别相加；不推断第三方usage字段包含关系或实际账单费用。

事件监听与usage服务归model-catalog作用域，卸载一起撤销；Fastify原生路由与原实现相同，增删/升级配置随整体服务重启生效，不承诺热卸载路由。没有新增用量工具或改变统计时区。
