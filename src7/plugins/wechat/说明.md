# wechat v1.2.14

1.2.14 客服页 `GET /api/wechat-kefu/messages` 增加可选 `version` 轻量判变快速路径：在连接 `temp` 库按 `(account, chat)` 维护增删改触发修订号（结合进程代次与 `PRAGMA data_version`），常规 3 秒轮询无变化时直接回 `{ unchanged: true, version }`，不再每次查询和序列化千条历史正文；有新消息、旧历史补录、原地撤回更新或重启重连时回 `{ unchanged: false, version, messages }`，未传 `version` 的调用方仍原样返回消息数组。`Store.save` 对已存消息在微信侧发生撤回等字段变更时原地刷新展示，不当新消息重复交给机器人。

1.2.13 标准消息的 `role` 直接写 `guest`：微信地址一律 `owner: false`，说话的一律是外人（原来经 channels 的 `resolveLegacyRole` 推，结果一样，那个函数已删）。`SessionRow.customer` 不再在这里声明，由 bots 一处声明，本插件只往地址上写 `customer`。

1.2.12 交给机器人的话经 channels 的 `emitInbound` 发：私聊 `channel/direct`，群里 @我 `channel/mention`（called 恒为 true），`routing: { autoFinal: true }`。

1.2.11 旧路自动回话（会话一轮结束、旧会话中途一句、前台送后台结果）也经 `channel/reply` 来，删渠道自己的 `send`；带会话号的只发做完的一轮。

同步请求、缩略图和引擎临时目录使用 `utils/Files.ts` 的 `ensureDir` 创建。

1.2.8 微信回话地址统一由 getWechatAddress 生成，固定带 owner: false，微信来的会话按外人算（工具只剩只读白名单）。

1.2.6 保留微信读取引擎启动失败时的原异常链。

客服页 `/wechat-kefu/` 在右栏展示待处理的 AI 建议。

1. 已监听的会话可点「让 AI 起草建议」。
2. 完成后可复制正文，演示打码时禁用复制。

页面没有发送按钮或自动发开关。后端保留 `/send`、`/outbox/send` 与 `send` 配置。默认 `send` 不为 true 时仅存草稿。

会话轮询规则

- 复用内置渠道最近 8 秒内成功读取的结果，同账号并发扫描共用一次引擎请求。
- 「一键扫描」跳过缓存。
- 监听状态从数据库实时读取。
- 页面只在数据有变化时提交轮询结果。搜索输入复用已排序的会话列表。

客服页 `/wechat-kefu/` 在消息气泡里显示语音时长和播放控件，点击播放才提取原音频。取不到时在原位置显示原因。演示打码会隐藏播放器和音频。

取音步骤

1. `Reader.voice` 按账号、会话、来源分片和消息号调用 `wechat_cli media --request` 的 `op: voice`。
2. `VoiceAudio` 检查 SILK 格式，用 `silk-wasm` 解码。
3. 实际时长与气泡记录相差一秒以内时，缓存为 `bots/<机器人>/message/wechat_voice_<消息键摘要>/voice.wav`。
4. 接口回 WAV 或一句脱敏原因。历史未记录时长时，页面显示播放器测到的时长。

缩略图和语音都读取 `wechat_cli media` 在 stdout 返回的结构化原因。

- 缺原件或图片解密密钥等失败回 404，带 `error` 和 `code`。日志仅记媒体类型、脱敏错误码及已知退出码。
- 按账号、会话、分片和消息号合并并发请求。
- 失败后 30 秒内复用同一结果，每种媒体最多缓存 512 条失败。
- 成功复用原有文件缓存。

取图片和语音只查本机微信已存在的文件与数据库副本，沿用程序自己的解密缓存和输出目录。图片和语音两个入口均不触发微信登录、联网或发包。

单文件 EXE 构建时，`Build_Src7.ts` 把 WASM 作为编译资产嵌入，并把实际资产路径交给 SILK 加载器的 `locateFile`。

本地 sherpa 转写经 voice 插件的实时麦克风入口运行。

- 当前 `voice/request` 提供状态、播报和停止。微信语音以播放器展示。
- 接入转写需要 voice 插件提供文件或 PCM 输入的请求动作，并回传文本及失败原因。

挂载 memory 后用 `memory_get` 翻当前微信渠道历史。

- 查询下一页时传 `before`。

微信渠道读取本机账号会话与消息。

- 自动起草
  1. 按监听名单经 `emitInbound` 交机器人起草：私聊发 `channel/direct`，群里 @我 发 `channel/mention`，带 `routing.autoFinal`。bots 按来源范围排进这个客户的前台，沿用同客户的旧前台。
  2. 一轮里 `channel_reply` 调几次就进几条发件。一次没调就把最后的话进发件。
  3. 模型的话照旧要本人点头才发，审批直回不再问。默认存草稿，显式开启 send 后经后台 worker 发送。
- 所有发到微信的话都经 `channel/reply` 到 `sendDirectText`，向 bots 只登记渠道名 `ctx.bots.channel(name)`。
- 旧路自动回话由 bots 的 `Bots.send` 发：没有来源快照，`target.address` 是会话记的微信地址，带 `sessionId`。`refuseUnfinished` 只放行会话 state 为 done 的一轮，出错、停下或还在转的不发给客户（rejected）。
- 跨渠道发话：`registerTextReply` 挂入 `getTargetAddress`，从微信自有表自认目标聊天。
- 手动起草：`draftReply` 仍走 `bots.receive`，前台按客户找到的是同一场。客户前台的认领已移出 `bot/receive`。

- 目录名和渠道名为 `wechat`，配置中的插件注册名为 `wechat-kefu`。
- `apply` 把公共方法交给页面路由和插件闭包。
- 模块导出 Reader、Sender 和 Window 三个类。
