# wechat v1.1.4

读取本机微信账号会话与消息，按监听名单经统一事件 `channel/message` 交机器人起草（`routing.autoFinal`：bots 按来源范围排进这个客户的前台，同客户的旧前台沿用；一轮里 `channel_reply` 几次进几条发件，一次没调就把最后的话进发件；`registerTextReply` 挂入 `getTargetAddress` 从微信自有表自认跨渠道目标聊天；模型的话照旧要本人点头才发，审批直回不再问；默认存草稿，显式 send 开启后经后台 worker 发送）；`History.ts`（`WechatHistory`）监听 `channel/history` 从 `wechat_messages` 回答跨渠道与当前微信会话历史并回传 `channel/history-result`。不再在 `bot/receive` 里按客户认领前台；手动起草（`draftReply`）还走旧入口 `bots.receive`，前台按客户找到的是同一场。

目录名为 `wechat`；配置可用 `wechat-kefu`，并保留旧别名 `wechat`；模块导出插件名为 `wechat-kefu`（`src7/plugins/Index.ts:137`、`src7/plugins/wechat/index.ts:32`）。Wechat虽export class，但apply未ctx.provide，公共方法实际给page.routes/插件闭包调用；Reader/Sender/Window为模块导出类，非独立Cordis服务。

## 听的事件

| 事件 | 位置 | 收到后做什么 |
|---|---|---|
| session/request | `src7/plugins/wechat/index.ts` | 地址customer=wechat前缀且account/chat都有时，读最近50条微信消息按时间升序加system，固定附草稿提醒 |
| web-api/status | `src7/plugins/wechat/index.ts` | push name:wechat/bot/connected:lastError为空/detail轮数或错误 |

| channel/reply | `src7/plugins/wechat/index.ts` | registerTextReply 响应模型的 channel_reply、零次兜底（askApproval:true，没开自动发要点头）和审批直回（轮名 approval，askApproval:false），写发件箱或发送队列，并回发channel/replied |
| channel/history | `src7/plugins/wechat/History.ts` | WechatHistory监听，本人可跨渠道/跨聊天查，外人仅当前微信会话；读wechat_messages并回发channel/history-result |
| approval/decided | `src7/plugins/wechat/index.ts` | 仅可选approval已挂；wechat-send payload.outbox批准deliver，其他mark rejected |
