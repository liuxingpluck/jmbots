# progress v1.1.9

跟踪会话一轮进度、长跑提醒、限时与延长/交接，并登记超时并在空闲时自动写复盘存入公共记忆（已并入原 review）。

## 飞书群每日进度

同时挂载 `feishu`、`progress` 和 `memory`。在飞书插件 `groups` 的目标群里填 `daily: { at: "17:30", bot: 周小灵, prompt: "应汇报成员：小林、小周。按交付、阻塞、明日安排汇总。" }`。`at` 用运行机器所在时区，重启错过的当天不补。机器人有多个有效应用时填 `daily.app_id`。启用日报时未填 `listen` 的群默认用 `all`，普通成员回复照常进本群记忆。

`GroupDaily.ts` 在预定时刻发 `channel/message`，来源标为 `daily-progress`，只派给该群指定机器人。它使用当天独立的前台轮，按 `channel_search` 读上次计划时刻到本次的群记录，用 `channel_reply` 回原群。把应汇报成员的准确群名片姓名写进 `prompt`，汇总时才能对照名单提醒未汇报的人。飞书发送时把已知群成员或 `people` 里登记的 `@姓名` 转成真实提及，未识别的名字保留为文字。

## 设计要点

- 限时、报时、长跑询问留在插件，骨架只提供状态、消息、请求、停止等通用口。
- 带渠道的 work 即使有 parent 也要受进度管理，内部小会话不纳入，避免漏掉前台交办的后台。
- 请求中的报时只改副本；卡片由 approval + feishu 承载；结束/取消与后续收尾是不同的事实。
- 会话上持久的 progress 和进程内 timers 分开；重启能延续计时不代表完整过程已恢复。
- 复盘（Review）：只在进度空闲且没有待审复盘时挑超时记录，避免工作中再发起重模型任务；先写 reviewedAt 再生成，取舍是防反复提醒，模型出错不保证自动重试。
- 复盘建议先交 approval，本人确认后才写共享 memory/复盘；只归纳已记录的工作过程，不把预计提速写成实测；记录位置通过可选 filesMirror.getDir 取，不假定镜像插件或文件一定存在。
