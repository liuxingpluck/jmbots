# host-guard v1.0.0

宿主机守卫：只盯跑 jmbots 的这台 Windows 宿主机的两条硬线（用户 #442/#443），不管 CPU。

- 物理内存不超过 `max_ram_gb`（默认 60 GB）。
- 任何一张显卡的显存不超过 `max_vram_gb`（默认 15.5 GB）。

只观测、告警、只读诊断，**绝不杀进程**。

1. 每 `interval_sec` 秒采样一次，每条线各记一个档位：`ok`、`warn`（过预警线）、`exceeded`（过红线）、`unknown`（读不到）。
2. 超线且离上次同线告警过了 `cooldown_sec` 才发一次告警，顺带拉一次占用前 5 的进程。
3. 告警后连续 2 次 `ok` 才发一次“已回落安全线”，预警档或读不到都让计数清零。
4. 告警发事件 `host-guard/alert`，配了 `notify_feishu` 再写一份进飞书发件箱；最近 50 条留在内存里。

GB 都按 GiB（1024³ 字节）算，和 programs 资源守卫同口径。

## 和 programs 资源守卫的分工

programs 插件的资源守卫（`src7/plugins/programs/ResourceGuard.ts`）管自己托管的外部程序：重活准入、高位时暂停、必要时关掉一个，并在 60 GB 发飞书。
本插件只看宿主机整机、只报不动手，显存红线按用户新定的 15.5 GB。
两边都开时，内存超线会各发一次；所以本插件的 `notify_feishu` 默认关，只发事件和接口，要飞书提醒再打开。
显存读数直接复用 programs 的 `ResourceProbe`（同一份 nvidia-smi 读法），不另写一套。

### HTTP 接口

| 接口 | 鉴权 | 返回 | 作用 | 定义位置 |
|---|---|---|---|---|
| GET /api/host-guard/status | 照 http 插件（本机不查令牌） | HostSnapshot | 只读看最近一次快照；还没采过时 `sampledAt` 是 null。 | `src7/plugins/host-guard/index.ts:421` |
| POST /api/host-guard/check | `ctx.http.isVerified`，不过回 403 | HostSnapshot | 立刻采一次再回。 | `src7/plugins/host-guard/index.ts:422` |

HostSnapshot：`{sampledAt, ram, vram, gpuAvailable, exceeded, alerts, top:{ram,vram}}`；ram、vram 是 `{usedGb, totalGb, maxGb, warnGb, level, alerting}`，读不到时 usedGb、totalGb 为 null。

## 配置

在 `config.yaml` 的 `plugins` 里加 `- name: host-guard`，`config` 都可省略：

| 配置键 | 默认 | 约束 |
|---|---|---|
| max_ram_gb | 60 | 正数 |
| warn_ram_gb | 54 | 正数，比 max_ram_gb 小 |
| max_vram_gb | 15.5 | 正数，按单卡算 |
| warn_vram_gb | 14 | 正数，比 max_vram_gb 小 |
| interval_sec | 30 | 5～600 的整数 |
| cooldown_sec | 300 | 不小于 0 的整数 |
| notify_feishu | false | true 或 false |
| nvidia_smi | nvidia-smi | 非空文字，命令名或路径 |

配置校验在 `src7/plugins/host-guard/index.ts:86`。
