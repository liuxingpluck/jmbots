# tutorial v1.1.6

一句话：教程页 `/tutorial/`——左栏最上方按 `kind: 'skeleton' | 'plugin'` 列出系统骨架（`main`、`resources`、`tools`、`sessions`，版本号取自 `Versions.ts`，文档与代码索引直接从源码提取，不另建 `说明.md`）并修复左栏顶部行被搜索框遮挡；泳道画布铺满底层并支持拖拽平移与滚轮缩放，左右两栏悬浮在画布上方可拖宽、可收起、长列表虚拟滚动，右栏顶部双页签「这一步 / 插件」（看步详情或翻看源码时不遮丢画布），全部文件:行号支持点开 VS Code。11-17 由 flow（画布、运行时变量、快照）、boot-trail（录启动）、trace（打印执行路径）合成。要写在 config.yaml plugins 段的**第一个**：录启动要赶上后面每个插件开始挂。

## 依赖

- inject `resources`：运行时目录（快照文件放 `data/flow/`）、配置里的插件名单、挂载结果 `pluginStatus`。
- inject `sessions`：录启动时数一下要接着跑几场会话；拍快照时认子会话（`live` 里的 `row.parent`）。
- 可选 `http`（`ctx.inject(['http'])`，http 起来后才登记接口）：登记下面的 HTTP 接口和 `/flow/` 跳转。
- 可选 `journal`（`ctx.get('journal')`）：按 `query` 取最近消息列表（不限 `#调试`，只在打开页面时读已有行），按 `request()` 取一条消息的跟踪行现算轨迹与预览。
- 可选 `tools`（`ctx.get('tools')`）：录启动时比出每个插件多登记了哪些工具。
- 自带插件名单 `plugins/Index.ts` 的 `BUILT_IN`：用到时 `await import`，列插件、读版本号。

## 数据

- 不建数据库表。
- `<运行时目录>/data/flow/boot.json`：这次启动的轨迹加每步快照，每次启动覆盖。
- `<运行时目录>/data/flow/<消息号>.json`：带关键词的消息的轨迹（`message`、`session`、`bot`、`channel`、`preview` 用户那句话、`at`、`ms`、`state`、`error`、`steps` 每一步、`notes` 键的解释）加 `snapshots`（每步那一刻的运行时变量和比上一步变了的路径）。只留最近 `snapshot_files` 个。
- `<运行时目录>/trace/<日期>.log`：`trace_file` 开着时的执行路径。
- 内存：录下的启动；带关键词的消息最近 500 份快照，按 JSON 新占字节估算并按 `snapshot_max_mb` 预算淘汰，至少保留最新一份。

## 配置

| 键 | 默认 | 作用 |
|---|---|---|
| `snapshot_keyword` | `#调试` | 话里带它的消息才拍快照，拍完从话里去掉 |
| `snapshot_max_mb` | 200 | 内存里的快照加起来最多多少 MB |
| `snapshot_files` | 20 | `data/flow/` 里消息文件留几个 |
| `recent_messages` | 50 | 「会话」左栏从 journal 按消息号去重最多列最近几条消息 |
| `workspace` | 空（自己往上找带 `src7/Main.ts` 的目录） | 源码根目录，「在 VS Code 里打开」用 |
| `trace_console` | false | 控制台打印执行路径 |
| `trace_file` | false | 执行路径同时写进 `trace/` |
| `trace_var_limit` | 200 | 打印时一个值最多几个字 |

### 嵌套结构

- FlowFile：Trail固定11字段 + snapshots数组；schemas.FlowFile继承Trail，不能只列message JSON的扁平字段而漏steps/docs/snapshots。
- Trail.steps[]：TrailStep → rows:TrailRow[]、docs:CodeDoc[]；notified为只听不留跟踪点的插件名。
- FlowFile.snapshots[]：null或StepShot{at,no,node,groups:StateGroup[],changed:string[][]|null}；changed是变更路径数组，不是具体旧新值。
- StateGroup：固定{name,note,value,notes}；value是unknown动态序列化值；除main的argv/candidate/pid及读取失败error外，没有固定内部字段全集。
- CodeDoc：继承ParsedDoc{summary,params:[{name,text}],returns,throws,effects}，另{name,site,important,missing,signature}。
- Lanes：{columns:string[],lanes:string[],cells:[{lane,column,items:[{step,text}],error}],edges:[{from,to}]}；lane/column/cell边索引均0基，step从1起。
- FunctionSource：{file,start,end,cut,lines,calls:[{name,site}],name,callers:[{site,code,why}]}。
- notes：Record<string,string>为动态键说明；message轨迹FACT_KEYS是有限表，boot轨迹FACT_NOTES有限表，注册组notes由插件提供。

### HTTP 路由登记簿与索引边界

进程内实际登记HTTP路由簿，不是配置、SQL表或JSON持久文件。
onRoute同步查看调用栈，取第一个src7/plugins/<folder>帧，跳过Routes.ts自身；定位失败owner/site空串，归others。
method可能单个或数组，展开后每项一条；代码对所有HEAD均跳过，不仅自动HEAD。

- 函数：插件目录下非测试TS顶层export function/export class（含async）；不含interface、const箭头和类方法全集。
- 路由：实际登记簿按owner文件夹过滤；others是owner空串，所有插件页试一试底部显示同份others。
- 调用方：仅扫描src7非测试源码中引号紧邻URL的词法出现，排除登记行；不扫描web、不证明真实HTTP调用，不提供运行时调用链。
- 工具：BootTrail.toolOwners挂载时工具名到插件名映射，与当前Tools.specs交集；不保证包含挂完以后登记的工具。工具清单只展示，不提供工具执行接口。
