# tutorial v1.2.5

1.2.5 快照和载荷按 `utils/Trace.ts` 给每次派发、每个跟踪点发的号（journal 的 `seq` 列）对齐流水行，不再按 50ms、200ms 的时间窗猜；改版前没有号的旧行、旧载荷就不对齐（快照空着、载荷 step 照旧），不报错（云端 36 号第 2 条）。

教程页：看懂每个插件、每条消息怎么走。

- 录启动、录消息：跟着挂载事件和 journal 的轨迹，摆成泳道图，跟踪点上拍运行时变量。
- 读文档：骨架、插件说明、组块阅读、骨架逐行、事件目录，都从源码目录现读。
- 把 tutorial 写在 `config.yaml` 的 `plugins` 段第一个，录启动时才能赶上后续每个插件开始挂。

## 依赖

- inject `resources`
  - 运行时目录，快照文件放 `data/flow/`
  - 配置里的插件名单
  - 挂载结果 `pluginStatus`
- inject `sessions`
  - 录启动时数一下要接着跑几场会话。
  - 拍快照时按 `live` 里的 `row.parent` 识别子会话。
- 可选 `http`（`ctx.inject(['http'])`，http 起来后才登记接口）：登记下面的 HTTP 接口和 `/flow/` 跳转。
- 可选 `journal`（`ctx.get('journal')`）
  - 按 `query` 取最近消息列表，不限 `#调试`，只在打开页面时读已有行。
  - 通过 `journal/request` 的 `trail` 读取消息及关联会话的行和整理好的轨迹，用来画画布、对快照、补左栏预览；`boot-trail` 把录下的启动行交给 journal 收成启动轨迹。`maxLines` 只计算匹配行。
- 可选 `tools`（`ctx.get('tools')`）：录启动时比出每个插件多登记了哪些工具。
- 自带插件名单 `plugins/Index.ts` 的 `BUILT_IN`：用到时 `await import`，列插件、读版本号。

## 数据

- 不建数据库表。
- `<运行时目录>/data/flow/boot.json`：这次启动的轨迹加每步快照，每次启动覆盖。
- `<运行时目录>/data/flow/<消息号>.json` 保存带关键词的消息，只留最近 `snapshot_files` 个。
  - 轨迹字段 `message`、`session`、`bot`、`channel`、`at`、`ms`、`state`、`error`。
  - `preview` 是用户那句话，`steps` 记录每一步，`notes` 是键的解释。
  - `snapshots` 记录每步的运行时变量和比上一步变了的路径。
- `<运行时目录>/data/flow/<消息号>.payload.json` 保存消息经过 15 类白名单事件时的真实参数对象前后拷贝与 `diff`，只留最近 `payload_messages` 个。
- `<运行时目录>/trace/<日期>.log`：`trace_file` 开着时的执行路径。
- 内存保留
  - 录下的启动。
  - 带关键词的消息最近 500 份快照，按 JSON 新占字节估算，按 `snapshot_max_mb` 预算淘汰，至少保留最新一份。
  - 最近 `payload_messages` 条消息的事件参数载荷桶（单份上限 `payload_item_kb` KB，单消息上限 `payload_message_mb` MB）。

| 键 | 默认 | 作用 |
|---|---|---|

| `snapshot_max_mb` | 200 | 内存里的快照加起来最多多少 MB |
| `snapshot_files` | 20 | `data/flow/` 里消息文件留几个 |
| `recent_messages` | 50 | 「会话」左栏从 journal 按消息号去重最多列最近几条消息 |

| `trace_file` | false | 执行路径同时写进 `trace/` |
| `trace_var_limit` | 200 | 打印时一个值最多几个字 |
| `payload_record` | `all` | 事件参数载荷录制模式：`all` 每条消息都录，`keyword` 只录带快照关键词的 |

## 补充：页面怎么用

画布的两种看法（左下角「表格」「顺序图」切换，默认表格，都在 `web/src/Tutorial/` 里）

- 表格：`LaneChart.tsx`，一道一行、一个阶段一列，格子里是步。
- 顺序图：`SeqChart.tsx`，一道一个插件、时间往下，每一步是它那道上的一个方块；这一步发的事件是一支箭头，从发出方指向每个监听者（没人听画一小截）。
  - 点方块：选中这一步，右栏看插件、函数、文件:行（VS Code 图标）、一句人话、关键变量，和表格一样。
  - 点箭头：选中这一步并高亮这个事件，右栏「这一步」顶上出事件详情：事件名、谁发谁听（带文件:行）、数据的 TS 类型（读 `GET /api/tutorial/events`）、这一次实际带的值（跟踪点记下的关键值）。表格里点事件名也出同一块。
  - 事件目录没生成时，详情里写明怎么生成，其余照常。
- 左栏「一条飞书消息的路线」：静态九站（`SeqChart.tsx` 的 `FEISHU_ROUTE`），写的是方案终态的事件名，没跑过消息也能看；是插件的标签能点，右栏看它的事件。

数据与接口

事件目录

- 数据是 `src7/docs/事件目录.json`，由 `bun ztools/check-events/Check_Event_Docs.ts` 扫源码写出（每次跑都会按源码重写，内容不变不动文件）。
- `GET /api/tutorial/events` 原样交出：`{ events: [...] }`，按事件名排。每项有 `name`、`mode`（挨个问、通知、请求-回执，没人发写“没人发”）、`pair`（请求和回执互为一对，没有是空串）、`declaredAt`（文件:行）、`signature`、`doc`、`params`（每个参数的名字、可选、类型、`@param` 说明）、`types`（签名里用到的接口和类型别名，展开一层：字段名、可选、类型、一句注释、定义处文件:行；接口的 `extends`、别名里引用的类型一并算）、`senders`、`listeners`（各项带插件名、函数、文件:行）。
- 还没生成这个文件时回 404，错误里写明怎么生成。编译版由 `scripts/Build_Src7.ts` 嵌入。
- 消息轨迹现在从渠道收到那一行起（飞书是 `Feishu.start`），由 journal 按标准消息号串好后交来，`Lanes.ts` 把渠道那几行摆在「收到」列。

### HTTP 路由登记簿与索引边界

进程内实际登记HTTP路由簿，不是配置、SQL表或JSON持久文件。
onRoute同步查看调用栈，取第一个src7/plugins/<folder>帧，跳过Routes.ts自身；定位失败owner/site空串，归others。
method可能单个或数组，展开后每项一条；代码对所有HEAD均跳过，不仅自动HEAD。

- 函数：插件目录下非测试TS顶层export function/export class（含async）；不含interface、const箭头和类方法全集。
- 路由：实际登记簿按owner文件夹过滤；others是owner空串，所有插件页试一试底部显示同份others。
- 调用方：仅扫描src7非测试源码中引号紧邻URL的词法出现，排除登记行；不扫描web、不证明真实HTTP调用，不提供运行时调用链。
- 工具：BootTrail.toolOwners挂载时工具名到插件名映射，与当前Tools.specs交集；不保证包含挂完以后登记的工具。工具清单只展示，不提供工具执行接口。
