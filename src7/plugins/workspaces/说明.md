# workspaces v1.1.0

1.1.0 `getAccess(bot, channel, address)` 多收渠道名，是不是本人改问 channels 协议插件的 `isOwnerTurn`（原来的 `isNonOwnerSpeaker` 删了）。真实渠道的地址都写了身份，判断不变；只有非本机渠道、地址一个身份字段都没写的，从本人变成外人（宁严勿松）。

默认工作区目录由 `utils/Files.ts` 的 `ensureDir` 创建。

一个机器人可以有多个工作区。每个工作区归属一个机器人，名字可以重复，ID 由 `crypto.randomUUID` 生成，唯一。

- 服务为 `ctx.workspaces`。
- 模型工具为 `workspace`。

- 旧目录原地登记，不搬不删。
  - `bots/<机器人>/workspace/` 登记为 private 默认工作区。
  - 机器人配置 `workspaces` 里的目录（例如源码仓库）登记为 private 工作区，只给本人。
  - 外人（builder、guest）的根，即飞书写进回话地址的 `workspace`（`utils/Workspace.ts` 的 `getWorkspace`），第一次用到时登记为该范围的默认工作区。
  - `hand_session` 的旧 `workspace` 相对路径首次使用时登记。
- 新建的工作区目录是 `bots/<机器人>/workspaces/<ID>/`。改名只改名字，归档只改状态，都不动文件。
- 工作区访问范围
  - 本人能查看和使用这个机器人全部范围的工作区。
  - 外人只查看和使用自己范围（`scope_key`）的工作区。拿别人的 ID 时回 `workspace_forbidden`，不透露名字和目录。
- 前台通过 bots 的 `hand_session` 派后台时
  1. 按 ID 选工作区，将 ID 绑在后台会话的 `row.workspaceId`。
  2. 将解析出的目录照旧写进后台回话地址的 `workspace`。file-tools、exec、image-gen 和 feishu 沿用该地址。

## 依赖

| 服务 | 类型 | 用途 |
|---|---|---|
| resources | 必需 | 库（建表 `workspaces`）、运行时目录 `root`（目录的存法、新建目录） |
| tools | 必需 | 登记工具 `workspace` |

被依赖：bots（必需，plugins 段 workspaces 要写在 bots 前面）。

## 听的事件

无。

## 发的事件

| 事件 | 什么时候 | 数据 |
|---|---|---|
| workspaces/changed | 存库以后：新建（含旧目录、默认第一次登记）、改名、归档。重复登记、改成同名、再归档一次不发 | `{ workspaceId, bot, action: 'created' \| 'renamed' \| 'archived' }`，不带目录 |
| trace | 定下工作区（`Workspaces.resolve`）、工作区变了（`Workspaces.emitChanged`） | 工作区、名字、范围、目录 / 机器人、动作 |

## 工具 workspace（只给前台）

| 参数 | 说明 |
|---|---|
| action | 必写：`list`、`get`、`create`、`rename`、`archive` |
| id | `get`、`rename`、`archive` 用 |
| name | `create`、`rename` 用 |
| includeArchived | `list` 用：归档的也列 |

交回 JSON

- 返回工作区时为 `{ ok: true, workspace }`。
- 返回清单时为 `{ ok: true, items }`。
- 出错时为 `{ ok: false, error: { code, message } }`。

权限

- `create`、`rename`、`archive` 只有本人能用。
- 工具只给前台。后台会话的回话地址中，`workspace` 已换成干活的目录，不能据此算外人的范围。
- 外人当前拿不到这个工具（approval 的 `READ_ONLY_TOOLS` 里没有它），服务里仍按范围限制。

## 对外函数（`ctx.workspaces`，都是同步的）

| 名称 | 参数 | 返回 | 作用 | 错误码 |
|---|---|---|---|---|
| getAccess | bot、channel（会话的渠道名，没有渠道传 undefined）、address（回话地址） | WorkspaceAccess `{ bot, owner, scopeKey, root }` | 从渠道和回话地址算谁在用：channels 的 `isOwnerTurn` 判是不是本人；`utils/Workspace.ts` 的 `getWorkspace` 算根目录；本人范围 `private`，外人范围 `dir:<他的根目录>` | 无 |
| create | `{ name }`、access | Workspace | 新建 private 工作区，目录 `bots/<机器人>/workspaces/<ID>/`；只给本人 | workspace_forbidden、workspace_invalid_name |
| get | id、access | Workspace | 按 ID 取，归档的也给 | workspace_not_found、workspace_forbidden |
| list | access、`{ includeArchived? }` | Workspace[] | 本人列全部范围、外人列自己范围；默认只列 active；按登记先后 | 无 |
| rename | id、name、access | Workspace | 只改名字；同名原样交回不发事件；只给本人 | workspace_forbidden、workspace_not_found、workspace_invalid_name |
| archive | id、access | Workspace | 归档，不动文件；已归档原样交回；默认的不能归档；只给本人 | workspace_forbidden、workspace_not_found、workspace_default_protected |
| resolve | access、selection `{ workspaceId?, legacyDirectory?, legacyName?, allowArchived? }` | ResolvedWorkspace `{ workspace, directory }`（directory 是绝对路径） | 写了 ID 按 ID 查归属和范围；写了旧目录（调用方已查过范围）就是范围根的算默认，别的没登记过原地登记；都不写是这个范围的默认。归档的只在 `allowArchived` 时给（已绑定的后台接着用，模型填不了） | workspace_not_found、workspace_forbidden、workspace_archived |
| ensureDefault | bot | Workspace | 登记 private 默认 `bots/<机器人>/workspace/`（目录没有就建），按目录认，反复调交回同一条；bots 建机器人时调 | 无 |

`WorkspaceError`：带 `code`（错误码）和 `reason`（一句话），`message` 是 `code：reason`。前台派活时原样抛给模型看。

调用方

- bots 的 `Bot` 构造函数用 `ensureDefault`，通过 `resolve` 登记配置目录。
- `Dispatch.getWorkspace` 用 `getAccess` 和 `resolve`。
- `Dispatch.list` 用 `getAccess` 和 `list`，外人看不到别人工作区的名字。

## 内部函数

| 名称 | 什么时候调 |
|---|---|
| run | 模型调工具 `workspace`：从前台的 `row.bot`、`row.address` 算 access，调 runAction，出错收成 `{ ok: false, error }` |
| runAction | run 里照 action 分到 create、get、rename、archive、list |
| getAllowed | get、rename、archive、resolve 按 ID 取：没有报 not_found；别的机器人的、外人碰别的范围的报 forbidden |
| getDefault | resolve 没写 ID 和旧目录、或旧目录就是范围根时：本人调 ensureDefault，外人登记他的根 |
| register | ensureDefault、getDefault、resolve 的旧目录：同一个机器人、范围、目录登记过就交回那条（不改名字），没有就 insert |
| insert | create、register：写一行，发 created |
| getResolved | resolve 的每条路：挡归档的、算绝对目录、发 trace |
| emitChanged | insert、rename、archive 存库以后：发 trace 和 workspaces/changed |
| getHome | getAccess、ensureDefault：机器人的默认目录 `bots/<机器人>/workspace/` |
| getStored | 目录的存法：运行时目录里的存相对路径（`/` 隔开），外面的存绝对路径，就是运行时目录本身写 `.` |
| getWorkspace（模块函数） | 表里一行换成 Workspace |
| getName（模块函数） | create、rename：名字去掉首尾空白，空的报 workspace_invalid_name |

## 数据表 workspaces

| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PRIMARY KEY NOT NULL | 唯一 ID，`crypto.randomUUID()`；不从名字、目录、机器人名推 |
| bot | TEXT NOT NULL | 归属哪个机器人（机器人名；没有 bots 表） |
| name | TEXT NOT NULL | 名字，只用来显示，可以重复；默认工作区叫“默认工作区”，旧目录第一次登记用配置里的名字或目录最后一段；改名只改这一列 |
| directory | TEXT NOT NULL | 目录，登记以后不改：运行时目录里的存相对路径（`/` 隔开），外面的（配置登记的源码仓库）存绝对路径；用时 `path.resolve(运行时目录, directory)` |
| scope_key | TEXT NOT NULL | 范围：`private` 是本人的；外人的是 `dir:<他的根目录>`（和现在按目录隔离一样） |
| is_default | INTEGER NOT NULL，CHECK 0/1 | 1 是这个机器人、这个范围的默认；默认的不能归档 |
| status | TEXT NOT NULL，CHECK active/archived | active 能用；archived 不能新派活，已绑定的后台照样接着用 |
| created_at | INTEGER NOT NULL | 登记的时刻，毫秒（旧目录是登记那一刻） |
| updated_at | INTEGER NOT NULL | 最后改名、归档的时刻，毫秒 |

索引

- `workspaces_default (bot, scope_key) WHERE is_default = 1` 唯一，每个范围一个默认。
- `workspaces_path_scope (bot, directory, scope_key)` 唯一，同一范围的同一目录只登记一条。
- `workspaces_bot_status (bot, status, created_at, id)` 用于列清单。

## 会话上的字段

`row.workspaceId` 声明在 bots 的 `Dispatch.ts`（和 `resultQueue` 同处），保存后台绑定的工作区 ID。

1. new 时定下 ID。
2. append 和 `bots.route` 保留原 ID。
3. progress 转新会话时照抄 ID。

## 配置

没有配置。plugins 段写一行，要在 bots 前面：

```yaml
plugins:
  - name: workspaces
  - name: bots
```

不写 plugins 段时默认就挂它（`utils/Checks.ts` 的 `DEFAULT_PLUGINS`）。机器人配置里的登记目录照旧写在顶层 bots 名单里：`workspaces: { 源码: <目录> }`。

## 设计要点

- 范围键：本人是 private；外人是 dir:<他的根目录>，根目录用 Workspace.of(机器人默认目录, 回话地址) 算出，不另造身份体系，和原来的隔离一样。
- access 是 {bot, owner, scopeKey, root}，由 ctx.workspaces.getAccess(bot, address) 从回话地址算；本人能看、能用这个机器人全部范围的工作区，外人只看、只用自己范围的。
- 目录保存方式
  - 运行时目录内用相对路径，以 `/` 分隔。
  - 外部目录（例如配置登记的源码仓库）用绝对路径。
  - 使用时调用 `path.resolve(root, directory)`，不做 realpath 或 Windows 大小写归一。
- 同一机器人、同一范围、同一目录只登记一条（唯一索引 `(bot, directory, scope_key)`）。名字只在第一次登记时用，之后改名不会被配置盖回去。
  - `bots/<机器人>/workspace/` 在 Bot 构造时用 `ensureDefault` 登记。
  - 配置 `workspaces` 的目录也在构造时登记为 private。
  - 外人的根在第一次用到时登记。
- 冲突校验放在 hand_session 入口（Dispatch.hand），resolve 是内部接口，两个都给时按 ID。
- workspace 工具只给前台（sessionKinds: ['front']）：后台会话的回话地址里 workspace 已换成干活目录，从它算外人范围会算错。
- bots 硬依赖 workspaces（inject）：config.yaml 的 plugins 段没写时 bots 不会开工。
- 本人的根固定是 bots/<机器人>/workspace/（不走 of），这样本人的 '.' 和相对路径同一个根；启动登记用 allowArchived: true，免得本人归档了登记目录以后机器人起不来。
