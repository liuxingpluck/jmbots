# voice v0.6.2

0.6.2 旧路回话经 `channel/reply` 进来，`VoiceReplies.onReply` 里 `adopt` 补来源快照后走标准回复；`ctx.bots.channel('voice')` 只登记名字。

聊天输入区上方的语音条用于

- 开麦，查看实时和最终字幕，收听机器人回复。
- 查看转写、合成、任务理解和断句实际用过的线路。
- 在字幕下查看已认领的任务。

默认双工。

1. 网页播放时继续上传经浏览器回声消除和降噪处理的麦克风音频。
2. 识别出与当前播报不同的插话后，立即停播并清空排队音频。
3. 插话的最终字幕沿用语音任务流程。

## 依赖

- `resources` 读取顶层 `voice`。
- `sessions` 提供已获认领的语音后台会话。
- `http` 提供 Fastify 与统一鉴权。WebSocket 使用 `@fastify/websocket`。依赖未安装时语音状态可查，其他 HTTP 路由照常运行。
- `programs` 回执放行本地模型。没有回执时本地线路不启用，按配置尝试备用线路。
- 网页复用现有令牌，浏览器麦克风需要本机安全上下文或 HTTPS。

## 接口

| 入口 | 参数 | 返回与作用 |
|---|---|---|
| GET /api/voice/status | 无 | 返回 `enabled`、`available`、`wsPath` 以及不可用原因。 |
| WS /api/voice/ws | 可配置路径，首帧为 `start`，含可选 `bot`、`lang` 和 `device` | 回 `ready` 与状态，`ready.bargeIn` 指示是否双工。语音为 16 kHz、16 位有符号小端单声道 PCM，浏览器以 100 ms 帧发送。 |

- 连接控制
  - 首帧不是合法 start 时返回 error 并以 4400 关闭。
  - 新连接以 4001 取代旧连接。
  - 客户端 stop 后停止收音并发送最后的 final。已进入判断的语音收尾后才回 idle。
  - ping 回 pong。
- 字幕帧为 `{type,seq,text}`，partial 与 final 共用句号。
- 浏览器在本地保存 UUID，通过 `start.device` 交给服务端当聊天号。旧客户端使用本机聊天。
- 网页「语音」与「全部」都从服务器读取已保存的来回，语音子菜单按聊天号区分浏览器。

每条机器人最终回复只发给原语音连接，按顺序发送

1. `reply` 文字帧。
2. `audio-start`（`utterId`、`format: pcm_s16le`、`sampleRate`）。
3. 单声道二进制 PCM。
4. `audio-end`。

播放过程的其他消息

- 小米流中断并退回本地时，用 `stop-audio` 清掉上一段未播完的音频。
- 音频不可用时发 `audio-error`，字幕连接继续接听。
- 浏览器播完第一块 PCM 后回 `audio-played`，带同一个 `utterId`。网页记录据此标记「已播报」，无确认时显示「未播报」。

1. `audio-end` 后浏览器继续播完已排队的声音。服务端按已发 PCM 的时长估计播放窗口，再加 150 ms 回声尾音。
2. 窗口内识别到的文字与播报文本比较。窗口内收到有声帧时，也为迟到的转写保留参考。相似字幕不显示、不派发。
3. 插话确认后复用 `stop-audio`。识别流继续接同一句音频，最终字幕通过回声判断后才送给任务处理。

线路切换原因随 `voice-route` 帧发出，并写入 `Voice.route` trace。

- `stage` 取 `asr`、`tts`、`judge` 或 `turn`。
- `place` 取 `local` 或 `cloud`，线路用尽时省略。

## 事件

| 事件 | 输入或发送内容 | 用途 |
|---|---|---|
| voice/request | `{action:'status'}` | 查询转写是否可用、连接数和是否在听。 |
| voice/request | `{action:'speak',text,group?,interrupt?}` 或 `{action:'stop',group?}` | 向当前连接排队或取消播报。指定组时只处理匹配的讲解，省略组时操作全部。 |
| voice/result | `{requestId,ok,error?,listening,clients,speaking?}` | 状态或操作回执。speak 成功表示音频已排队。 |
| voice/transcript | `{seq,text,final,at}` | 发布当前连接产生的临时字幕。 |
| voice/state | `{state,reason?}` | 通知 listening、idle 或 error。 |
| programs/resource-request、programs/resource-result | `{action:'can-start',who:'voice',heavy,requestId}` 和准入回执 | 本地模型加载前检查资源。内置断句模型标记为轻量 CPU 判断。 |
| trace | 阶段、线路、固定原因 | 记录切换和失败，供应商响应、字幕和密钥均不进入该条记录。 |
| decision/judge | `kind: voice / voice-final`、候选文字、之前任务及阈值 | 同一轮同时只等一份回执。无决策服务时，已收尾且够字数的句子交给机器人。 |
| voice/dispatch | 标准语音消息形状与认领控制 | 让 bots 按半句提前开始。消息号沿用到该句最终档案。 |
| voice/record | 最终语音消息与可选会话号 | 让 web-api 保存最终原话，之后才交给标准渠道。 |
| channel/message | 最终 voice 消息与认领控制 | 通知记忆索引。提前开工的消息带 `routing.recordOnly` 和 `routing.taskId`，仅入档且绑定原会话。 |
| channel/reply | 标准文字回复（模型 `channel_reply`、零次兜底，以及旧路回话） | `VoiceReplies.onReply` 接 `channel` 为 `voice` 的请求，沿用原消息号播报；提前完成时等最终字幕入档。旧路回话（后台会话一轮结束、前台送后台结果）由 `Bots.send` 经 `channel/reply` 来，没有来源快照，`target.address` 是会话记的语音地址，带 `sessionId`；`adopt` 补快照后和标准回复同一条路。 |
| channel/replied | 标准回复回执，含 `spoken` | 网页用 `replyRequestKey` 去重并保存文字与播放结果。 |
| bot/settled、session/change | 来源消息或会话结束 | 关闭旧任务的合并窗口。前者用于标准渠道收尾，后者用于已有后台投递路径。 |
| voice/task 和 WS task | `{taskId,text,bot,merged,sessionId}` | 只在收到机器人认领后发出，网页显示最近五条。 |

## 函数与数据

- `apply(ctx)` 校验配置，在现有 HTTP 上挂路由和事件；卸载时释放本插件连接。
- `ctx.bots.channel('voice')` 只登记渠道名（网页的渠道清单用），发话不靠它。
- `VoiceReplies.onReply(request)` 听 `channel/reply`：只接 `voice` 渠道的请求，同一 `replyRequestKey` 重放回执，不重复播报；没有来源快照的先交 `adopt`，补不上就回 rejected。
- `VoiceReplies.adopt(request)`（旧路回话，没有来源快照）：
  1. 从 `target.address` 取 `voiceMessageId` 当 `messageId`，`chatId` 默认 `local`，`customer` 默认 `voice:本机`；`origin.address` 加 `voiceSessionId`。
  2. 补一份来源快照，去掉 `target`，轮键 `getReplyRoundKey(messageId, bot, sessionId)`。
  3. 会话做完是 `final`、请求键固定 `voice-final`（多次转发合并成一条、不重复播报）；还在转是 `progress`、新 UUID。
  4. 补快照前先等这句最终字幕入档（`unfinished` 门），听写取消就拒收。
- `Voice.playReply(text, request)` 读 `request.sourceSnapshot?.messageId` 找原消息，把文字和音频送给原连接。
- `Voice.attach(socket)` 接入已鉴权的连接，关闭被取代的连接。 `Voice.dispose()` 关闭并释放当前会话。
- `Asr.accept(pcm)` 输入一帧 PCM，以 `onPartial`、`onFinal` 和 `onSpeechStart` 通知结果。`close()` 终止流。模拟实现按静音和时长切句，输出固定测试字幕。
- `loadSherpa(options)` 从数据目录下 `program/sherpa-onnx/` 和 `program/voice-models/` 加载共享的在线识别器，每条连接独立管理解码流和 Silero VAD。
- `RoutedAsr` 在转写启动或运行失败时切换到配置的备选。连接内滚动保留未获最终字幕的 PCM，换线时从未确认处重放。上一线路的迟到回执会丢弃。
- `createSpeaker(lines)` 按主备次序调用小米 SSE 或 Worker MeloTTS。中途换线会清掉队列中的旧音频并重合成当前句，已经播出的开头可能再听到一次。
- `Turn` 在短停顿后让模型判断当前字幕，只有当字幕和开口状态未变化且明确判完，才让支持提前收尾的 ASR 确认句尾。判断拒绝、超时或信心不足时仍等原端点。
- `VoiceTasks.push(event)` 更新当前句和待判断文本。满足字数、时间间隔或句尾条件就请求决策。超过常规限额时仍判断句尾；迟到或已撤销的回执会被忽略。
- 音频只在客户端和当前服务端转写路径使用，不写文件。
- 临时字幕放在内存。
- 最终字幕、回复文字和播放结果进入网页时间线。记忆工具可按语音聊天号查询已索引的文字。

## 配置

`config.example.yaml` 有默认关闭的挂载与启用示例。

- 路径默认为 `/api/voice/ws`，采样率固定 16000。
- `asr.provider` 默认 `sherpa`，显式选 `fake` 时只产生模拟字幕。
- `turn.silence_ms` 默认 1200，`turn.max_utterance_ms` 默认 60000。
- 机器人按 `start.bot`、`voice.bot`、配置中的第一个机器人取值。
- 默认 6 个字才判断，再多 12 字或间隔 1 秒时可提前判。常规每分钟 30 次，句尾判断保留。

具体键值见配置模板。

| `voice` 配置 | 默认值 | 作用 |
|---|---|---|
| `barge_in` | `true` | 播放时继续送音并允许插话。设为 `false` 时暂停麦克风上传，等音频播完和 150 ms 尾音结束后恢复。 |
| `barge_in_min_chars` | `3` | 实时字幕至少包含这么多个有效字符才用来触发停播。最终字幕也检查回声，并可确认短插话。 |
| `barge_in_echo_similarity` | `0.75` | 忽略大小写、全半角差异、标点和空白后，用 `1 - 编辑距离 / 字幕字符数` 比较字幕与播报中的最佳连续片段。达到阈值视为回声。有效范围为大于 0 且不大于 1。 |

`asr.provider` 可选 `sherpa`、`bailian` 或 `xiaomi`。用 `asr.fallback` 显式启用另一端，主备要分别位于本地和云端。

- 百炼实时转写用 `providers.bailian` 的地址和密钥。根地址会转到 `/api-ws/v1/inference`，也可填完整的 WebSocket 地址。
- 小米整句转写用 `providers.xiaomi` 的 Chat Completions 端点。

Sherpa 和百炼在实时字幕达到条件时就能停播。小米整句转写要等句尾回执才能判断插话，延迟随断句和网络变化。

- `tts.provider` 默认 `xiaomi`，失败时默认退到 `local`。
- 本地用 MeloTTS，`Download.mjs --tts` 安装本地模型。
- `tts.fallback: xiaomi` 启用反向退路，`none` 关闭。
- 小米应用后端凭据从 `providers.xiaomi` 读取，音色默认 `mimo_default`。

`turn.detector` 默认用 `builtin:zh-tail-v1`，可设为 `false` 关闭。

- 模型由中文句尾和截断句的字符频数训练，在本机推理。
- 较长的词尾匹配权重更高。单字和常见名词尾部的证据不足时继续等静音。
- Sherpa 支持用断句结果提前收尾。百炼和小米沿用各供应商的端点规则。

两项设置可以分别配置

- `turn.detector` 控制断句。
- `judge.models` 控制任务理解，字段有 `local_model`、`cloud_model`、`prefer` 和单线路 `timeout_ms`。

外部模型使用 `供应商名/模型ID`，适合稳定输出 YES 或 NO 的短回复模型。省略 `judge.models` 时沿用 `decision/judge` 和原有的提前开任务规则。
