# knowledge v1.2.0

管理积木知识库的目录、文档、标签、别名、[[双链]]、磁盘镜像、本地目录只读同步与检索工具。

1.2.0 加两件事：实体别名 `aliases`（参与搜索、`[[双链]]` 唯一别名命中、同名消歧接口 `GET /api/knowledge/disambiguate` 与工具 `kb_disambiguate`）；本地文件夹只读同步（`FolderSync.ts`，配置 `localWatchDirs`，`POST /api/knowledge/sync-folders`、`GET /api/knowledge/sync-status`）。

1.1.0 加三件事：Obsidian 式 `[[双链]]`（关系表 `kb_links`，引出、反向链接与图谱接口）；多标签 `tagMode=all|any` 组合筛选；「硬性系统规则」`isSystemRule`（只有本人在网页上能改，`kb_save` 不能建、不能改）。

1.0.3 记忆桥接（`memory/request` 的 search）的 4 秒时限改成 `AbortSignal.timeout` 中止信号，不再用 `requestEvent` 已删的 `timeoutMs`；到点按“记忆桥接未完成”退回只查本地（云端 31 第 2 条）。

积木知识库（knowledge）后端插件：围绕「文档、多对多标签、虚拟目录树」构建 SQLite 存储，支持与工作决策台（`/work-decision/`）专题节点 `topicId` 挂载关联，自动导出磁盘文件镜像，并通过 `requestEvent` 按需附查 `memory` 混合检索。

## 依赖

- inject `resources`：共用应用主 SQLite 连接 `ctx.resources.db` 与运行时目录 `ctx.resources.root`。
- inject `http`：在 `ctx.http.app` 登记 `/api/knowledge/*` REST 接口，并用 `ctx.http.requireVerified(request, ...)` 拦截未核验写请求。
- inject `tools`：向 `front`（前台对话）与 `work`（后台干活）会话登记只读工具 `kb_search`、`kb_disambiguate` 和写工具 `kb_save`。
- inject `db`：建表只走 `ctx.db.migrate` 的迁移账本（1.0.4 起必需，`KnowledgeStore` 不再自己建表），共 5 版。
  - 第 1 版是原来的整串建表语句 `SCHEMA_SQL`，原样保留：0.7.90 起有 db 的库已按它记过账，改了哈希就对不上。
  - 它交给 `db.migrate` 时只执行了第一句（只建出 `kb_dirs`），所以有第 2 版 `SCHEMA_SPLIT_SQL`：同一串语句按 `--> statement-breakpoint` 拆开逐句执行。都是 `IF NOT EXISTS`，旧库什么都不改，新库补齐四张表和索引。
  - 第 3 版 `SYSTEM_RULE_SQL`（1.1.0）：`kb_docs` 加 `is_system_rule INTEGER NOT NULL DEFAULT 0`，带 `adoptColumn`，列已在的库只登记。加列单独一版，因为 `adoptColumn` 要求这一版只有加列这一句。
  - 第 4 版 `LINKS_SQL`（1.1.0，`Links.ts`）：建 `kb_links` 和两个索引，分段写法逐句执行。
  - 老库刚升到第 4 版时 `kb_links` 是空的，`apply` 里按已有正文回填一次（`KnowledgeLinks.rebuildAll`，标了 `//退场：`）。
  - 第 5 版 `ALIAS_HASH_SQL`（1.2.0，`Store.ts`）：`kb_docs` 加 `aliases TEXT NOT NULL DEFAULT '[]'` 和 `content_hash TEXT NOT NULL DEFAULT ''`，分段写法逐句执行。只加带默认值的列，已有文档一行不动；`source_path` 第 1 版就有，不再加。
- 依赖 `channels` 的 `isOwnerTurn`：`kb_save` 执行时再核一次是不是本人。

## 对外函数

### HTTP 接口（写接口均需 `isVerified`，未核验回 `403`）

- `GET /api/knowledge/tree` → `{ ok: true, dirs, flatDirs, tags, topics, totalDocs, unassignedDocs }`
- `GET /api/knowledge/tree` 的回包 1.1.0 起多一项 `systemRuleDocs`（硬性系统规则篇数）。
- `GET /api/knowledge/docs`（支持 `dirId`、`topicId`、`tag`、`tags`、`tagMode`、`systemRule`、`q`、`limit`、`offset`、`includeContent`）→ `{ ok: true, items, total, limit, offset }`；每项多一个 `isSystemRule`。
  - 多标签组合（1.1.0）：`tagMode=all`（默认，交集，和 1.0.1 起的老行为一样，老前端发多个标签时照旧取交集）或 `tagMode=any`（并集，带上任一个就算）；写了别的回 400。实现是同一个子查询，`HAVING COUNT(DISTINCT t.id) >= ?`，all 时是标签数，any 时是 1。
  - `systemRule=1`（或 `true`）：只看硬性系统规则。
  - 多标签交集（v1.0.1）：`?tag=a&tag=b` 重复参数或 `?tags=a,b` 逗号分隔（中文逗号也认），和单个 `tag` 合并；去掉前导 `#`、空项，大小写不敏感去重（`Store.ts` 的 `getFilterTags`）；最多 `MAX_FILTER_TAGS` = 20 个，超过回 400「筛选标签最多 20 个」，免得极端长的网址撞上 SQLite 参数上限。文档要把这些标签全带上才算：`kb_doc_tags` 子查询 `GROUP BY doc_id HAVING COUNT(DISTINCT tag_id) = 标签数`。
- `GET /api/knowledge/docs/:id` → `{ ok: true, doc }`
- `POST /api/knowledge/docs` / `PUT /api/knowledge/docs/:id`（支持可选 `baseUpdatedAt` 乐观锁，与当前 `updated_at` 不一致时返回 `409` 并带回最新 `doc`） / `DELETE /api/knowledge/docs/:id`
  - 请求体可带 `isSystemRule`（布尔，写错类型 400），设上或取消硬性系统规则。能走到这里的都过了 `requireVerified`（本机或带令牌的本人）。
  - 请求体可带 `aliases`（1.2.0，字符串数组，不是数组 400）：`Store.ts` 的 `normalizeAliases` 去两头空白、去空、大小写不敏感去重；最多 20 个、每个最多 60 字，超了 400。PUT 带了是全量替换，不带不动。文档每项都多一个 `aliases`。
  - 新建、修改、删除动到硬性系统规则时，`Routes.ts` 的 `logSystemRuleWrite` 记一行日志：`knowledge：硬性系统规则<新建|修改|删除>，操作者=<本机|远程已核验>，docId=…，标题=…`。
- `GET /api/knowledge/docs/:id/links`（1.1.0）→ `{ ok: true, outgoing: [{ targetTitle, targetId, exists, ambiguous }], backlinks: [{ id, title, summary, updatedAt }] }`。引出链接按正文里出现的先后，悬空的 `targetId: null, exists: false`；反向链接不含自己，新的在前；文档不存在 404。
  - 1.2.0：没有这个标题时按别名找，恰好一篇用了这个别名才连上；两篇以上用了同一个别名不连，`ambiguous: true`，免得串链。标题对上的永远优先于别名。
- `GET /api/knowledge/graph`（1.1.0，可选 `centerId`）→ `{ ok: true, nodes: [{ id, title, tags, isSystemRule, degree }], edges: [{ source, target, targetTitle }] }`。
  - 不带 `centerId`：全部文档都是节点（网页拿它当标题索引），边是全部连上的链接。
  - 带 `centerId`：这篇和它的一跳邻居，边只要一头是它的；不存在 404。
  - 指向自己、悬空的链接不算边；`degree` 是这张图里连着它的边数。
- `POST /api/knowledge/dirs` / `PUT /api/knowledge/dirs/:id` / `DELETE /api/knowledge/dirs/:id`
- `PUT /api/knowledge/tags/:name`（v1.0.2，写）：请求体 `{ newName }`，照 `normalizeTags` 查（不能空、不能带逗号、最多 64 字）。新名字还没有：原地改名；已有另一个同名标签：把原标签的文档挂过去（`INSERT OR IGNORE`，两个都挂着的不重复），再删原标签。受影响的文档 `updated_at` 记成现在（编辑框里的旧稿再存会拿到 409 去刷新），刷新磁盘镜像。→ `{ ok: true, oldName, newName, merged, affectedDocs }`；原标签不存在 404。
- `DELETE /api/knowledge/tags/:name`（v1.0.2，写）：解除这个标签和所有文档的关联再删掉，文档本身不动；同样刷新 `updated_at` 和镜像。→ `{ ok: true, name, affectedDocs }`；不存在 404。
- `GET /api/knowledge/docs/:id/related?limit=6`（v1.0.2）：相关文档，同专题 +3、每个共同标签 +2、同目录 +1，只要分大于 0 的、排除自己；分高的在前，同分新的在前；`limit` 默认 6，限在 1～20。→ `{ ok: true, docId, items: [{ id, title, summary, dirId, topicId, tags, score, reasons, updatedAt }] }`，`reasons` 如 `['同专题', '共同标签: AOBB']`；文档不存在 404。
- `GET /api/knowledge/search?q=...`（`dirId`、`topicId`、`tag`/`tags`、`tagMode`、`systemRule` 同上；`includeMemory=0` 不查记忆）：本地标题/别名/标签/摘要/正文多字段加权检索 + 通过 `memory/request`（`action: 'search'`）附带查询记忆片段；未挂载 `memory` 或远端离线时退回只查本地（`memoryAvailable: false, memoryHits: []`），不报错。
  - 排序（1.2.0）：整个搜索词和标题一样 +1000，和某个别名一样 +500，再加按词包含的分（标题 50、别名 40、标签 35、摘要 20、正文 10），所以是精确标题 > 精确别名 > 包含。`matchedIn` 多一种 `alias`。
- `GET /api/knowledge/disambiguate?q=<词>`（1.2.0，只读）→ `{ ok: true, query, exact, aliasMatches, candidates, ambiguous }`。
  - `exact`：标题和这个词一样（大小写不敏感）的文档；`aliasMatches`：别名里有它、标题不是它的；`candidates` 是两者合起来，标题对上的在前，都按建的先后。
  - 每篇候选 `{ id, title, category, aliases, summary, matchedBy }`，`category` 是所在虚拟目录的名字（未归目录是空串），`matchedBy` 是 `title` 或 `alias`。
  - 候选两篇以上 `ambiguous: true`。`q` 去空白后是空的 400。
- `POST /api/knowledge/sync-folders`（1.2.0，写）：请求体可选 `{ dirs?: string[], category?: string }`，同步一次本地目录 → `{ ok: true, scanned, created, updated, skipped, errors: [{ path, reason }], lastSyncedAt }`。
  - `dirs` 给了用它（每项要是绝对路径，`Checks.ts` 的 `checkDirs` 查，不对 400），不给用配置的 `localWatchDirs`；两者都没有 400。
  - 系统根目录（`/`、盘符根）和根下的系统目录（Windows、Program Files、ProgramData、/etc、/usr 等）400。
  - `category` 是放新文档的虚拟目录名，不给是「外部学习」；第一次真有新文件时才找或建这个目录。
  - 规则见下面 `FolderSync.ts`。
- `GET /api/knowledge/sync-status`（1.2.0，只读）→ `{ ok: true, localWatchDirs, lastSync }`：配置的目录（规范化后的绝对路径）和这次启动以来最近一次同步的结果，还没同步过 `lastSync: null`。

### 模型工具

- `kb_search`（只读，`sessionKinds: ['front', 'work']`）：不传筛选词时返回目录/标签/专题总览；传 `query`、`topicId`、`tag` 或 `dirId` 返回精简摘要索引；传 `docId` 按需读取单篇完整正文。硬性系统规则照常读，命中项标 `[硬性系统规则·只读]`，正文头写明“必须遵守，不能用 kb_save 修改”。
- `kb_disambiguate`（只读，1.2.0，`sessionKinds: ['front', 'work']`）：参数 `query`（必填）。按标题和别名精确比（大小写不敏感），每篇候选一行：`docId`、是标题还是别名对上的、标题、`[分类:…]`、`[别名:…]`、摘要。两篇以上时开头写明「有歧义」，提醒写 `[[引用]]` 或查资料前先用 `docId` 选定、必要时问用户；一篇也没有时提示改用 `kb_search`。和 `kb_search` 一样不在 approval 的只读白名单里，外人那一轮拿不到。
- `kb_search` 1.2.0 起也按别名找；读单篇时多一行「别名」，命中项带 `[别名:…]`。
- `kb_save`（写，v1.0.2，`sessionKinds: ['front', 'work']`）：
  - 不传 `docId`：新建，`title`、`content` 必填；可带 `summary`、`tags`（最多 20 个）、`dirId`、`topicId`、`sourceType`（默认 `note`）。
  - 可带 `aliases`（1.2.0，全量替换，规矩同 HTTP）。
  - 传 `docId`：`mode` 默认 `append`，新内容空一行接在原正文后面，原文不动（内部用读到的 `updatedAt` 防和别处同时写）；`mode: 'replace'` 整篇替换，必须带 `baseUpdatedAt`，不带或过期都不覆盖，报错里写明最新 `updatedAt`。两种模式都可顺带改 `title`、`summary`、`tags`、`dirId`、`topicId`、`sourceType`。
  - 写后走 `Store` 的事务和磁盘镜像；返回 docId、标题、摘要、`updatedAt` 等。
  - 外人那一轮：approval 的只读白名单 `READ_ONLY_TOOLS` 里没有它，拿不到；没挂 approval 时，执行时 `isOwnerTurn` 再核一次，不是本人报「只有本人能写知识库」。
  - 硬性系统规则（1.1.0）：参数里塞了 `isSystemRule: true`，或 `docId` 指向的文档已标记，追加、替换、只改标题标签都拒，报 `SYSTEM_RULE_DENIED`：「该文档为硬性系统规则，AI 仅可读不可修改，请由用户本人在知识库网页操作」。参数定义里本来就没有 `isSystemRule`，新建的文档一律不是规则。

## 内部函数

- `Store.ts`：迁移用的 `SCHEMA_SQL`、`SCHEMA_SPLIT_SQL`、`SYSTEM_RULE_SQL`、`ALIAS_HASH_SQL`；`KnowledgeStore` 目录/文档/标签增删改查、乐观锁、相关文档打分、`deriveAutoSummary`、`normalizeTags`、`normalizeAliases`。建文档、改正文、改标题、改别名、删文档时，在同一事务里调 `links` 刷新双链（别名变了把新旧别名都交给 `relinkTitles`）。1.2.0 加的：
  - `disambiguate(query)`：消歧接口和 `kb_disambiguate` 共用；
  - `listImported()`：`content_hash` 不空的文档（同步导入过的），`FolderSync` 按它认文档；
  - `getOrCreateDirByName(name)`：按名字找虚拟目录，没有就在顶层建，同步放分类时用。
  - `createDoc`、`updateDoc` 的入参多 `contentHash`，只有 `FolderSync` 带；`updateDoc` 不带时留着库里原来的。
- `Links.ts`（1.1.0）：迁移第 4 版 `LINKS_SQL`；`parseWikiLinks` 从正文解析 `[[标题]]`、`[[标题|别名]]`（跳过围栏代码块和行内代码，标题大小写不敏感去重）；`KnowledgeLinks` 类：
  - `refreshDoc`：建文档、改了正文时，重写这篇的引出链接并按标题连上；
  - `relinkTitles`：新建、改名（新旧两个标题）、删除后，指向这些标题的链接重新按标题找文档。悬空的连上，删掉的置空，有同名的换成最早建的那篇；
  - `removeSource`：删文档时删掉它写出去的；
  - `getLinks`、`getGraph`：给两个只读接口；
  - `isEmpty`、`rebuildAll`：老库升级后回填一次。
- `DiskMirror.ts`：`DiskMirror` 维护文档磁盘镜像目录与 `content.md`/`meta.json` 导出清理，`generateAtomId`、`formatDateFolder`、`sanitizeTitleSlug`。
- `FolderSync.ts`（1.2.0）：`FolderSync` 类，`index.ts` 用配置的 `localWatchDirs` 和镜像目录建好交给路由。
  - `sync(dirs, category)`：`POST /api/knowledge/sync-folders` 调。只读源目录，只用 `readdir`、`stat`、`readFile`，不改、不删、不挪用户的文件。
    - 收文件：每个目录广度优先，跳过以 `.` 开头的（`.git` 等）、`node_modules`、`dist`、知识库自己的镜像目录，不跟链接；只收 `.md`、`.txt`；每个目录最多 200 个，多的不扫并记一条问题。
    - 单个文件超过 256 KB 不读，记一条问题；正文去掉 UTF-8 BOM 后算 `sha256` 当 `content_hash`。
    - 按 `getPathKey` 规范化的 `source_path` 认出导过的那篇：哈希一样算 `skipped`；那篇已标硬性系统规则的不覆盖、记一条问题；哈希变了 `updateDoc` 原位更新正文和哈希（标题、标签、目录本人可能改过，不动）。
    - 新文件 `createDoc`：标题取第一行 `# 标题`，没有用文件名去扩展名；`sourceType: 'file'`、`sourcePath` 是文件路径、标签 `#本地导入`、放进 `category` 目录。
  - `getStatus()`：`GET /api/knowledge/sync-status` 调。
- `Routes.ts`：挂 `/api/knowledge/*` 路由，参数校验与 `memory/request` 附查。
- `Tools.ts`：登记 `kb_search`、`kb_disambiguate`、`kb_save` 三个模型工具。

## 数据

1. `kb_dirs`：虚拟目录树（`id`, `parent_id`, `name`, `sort_order`, `created_at`, `updated_at`）。支持层级移动环路拦截；删除目录时子目录自动上提至原父级、原目录内文档解绑为未归类（`dir_id = NULL`），不删原文档。
2. `kb_docs`：知识文档（`id`, `dir_id`, `topic_id`, `title`, `summary`, `content`, `source_path`, `source_type` [`note`/`file`/`url`/`transcript`], `is_system_rule` [0/1，1.1.0], `aliases` [JSON 字符串数组，1.2.0], `content_hash` [同步导入时源文件的 sha256，别的文档是空串，1.2.0], `created_at`, `updated_at`）。未显式填写 `summary` 时自动从 Markdown 正文提取导读摘要。
3. `kb_links`（1.1.0）：`[[双链]]` 关系。
   - `source_id`：写链接的文档；
   - `target_title`：`[[ ]]` 里的标题（不含别名）；
   - `target_id`：按标题（大小写不敏感，同名取最早建的）找到的文档，没有是 NULL；
   - 主键（`source_id`, `target_title`），索引 `target_id`、`target_title COLLATE NOCASE`。
4. `kb_tags` + `kb_doc_tags`：大小写不敏感标签表与多对多映射，文档更新或删除时自动清理无引用孤立标签。标签名不能含英文或中文逗号（逗号是筛选参数的分隔符），写入时 `Store.ts` 的 `normalizeTags` 回 400「标签名不能包含逗号」。
5. 磁盘镜像：每次文档变更同步原子导出至 `<runtimeRoot>/knowledge/YYYYMMDD/<id>_<标题>/{content.md, meta.json}`；1.1.0 起 `meta.json` 多一项 `isSystemRule`，1.2.0 起多一项 `aliases`。
6. 最近一次同步的结果只放在 `FolderSync` 的内存里，重启就没了，不进库。

## 配置

- `mirror_dir`（可选字符串）：自定义磁盘镜像根目录；缺省写入 `<runtimeRoot>/knowledge`。
- `localWatchDirs`（可选，1.2.0）：本地文件夹只读同步的目录，绝对路径的数组；缺省是空数组。启动时用 `checkDirs` 查一次（不是数组、不是绝对路径插件挂不上），规范化后交给 `FolderSync`。只在调 `POST /api/knowledge/sync-folders` 时同步，不自动扫。
