# base-bridge v1.2.1

提供 `ctx.base` 请求服务、请求事件 `base/request`（契约 3.2 第 10 条，别的插件不拿 `ctx.base`，发它请基地办事）、4 条更新和自启动网页接口，以及可选的基地通知（`Notify.ts`，原 `notify`）与更新监听（`UpdateWatch.ts`，原 `update-watch`）。

更新监听和 approval、bots 说话都走事件（契约第五节第一份 #10–#12、#27）：`approval/request`（list 3 秒、ask 5 秒、过时项 decide 不等回执），`bot/say` 通知；不再 inject approval，没挂 approval 时当没有在等的、新版本登记不上就打一行 `console.error` 下一轮再试。

## 听的事件

| 事件 | 位置 | 收到后做什么 |
|---|---|---|
| `base/request`（请求，serial） | `src7/plugins/base-bridge/index.ts` 的 `Base` 构造函数、`Base.onRequest` | 载荷 `{ method:'GET'\|'POST', route, timeoutMs, body? }`：GET 调 `getJson`、POST 调 `postJson`，带 `requestId` 时回 `base/result` `{ ok:true, status, body }`；没配地址、连不上、超时回 `{ ok:false, error }`。发的一方的等待取 `timeoutMs + 1000`。 |
| `approval/asked` | `src7/plugins/base-bridge/Notify.ts` | 仅开启 `config.notify` 时监听：发出标题“有待确认”的通知。 |
| `progress/update` | `src7/plugins/base-bridge/Notify.ts` | 仅开启 `config.notify` 时监听：任务进入终态（`done`/`error`/`stopped`/`timeout`/`flagged`/`handed`）时按 `sessionId:id:stage` 去重发一次通知。 |
| `ready` | `src7/plugins/base-bridge/UpdateWatch.ts` | 仅开启 `config.update_watch` 时监听：在 `first_ms` 后调度第一次版本检查。 |
| `approval/decided` | `src7/plugins/base-bridge/UpdateWatch.ts` | 仅开启 `config.update_watch` 时监听：处理 `kind==='update'` 决议（拒绝则记入 `declined`，同意则调 `/update/apply` 并将状态写入 `swapping`）。 |

## 发的事件

| 事件 | 位置 | 触发时机 | 携带内容 |
|---|---|---|---|
| `trace` | `src7/plugins/base-bridge/Notify.ts` | 开启 `config.notify` 挂载完成时触发一次。 | `notify.apply`：`{ 地址, 开着 }` |
| `trace` | `src7/plugins/base-bridge/UpdateWatch.ts` | 报告更新结果、登记新版本待确认、批准换版、找不到前台会话时。 | `UpdateWatch.check`（报更新结果/登记新版本）、`UpdateWatch.onDecided`、`UpdateWatch.tell` |
| `trace` | `src7/plugins/base-bridge/index.ts` 的 `Base.onRequest` | 每接一次 `base/request`。 | `Base.onRequest`：`{ 方法, 路径, 请求号 }` |
| `base/result`（回执，emit） | `onRequestEvent` 代发 | `base/request` 带 `requestId` 时办完。 | `BaseResult`：requestId、ok、status?、body?、error? |
| `approval/request`（请求，serial） | `src7/plugins/base-bridge/UpdateWatch.ts` 的 `check` | 每轮：`list`（kind: update，等 3 秒，退回空清单）；过时的 `decide`（拒绝，不带 requestId）；新版本 `ask`（等 5 秒，没登记上记一行）。 | 见 approval 说明 |
| `bot/say`（通知） | `src7/plugins/base-bridge/UpdateWatch.ts` 的 `tell` | 报换版结果、换版没开始。 | (前台会话, 话) |

## 数据

### 数据库

- 无

### 文件（仅开启 `config.update_watch` 时读写）

- 路径：`<runtime>/data/update_watch.json`
- 字段：
  - `declined?: string`：用户明确拒绝的版本，不再重复登记；
  - `swapping?: { version: string; bot?: string }`：用户同意并成功触发 `/update/apply` 后暂存，下次检测到非 `applying` 时向前台汇报结果并移除。

## 配置

启动时兼容旧 `engine.index_url` 并提示迁移一次；新旧同时填写时使用插件配置。通知使用相对地址时与更新监听共用这个基地地址，显式通知 URL 可单独使用。

| 配置键 | 默认 | 用途 | 位置 |
|---|---|---|---|
| `plugins[base-bridge].config.index_url` | `''`（允许不配独立运行） | 须为 `string`，去掉空白和末尾 `/` 后须是无 query/hash 的 `http://` 或 `https://` 地址 | `src7/plugins/base-bridge/index.ts` |
| `plugins[base-bridge].config.notify` | **`false`（默认关闭）** | 不写或 `false` 不注册 `notify_user` 与通知监听；写 `true` 或 `{ url?, enabled? }` 开启（`url` 覆盖 `/notify` 完整地址） | `src7/plugins/base-bridge/Notify.ts` |
| `plugins[base-bridge].config.update_watch` | **`false`（默认关闭）** | 不写或 `false` 不启动版本检查定时器；写 `true` 或 `{ first_ms?, every_ms?, enabled? }` 开启（默认 `first_ms=10000`、`every_ms=60000`） | `src7/plugins/base-bridge/UpdateWatch.ts` |
| `server.port` | 未单列 | 为 `number` 时用于拼接通知携带的可点击本地网页 URL `http://127.0.0.1:<port>/` | `src7/plugins/base-bridge/Notify.ts` |

### 怎么打开通知和更新监听（默认均关闭）

在 `config.yaml` 的 `plugins:` 下给 `base-bridge` 加上需要的子键即可：

```yaml
- name: base-bridge
  config:
    notify: true          # 或 { url: 'http://127.0.0.1:15762/notify' }
    update_watch: true    # 或 { first_ms: 10000, every_ms: 60000 }
```

## 设计要点

- 统一可选的基地客户端和网页转发，各业务插件不必重复拼地址、超时、JSON 请求。
- 本地能力不因基地缺失而停工；后台轮询静默跳过，和用户已确认的操作失败要说明原因，这两种分开。
- 上游业务状态和正文要保留；缺配置或网络无响应由转发边界回 503，不把业务 4xx 当断线。
- update-watch：发现更新和执行换版分开，本插件做定期发现和去重审批，基地负责真实替换和守护；用户同意后的动作失败必须说明，不能把“已请求”当换版成功。
- update-watch 拒过的版本和正在换的状态持久保存；旧的待确认在新版本出现或消失时收束，免得多张卡反复问；结果说给所选 bot 现有的前台。
