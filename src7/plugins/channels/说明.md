# channels v1.3.0

渠道协议：渠道和机器人之间共用的事件、标准数据结构和无状态小函数（接口 A）。协议插件，不挂服务：不进 `plugins/Index.ts` 的自带名单，`config.yaml` 的 `plugins` 段也不写它；用到的插件直接 `import * as xxx from '../channels/index.ts'`，导出的名字全在 `index.ts` 汇总。

## 依赖与配置

- 不依赖服务；没有配置、数据表、HTTP 接口和工具。
- 只用骨架的通用工具：`utils/index.ts`（`getField`、`getStringField`）、`utils/Workspace.ts`（`isOwnerTurn`）、`utils/RequestEvent.ts`（`requestEvent`）、`utils/Text.ts`（`getErrorMessage`）。
- 谁在用：approval、assist、bots、cli、feishu、memory、programs、progress、voice、web-api、wechat（journal 只在测试里用类型）。

## 文件

| 文件 | 管什么 |
| --- | --- |
| `index.ts` | `version`、`declare module 'cordis'` 里六个事件的声明，把下面四个文件 `export *` 汇总 |
| `Archive.ts` | 聊天 Markdown 归档 `ChatArchive`：每个聊天一个“名字_ID”文件夹（渠道/私聊或群聊下），按 UTC 日期分卷、每卷最多 200 条，记录头带稳定键去重，`findChat` 按聊天号找已有目录 |
| `ArchiveListen.ts` | `applyChatArchive(ctx, root)`：听 `channel/direct`、`mention`、`listen`、`replied`、`recall` 写进 `ChatArchive`，附件原件复制进聊天目录的 `附件/`；由 memory 插件启动时调用，写不进只打日志 |
| `Message.ts` | 进来的一条消息：`ChannelMessage` 和它的提及、附件、引用、来源、可见性、路由 `ChannelRouting`、网页查看上下文，进来发哪个事件 `InboundEvent`、分法 `getInboundEvent` 和发事件 `emitInbound`，认领记录 `ChannelClaimRecord`、`ChannelMessageControl`，来源快照 `SourceSnapshot`，撤回载荷 `ChannelRecallEvent` |
| `Reply.ts` | 回复：`ChannelReplyRequest`、片段 `ReplyPartInput`、回执 `ReplyReceipt`（v: 2）、`ChannelRepliedEvent`（带请求本身）、没有来源快照时的 `ReplyFrom`、`ChannelSettledEvent`（事件名 `bot/settled`，bots 发），回复键、请求摘要、发回复和拼回执的函数 |
| `TextReply.ts` | 只发纯文字的渠道共用的 `channel/reply` 响应器 `registerTextReply` 和适配器类型 |
| `Target.ts` | 跨渠道、跨聊天发话：目标 `ChannelReplyTarget`、能不能跨、目标串怎么拆、候选聊天怎么认、认不出怎么说 |

## 事件（声明在 `index.ts`）

| 事件 | 谁发 | 谁听 | 载荷 |
| --- | --- | --- | --- |
| `channel/direct` | 本插件 `emitInbound`（cli、feishu、programs、voice、web-api、wechat 经它发） | approval（消息级命令先看）、bots（按 `targetBots` 逐个认领）、memory、`applyChatArchive`、web-api、voice `VoiceReplies` | `ChannelMessage`，可选 `ChannelMessageControl`。私聊机器人：飞书 p2p、微信、网页、命令行、语音；语音半句提前开工的带 `routing.partial` |
| `channel/mention` | 本插件 `emitInbound`（feishu、programs、wechat 经它发） | approval（消息级命令先看）、bots（认领 `targetBots` 里被叫到的）、memory、`applyChatArchive`、web-api | `ChannelMessage`，可选 `ChannelMessageControl`。群里叫了机器人：@ 了它，或引用了它发的那条 |
| `channel/listen` | 本插件 `emitInbound`（feishu、programs、voice 经它发） | bots（只听：记背景或判断要不要接；`targetBots` 空的谁都不进）、memory、`applyChatArchive`、web-api；approval 不听 | `ChannelMessage`，可选 `ChannelMessageControl`。机器人收到了、但没叫它：群里没 @（没登记的群也发）、语音里只入档的整句 |
| `channel/reply` | 本插件 `requestChannelReply`（approval、bots、relay、work-decision 经 `requestTextReply` 调它） | feishu、voice、本插件 `registerTextReply`（cli、web-api、wechat、programs 调它挂） | `ChannelReplyRequest` |
| `channel/replied` | 本插件 `emitReplied`（feishu、voice、`registerTextReply` 调它）；approval 的 `publish` 给外置程序的发件补一条 | `requestChannelReply`（按 `requestId` 配对）、bots `FrontDesk`、memory、`applyChatArchive`、web-api | `ChannelRepliedEvent`（回执 + 请求本身） |
| `channel/recall` | feishu `FeishuInbound.onRecall` | bots `DispatchRecall.listen`、`applyChatArchive`（另记一条撤回备注） | `ChannelRecallEvent` |

进来的三个事件互斥，一条话只发一个：没叫机器人发 `channel/listen`；叫了、在群里发 `channel/mention`；叫了、不在群里发 `channel/direct`。分法只在 `getInboundEvent(chatType, called)` 一处，各渠道都经 `emitInbound` 发，事件名不在渠道里写。`ChannelRouting` 只有 `sessionId`、`replyOrigin`、`autoFinal`、`partial` 四样，私聊、@、只听不在里面标，看发的是哪个事件；`partial` 是半句（话还没说完先交机器人开工），记录类插件（memory）不记、approval 不当批复认，等同一消息号的整句。

所有发出去的话（模型 `channel_reply`、零次兜底、审批直回、旧路自动回话、relay 回信、本人批准的主动发件）都走 `channel/reply` → `channel/replied`。回执带着整份请求（正文、来源快照、目标），记往来、记忆、网页挂回都只听 `channel/replied`。

`ChannelReplyRequest` 的 `sourceSnapshot` 可选：回某条消息时有；没有的一定带 `target.address`。`sessionId?` 是哪场会话说的，渠道照它定细节（命令行出错标红、微信只发做完的一轮、网页挂回会话认领的那条）。`atFiles?` 让正文里的 `@路径` 当文件发，只有旧路自动回话、relay 回信开，只有飞书认。`ChannelReplyTarget.address?` 是渠道自己的确切地址，给了就照它发，渠道不再按 `chat` 认聊天。

本插件自己不挂监听；`registerTextReply` 是在调用方插件的 ctx 上听 `channel/reply`，随调用方卸载自动撤销。

## 聊天记全写 MD

`applyChatArchive` 把五个事件写进 `<运行时根>/chats/<渠道>/<私聊或群聊>/<名字_ID>/<UTC日期>_<卷号>.md`：每条是“发话人 ID · 昵称 · 时间”一行、原话（多行照原样）、附件相对路径；用户的话键是 `in:<messageId>`，机器人的话（回执 sent、partial，且带来源快照）键是 `out:<replyRequestKey>`，撤回键是 `recall:<messageId>`，重放不重复。群聊名取来源地址的 `chatName`，私聊、本机聊天取发话人昵称，都没有时只用 ID；目录首次建好后按 `.chat-id` 认，改名不换目录。附件把渠道目录里的原件复制进聊天目录 `附件/`，没下载下来的跳过（正文里已有原因）。语音半句（`routing.partial`）不记。撤回事件没带聊天种类，找不到已有目录就不新建。JSONL 原件不动。memory 库加附件路径、撤回时刻这部分还没做。

## 对外函数

| 函数 | 文件 | 参数 | 作用 |
| --- | --- | --- | --- |
| `makeChannelMessageId(channel, accountId, nativeId)` | Message.ts | 渠道名、平台账号（本地入口 `'local'`）、平台消息号 | 标准消息号 `JSON.stringify([channel, accountId, nativeId])`，渠道发进来的事件前算 |
| `getInboundEvent(chatType, called)` | Message.ts | 聊天种类、叫了机器人没有（私聊、群里 @ 了、引用了机器人的话是 true） | 进来的一条话发哪个事件（类型 `InboundEvent`）：没叫 `channel/listen`；叫了、在群里 `channel/mention`；叫了、不在群里 `channel/direct` |
| `emitInbound(ctx, message, called, control)` | Message.ts | 渠道 ctx、标准消息、叫了没有、认领协调对象 `ChannelMessageControl` | 渠道存好原件后调：照 `getInboundEvent` 分好，用 `ctx.serial` 发 `channel/direct`、`channel/mention`、`channel/listen` 之一，等大家处理完；三个事件只在这一处发 |
| `getClaimKey(messageId, botName)` | Message.ts | 消息号、机器人名 | 认领去重键 |
| `getSourceSnapshot(message, botName, origin, claimKey, replyRoundKey)` | Message.ts | 渠道消息、机器人、地址、认领键、轮键 | 深拷贝一份本轮来源快照，后面回复都照它定位 |
| `resolveLegacyRole(address)` | Message.ts | 渠道地址 | 按地址里的 `owner`、`role` 算身份档位，缺证明是 `guest` |
| `getReplyRoundKey(messageId, botName, roundId)` | Reply.ts | 消息号、机器人、轮标识 | 回复轮键 |
| `getReplyRequestKey(replyRoundKey, callId)` | Reply.ts | 轮键、工具调用号 | 单次回复的幂等键 |
| `getPayloadHash(value)` | Reply.ts | 任意载荷 | 16 位 sha256 摘要，同键重试时比对正文 |
| `requestChannelReply(ctx, req, timeoutMs?)` | Reply.ts | ctx、去掉 `requestId` 的请求、超时（默认 30 秒） | 发 `channel/reply` 等 `channel/replied`；没渠道接是 rejected，超时是 uncertain |
| `requestTextReply(ctx, from, text, options)` | Reply.ts | ctx、来源快照或 `ReplyFrom { bot, replyRoundKey, target, sessionId? }`、正文、幂等键和类别和可选目标和 `atFiles` | 拼一段纯文字的请求再交给 `requestChannelReply`；没有来源快照的（Bots.send、relay、approval 主动发件）给 `ReplyFrom`，`target.address` 必带 |
| `getReceipt(request, status, reason?)` | Reply.ts | 请求的键和片段、状态、原因 | 拼 v2 回执，逐段带状态 |
| `emitReplied(ctx, request, receipt)` | Reply.ts | ctx、整份请求、回执 | 发 `channel/replied`（回执带请求本身），渠道回执的唯一出口 |
| `registerTextReply(ctx, adapter)` | TextReply.ts | 渠道 ctx、`TextReplyAdapter`（渠道名、可选认聊天回调、直发回调 `sendDirectText(text, request, targetAddress?)`，可交回 `TextReplyOutcome`，不交回算已发） | 挂纯文字渠道的 `channel/reply` 响应：认领、同键重放、同键不同正文拒收；请求带 `target.address` 时照它发（不调 `getTargetAddress`），只带 `target.chat` 才认聊天；发完回回执 |
| `applyChatArchive(ctx, root)` | ArchiveListen.ts | 插件 ctx、运行时根目录 | 挂聊天归档的五个事件监听，交回 `ChatArchive` |
| `canReplyAcrossChats(snapshot)` | Target.ts | 来源快照 | 这一轮能不能跨渠道、跨聊天发：外人和群里一律不行 |
| `parseChatTarget(raw, labelPrefixes)` | Target.ts | 原始目标串、渠道展示前缀 | 拆成整串、去前缀的名字、“前缀:聊天”两半 |
| `findChatByIdOrName(candidates, id, name)` | Target.ts | 候选聊天（可以是生成器）、号、名字 | 号或名字先对上的那个 |
| `getChatNotFoundMessage(chat)` | Target.ts | 原始目标串 | 认不出时的原因文字 `chat_not_found：…` |

## 内部

`registerTextReply` 里有一张只在内存的表：`replyRequestKey` → 摘要和回执，只记 sent、draft 的，用来同键重放；插件重挂就清空。没有别的状态。
