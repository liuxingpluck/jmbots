# web-api v1.1.20

保存附件未获回执且结果不确定时返回 504，保留暂存附件并中止消息提交。

插件提供

- HTTP 消息渠道
  - 网页的话一律经 `channel/message` 入站，role 写 owner，`origin.address` 带 `owner: true`，让“同意 N”可批所有待确认，并设置 `routing.autoFinal`。
  - `registerTextReply` 挂入 `getTargetAddress`，自认本机聊天。
  - `replyDirect` 承接带 `target` 的跨渠道发话，新建时间线行，不串挂原入站消息。
  - 所有发到网页的话（模型的 `channel_reply`、旧路自动回话、审批直回、本人批准的提醒）都经 `channel/reply` 到 `replyDirect`，向 bots 只登记渠道名 `ctx.bots.channel(name)`。
  - 旧路自动回话（会话一轮结束、旧会话中途一句、前台送后台结果，没有来源快照）由 bots 的 `Bots.send` 发：`target.address` 是会话记的 `{ messageId }`，带 `sessionId`，挂在说话的那场会话上。
  - 指定 `session` 或引用别的渠道的消息时，带校验过的 `routing.sessionId`。引用时再带 `routing.replyOrigin`，回话回到网页这条。
  - 前台一轮内，`channel_reply` 调几次就追加几条回话。一次没调时由零次兜底发最后的话。收尾 `bot/settled` 时才标 replied。
- 跨渠道消息时间线
  - 其他渠道的消息记标准消息号 `source_id`，回话按“消息号 + 机器人”精确挂回。
  - `GET /api/channels` 列出挂着的渠道和聊天。
  - 时间线按 `channel` + `chat` 筛，`POST /api/message` 收可选 `view`。
- 会话控制与追溯
- 网页机器人与状态接口

网页定时提醒

1. `POST /api/message` 从 HTTP 鉴权钩子取得 `verifiedOwner` 并写进 `origin.address`。创建者用此标记确认。
2. 到期时本人批准的主动发件经 `channel/reply` 来，`target.address` 带 `reminder` 意图号。`replyDirect` 调 `writeReminder`，按原机器人在本机网页时间线写一条“（系统）正文”，按 `reminder:<意图号>` 去重。机器人已不在是 rejected。
3. 回 `channel/replied`。

语音时间线

- `voice/record` 以标准来源号和机器人去重存最终原话，保留语音产生时间、浏览器聊天号和关联会话。
- 语音回复经 `channel/replied` 追加，以 `replyRequestKey` 去重并保存浏览器的 `spoken` 确认状态。
- `GET /api/messages` 支持全部、语音、指定浏览器三种范围。

时间线遇到旧消息中的损坏地址时，仍返回该条和同页消息。飞书和微信的标签只使用地址中的字符串字段，缺少名称时沿用各渠道的备用显示。

## 数据

### 数据库表

`web_messages` 是收件表：各渠道进来的每句话和机器人对它的回话；一行是一条收到的消息，回话追加在 `replies` 里。

| 列名 | 类型 | 能不能空 | 意思 | 谁写、什么时候写 |
|---|---|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 否 | 收件消息号 | `Timeline.insert` 插入时自增 |
| `bot` | TEXT NOT NULL | 否 | 机器人 | `insert`：别的渠道来话由 `bot/receive` 监听调，HTTP/网页来话由 `accept` 调 |
| `channel` | TEXT NOT NULL | 否 | 原收话渠道（http / feishu / wechat 等） | `insert` |
| `source` | TEXT NOT NULL | 否 | 来源：HTTP 的 from（默认 http，网页传 web）；别的渠道等于 channel | `insert` |
| `address` | TEXT | 能 | 原渠道地址 JSON；http 来话是 NULL | `insert` |
| `text` | TEXT NOT NULL | 否 | 原话加 @附件路径 | `insert` |
| `session_id` | TEXT | 能 | 处理它的会话 | `insert` 写 NULL；`bot/receive` 已有会话时、`accept` 指定/分派会话时 UPDATE；`Timeline.reply` 首次回话时补（COALESCE） |
| `status` | TEXT NOT NULL | 否 | `taken` 处理中 / `replied` 回完 | `insert` 写 taken；`Timeline.reply` 会话不在转了改 replied；`replyDirect` 改 replied |
| `replies` | TEXT NOT NULL DEFAULT '[]' | 否 | 回话列表 JSON（StoredReply[]：时刻、会话、文字、生成信息、用时） | `Timeline.reply` 每句回话追加 |
| `created_at` | INTEGER NOT NULL | 否 | 收话毫秒时刻 | `insert` |
| `updated_at` | INTEGER NOT NULL | 否 | 最近一次回话或收尾的毫秒时刻 | `insert`、`reply` |
| `reply_to` | INTEGER | 能 | 引用回复的是哪条 `web_messages.id` | `Timeline.insert` |
| `source_id` | TEXT | 能 | 原渠道提供的标准消息号 | `Timeline.insert` |

现有运行库的 `web_messages` 需包含这两列，空值允许保留。

删：`Timeline.remove` 删一行。

## 设计要点

- 消息时间线、回话关联是网页渠道的投影，独立于会话持久化；其他渠道的记录也记一份供同一界面查看。
- Timeline 处理展示用的收件，Trace 组织已有的会话和 journal 证据；不凭不存在的分派记录编历史。
- 可选服务用 ctx.get / inject 取，缺辅助插件时核心收件仍能挂上。
