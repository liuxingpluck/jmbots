# context-fit v1.1.2

会话上下文总结、压缩与裁剪合在一个插件，由原 `compress`、`context-fit` 和 `summary` 合并（方案名 `session-context`）。

1. `Summary`（`Summary.ts`）
   1. 干活的会话完成一轮（`state=done`）后，起 `summary` 小会话。
   2. 生成一两句总结，写入 `row.summary`。
2. `Compress`（`Compress.ts`）
   1. 请求发送前监听 `session/request`，检查上一步模型总 token。
   2. 达到 `compress.at` 时起 `compress` 小会话，把旧对话压成摘要写入 `compress_log`。
   3. 本次 `request.messages` 替换为 `[摘要消息, ...后续原文]`。
3. `ContextFit`（`index.ts`）紧随 `Compress` 监听 `session/request`。压缩后仍超出上下文窗口比例 `ratio` 时依次处理。
   1. 将较早工具结果换成“已省略”，保住最近 `keep` 条。
   2. 仍超出就按段裁掉早期对话，保留最后用户话和最近 `keep` 段。
   - 裁剪只修改请求副本，原 `SessionRow.messages` 保持原样。

## 数据

### 数据库表（`ctx.db.orm`）

`Schema.ts` 声明原来的 `compress_log`，启动时把首个迁移交给 db。旧表保留原来的列、会话号和记录。没有 db 时，Cordis 把本插件标为等服务；在 `plugins` 中把 `db` 放到 `context-fit` 前。

`compress_log` 每行是一场压缩过的会话，只压 `work` 会话。每行记录两样。

- 后台会话压到哪
- 摘要是什么

| 列名 | 类型 | 能不能空 | 意思 | 谁写、什么时候写 |
|---|---|---|---|---|
| `session` | TEXT PRIMARY KEY | 否（主键） | 会话号 | `Compress.compress` 跑完 `compress` 小会话后写入摘要，再压时更新同一条记录。 |
| `upto` | INTEGER NOT NULL | 否 | 压到第几条消息（不含），之前的都用摘要代替 | 同上 |
| `summary` | TEXT NOT NULL | 否 | 摘要全文，以后每次 `session/request` 套在尾部消息前面 | 同上 |

表定义见 `src7/plugins/context-fit/Schema.ts`，压缩条件和写入见 `src7/plugins/context-fit/Compress.ts`。

## 设计要点

- 只改请求副本来缩短发出去的上下文，原始会话保留。
  1. 省略旧的工具内容。
  2. 按完整消息段裁剪，保持工具链完整。
- 预算裁剪确定且便宜，与 compress 的模型摘要、fallback 换模型分开。
  - 有 catalog 上限时优先用它。
  - 没有 catalog 上限时回 getModel。
