# context-fit v1.1.6

1.1.6 云端 26 复核修复：`estimate` 遇到图片块按 `IMAGE_TOKENS`（1500）计，不再把 base64 当文字（一张 500KB 截图原来会被估成十几万 token，裁剪为它丢掉大段历史）；`getCompressInput` 每条消息的每块文字（用户话、模型正文、思考、调工具参数、工具结果）都按预算的 1/4（至少 200 字）截，还超就先保最新一条、首条装得下才留，块太多仍超就整段截到预算内，单条超大消息也不会撑爆压缩小会话；压缩小会话没做成后记下当时的消息数，再多出 `RETRY_AFTER_MESSAGES`（10）条才重试（失败记录最多 500 场），不再每一步都开一场注定失败的压缩；`readModelWindow` 遇到没有“供应商/”的模型名不再砍掉最后一个字，报一行警告并记一分钟；`fit` 能丢的都丢了还超预算时打一行警告（照原样发出）。

1.1.5 体检修复（第 13 块第 1–3 条）：压缩只认前台（`front`）、后台（`work`）两种长期对话，小会话不管带没带 `parent` 都跳过（原来按一张小会话种类表加 `parent` 判断，`decision` 不带 `parent` 会漏网）；交给压缩小会话的那段对话按登记窗口的一半限长（`getCompressInput`：图片换成“[图片]”、单条工具结果超 2000 字留头尾、还超就留第一条和最后几条、中间写一句省了几条）；模型目录给的登记窗口按模型名在本插件里缓存 60 秒，目录没就绪、查不到、只有估算值时不缓存。`estimate` 挪到 `Compress.ts`，`index.ts` 照旧导出。

1.1.4 裁剪和压缩查询目录窗口时直接等待回执，保留请求取消信号。目录缺席、处理失败或缺少已登记窗口时，先查手写配置。缺少登记值时压缩跳过，裁剪仍可用估算窗口。

会话上下文总结、压缩与裁剪合在一个插件，由原 `compress`、`context-fit` 和 `summary` 合并（方案名 `session-context`）。

1. `Summary`（`Summary.ts`）
   1. 干活的会话完成一轮（`state=done`）后，起 `summary` 小会话。
   2. 生成一两句总结，写入 `row.summary`。
2. `Compress`（`Compress.ts`）
   1. 请求发送前查目标模型的上下文窗口，读取上一步回答的 `usage.totalTokens`。
   2. 用量达到已登记窗口的 `compress.ratio`（默认 80%）时，起 `compress` 小会话整理当前请求里较早的消息。只有前台和后台会话会触发。
   3. 交给小会话的那段对话先经 `getCompressInput` 限长到登记窗口的一半，免得压缩请求自己先超长。
   4. 本次 `request.messages` 替换为 `[摘要消息, ...后续原文]`。
3. `ContextFit`（`index.ts`）在同一个 `session/before-model` 监听里完成压缩和裁剪，两个阶段共用一次窗口查询。压缩后仍超出顶层 `ratio` 对应的预算时依次处理。
   1. 将较早工具结果换成“已省略”，保住最近 `keep` 条。
   2. 仍超出就按段裁掉早期对话，保留最后用户话和最近 `keep` 段。
   - 裁剪只修改请求副本，原 `SessionRow.messages` 保持原样。

## 数据

### 数据库表（`ctx.db.orm`）

`Schema.ts` 声明原来的 `compress_log`，启动时把首个迁移交给 db。旧表保留原来的列、会话号和记录。没有 db 时，Cordis 把本插件标为等服务；在 `plugins` 中把 `db` 放到 `context-fit` 前。

`compress_log` 每行是一场压缩过的会话。

- 会话压到哪
- 摘要是什么

| 列名 | 类型 | 能不能空 | 意思 | 谁写、什么时候写 |
|---|---|---|---|---|
| `session` | TEXT PRIMARY KEY | 否（主键） | 会话号 | `Compress.compress` 跑完 `compress` 小会话后写入摘要，再压时更新同一条记录。 |
| `upto` | INTEGER NOT NULL | 否 | 压到第几条消息（不含），之前的都用摘要代替 | 同上 |
| `summary` | TEXT NOT NULL | 否 | 摘要全文，以后每次 `session/before-model` 套在尾部消息前面 | 同上 |

表定义见 `src7/plugins/context-fit/Schema.ts`，压缩条件和写入见 `src7/plugins/context-fit/Compress.ts`。

## 设计要点

- 只改请求副本来缩短发出去的上下文，原始会话保留。
  1. 省略旧的工具内容。
  2. 按完整消息段裁剪，保持工具链完整。
- 只压前台（`front`）、后台（`work`）这两种长期对话（`COMPRESS_KINDS`）。别的种类都是 `sessions.ask` 开的小会话（`compress`、`summary`、`exec-review`、`decision`、`review`……），不管带没带 `parent` 都跳过；以后新开一种小会话不用来这里登记。带 `parent` 的后台会话照样能压缩。
- 交给压缩的那段对话最多占登记窗口的一半（`INPUT_SHARE`）：先换图片、每块文字截到预算的 1/4（`MESSAGE_TEXT_MIN` 至少 200 字，工具结果最多 `TOOL_TEXT_MAX` 2000 字）；还超就先保最新一条、首条装得下才留、中间写一句省了几条；块太多仍超就整段截到预算内。压缩小会话自己不会因为输入太长失败。
- 压缩没做成（小会话出错、被停，或 `sessions.ask` 直接抛异常）不每步重试：记下当时的消息数，多出 `RETRY_AFTER_MESSAGES`（10）条再试；提问方被叫停不算失败；抛异常时打一行日志，这一步不压，不挡主会话。
- 截短（`getShortText`）留头尾时，切口落在 emoji 这类 UTF-16 代理对中间就把半个字丢掉，不发出孤立的代理码点。
- 估 token 时图片每张按 `IMAGE_TOKENS`（1500）算，裁剪和压缩口径一致，不会为一张截图丢掉历史。
- 当前请求仍包含原会话的对应历史前缀时，可以保存并复用摘要。上游已筛选的消息按当前可见范围压缩，摘要只用于这一轮。
- 压缩阈值用目录或手写配置登记的正数窗口。窗口缺失、为零或只有估算值时跳过生成新摘要，已有摘要仍可使用。裁剪可沿用目录和 Resources 的估算窗口。
