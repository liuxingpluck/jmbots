# file-tools v1.2.2

给 work、front 会话提供工作区基础文件工具（`time`、`read`、`list_dir`、`write`、`edit`、`find`）、`@图片` 接看图模型，以及技能清单注入和只读 `skill` 工具。
关键边界：读写只限当前轮的工作区和授权目录（符号链接解开后核对）；`skill` 只读不跑脚本，只给 work 会话。
分工：`BaseTools.ts` 基础工具和看图，`index.ts` 的 `edit`、`find`，`EditMatch.ts` 替换匹配，`Skill.ts` 技能，`dsh-control/` 随源码带的技能。

## 干什么

- 工具 `time`、`read`、`list_dir`、`write`、`edit`、`find`。
- 用户 `@图片` 接入看图模型请求。
- 技能（`Skill.ts`，默认可用，`config.yaml` 不单列）：每步调模型前把技能清单注入 work 会话系统提示词，并提供只读 `skill` 工具。
- 机器人名单和目录等只读值由 `utils/Bots.ts` 读取；工作区写文件前用 `utils/Files.ts` 的 `ensureDir` 建父目录。
- 文件路径解析用本轮机器人名和回话地址：工作区由它们确定，授权目录取回话地址 `grants.dirs`（approval 的目录授权），都经 `utils/Bots.ts` 的 `resolveSessionPath`。

### 文件

- 文件操作限于当前轮的工作区和授权目录。
  1. 用 `Workspace.getWorkspace(botWorkspace, address)` 取工作区，`Workspace.getGrantDirs(address)` 取授权目录。
  2. 由 `Workspace.resolveWorkspacePath` 解开符号链接，核对落在其中一个里面。
  - 无插件专属固定 schema 文件。
- 技能路径：`<root>/skills/<目录>/SKILL.md`、`<root>/bots/<bot>/skills/<目录>/SKILL.md`。
  - YAML.name：非空 string 作为技能名，否则目录名；YAML.description：string 作为说明，否则首条正文非空行去标题 `#`，最多 200 字符。
  - 正文完整保留，`skill` 工具直接交回文件全文；`file` 参数指定的同目录文件以 utf8 读任意普通文件，不执行脚本。
  - 来源：`src7/plugins/file-tools/Skill.ts:49`

## 随源码带的技能（dsh-control）

插件目录下的 `dsh-control/` 是一份技能的源码，负责把活交给 Windows 上的 DSH。它不会作为插件编译进程序。

1. 把整个目录复制到 `<数据根>/bots/<机器人>/skills/dsh-control/`。
2. 照 `settings.example.json` 写一份 `settings.json`，填入
   - DSH 客户端路径
   - 登记的工作区
   - 默认等待时长

- `SKILL.md`：work 会话用 skill 工具读，写清何时用、怎么跑、输出怎么看；读它不会跑任何东西。
- `scripts/dsh.mjs` 由 work 会话用 exec 显式运行。
  - 每一步调用现有的 `ztools/dsh-control/Dsh_Control.mjs`，不自行连接 DSH 或读令牌。
  - 只认 `settings.json` 登记的工作区，必须和当前目录精确相同。
  - 记录写在工作区 `.dispatch/<任务号>/dsh.json`。
- 测试：`DshSkill.test.ts`（假客户端，不连真 DSH）。

## 设计要点

- edit 的写入约束
  - 对同一份原文校验后一次写回。
  - 唯一、不重叠的规则减少误改。
  - 模糊匹配只限已有的规范化规则。
- find 使用运行时自带能力，机器无需装 rg。
  - 限制文件体积、二进制和输出量。
  - 路径受当前身份的工作区边界约束。

- 技能设计：摘要清单先于正文，work 按需调用只读 `skill`，避免每步注入所有技能全文；机器人同名技能覆盖全局，补充文件限制在同一技能目录；读取和执行分离，不因文件存在自动跑脚本。
- DSH 技能（随源码带的 dsh-control）
  - 技能是目录，必需 `SKILL.md`，可选 `scripts/`、`references/`、`assets/`。
  - 技能说明不授予权限。DSH 脚本只接受可信服务登记且来源身份获准的任务。调用者自制的请求 JSON 不能作为授权。
- DSH 脚本由 work 用 exec 显式启动，工作目录为选定的机器人工作区。
  1. 在该工作区 `.dispatch/<任务号>/` 保存请求和会话映射，先持久记录稳定的 `sessionId` 和 `requestId`。
  2. 等选模型成功再发 prompt。
  3. 超时后保存 ID，继续查同一会话，不换 ID 重发。
- 错误与暂停
  - 工作区不唯一回 `workspace_mismatch`，缺配置回 `configuration_missing`。
  - 401/403、TLS 和网络错误交回原因，不输出 Cookie 或 token。
  - 模型或档位不可用时不更换供应商。子代理不存在时不拿多个普通会话冒充。
  - 暂停时先停脚本投递，再 cancel 已知会话。确认不了就回 `pause_unconfirmed`。
