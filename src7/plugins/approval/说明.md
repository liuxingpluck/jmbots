# approval v1.1.6

审核命令、按说话人限制工具，并持久管理用户待确认及卡片。别的插件找它办事发请求事件 `approval/request`（契约 `docs/开发进度/插件互调_事件契约_20261118.md` 3.2 第 1 条），不再直接调 `ctx.approval`（服务方法保留给还没改的调用方）。

审核四档：程序规则（密钥拒绝、项目检查放行、**可信目录放行**）→ 决策模型（发 `decision/judge`）→ 审核小会话 → 问用户。

**可信目录**（1.1.1，用户 11-18 #169）：命令的执行目录、开头 `cd` 到的目录、命令里写的每个绝对路径、带 `..` 往上走和从盘根算（`\` 开头、只写盘符）的相对路径，解开后都落在可信目录里，又不命中 `mustAsk`（删系统、删注册表、删数据、格式化），程序规则直接放行，`by: 'rule'`、原因“可信目录”。可信目录 = 配置 `trusted_dirs` + 这场会话的授权目录。写了环境变量（`%X%`、`$X`、`${X}`、`~`）的命令算不出落在哪，不算可信；碰密钥文件的照旧先拒；builder 让跑的（`confined`）不看可信目录。

**审批卡片说清楚**（1.1.2，用户 11-18 #172）：命令要问用户时，卡片正文（`card.reason`）固定三行，飞书卡片顶上、网页审批面板一眼看完：
1. `要做什么：` 审核小会话写的命令执行完的结果（`what`，不复述命令）；它没写就用决策模型顺带写的执行结果（1.1.6：`askDecision` 带 `want: ['what']`，`decision/judge-result` 回的 `what`，决策模型拿不准、往下走时才用得上）；都没有就写“说不清会做成什么（命令：<命令>）”，不编，照旧问用户。这句只用来显示，放行规则（可信目录、mustAsk、决策模型阈值、审核小会话 safe）不看它；
2. `动哪些：` 命令里解析出的绝对路径在前、审核列的 `paths` 在后，去重后最多 5 个（多了写“等 N 个”），都没有写执行目录；
3. `为什么问你：` review 一路记下的每一档没放行的原因（`asks`）：mustAsk 的原因、`getUntrusted` 的原因（没配可信目录 / 某路径不在可信目录里 / 写了环境变量）、决策模型拿不准的原话（真答过才写）、`审核小会话：<risk 原文>`。

审核小会话没写 risk、或不放行却写“无”时一律写“审核没给出理由”（`getReviewReason`），不留空；`card.risk.text` 也用它，不单写“风险中”。每行最多 160 字。审核提示词要求 what、risk 写具体的路径、操作和后果，不许只回“有风险”。

**授权目录（grants）**：本人或中控（`from: 'claude'`）发 `POST /api/message` 时带 `grants: { dirs: [绝对路径…] }`，web-api 入口用 `utils/Checks.ts` 的 `checkGrants` 查一次、规范化一次，写进回话地址 `origin.address.grants`；`bots.route` 把地址记到 `session.row.address`，交办的后台会话带着同一个地址。approval 审 exec 时读 `sessions.find({ id })[0].address.grants.dirs`，只认 `owner: true` 的地址。地址跟着最后一句带渠道的话换：后来的消息没带 grants，授权就没了。

**命令名后缀不写死**（1.1.4）：项目检查直接放行的 `bun run typecheck:src7`、`test:src7`，后缀取 `src7/utils/SourceDir.ts` 的 `SOURCE_DIR`，源码目录改名时跟着变。

## 数据

## 设计要点

- 判断和执行分开：approval 只给结论和持久的待确认，exec、runs、update-watch 等提问者自己执行。
- 规则、可选的 decision、审核小会话、本人确认分层；必须人审的危险操作不能被模型放行，builder 不能自己审批自己的越权请求。
- 卡片是渠道对 CardData 的渲染；渠道和文字回复按实际 customer、actor、群权限核对。
