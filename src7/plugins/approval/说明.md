# approval v1.1.0

审核命令、按说话人限制工具，并持久管理用户待确认及卡片。

## 数据

### 数据库表

`approval_pending` 存要用户点头的事（执行命令、更新、复盘、长任务等）；一行是一次提问，从等着到定下都在这一行上改。

| 列名 | 类型 | 能不能空 | 意思 | 谁写、什么时候写 |
|---|---|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 否 | 待确认号（“同意 N”里的 N） | `Approval.ask` 插入时自增 |
| `kind` | TEXT NOT NULL | 否 | 提问用途：exec / run / update / review / long-run 等 | `ask`，由提问的插件给 |
| `title` | TEXT NOT NULL | 否 | 标题 | `ask` |
| `detail` | TEXT NOT NULL | 否 | 说明文字 | `ask` |
| `payload` | TEXT NOT NULL | 否 | 提问方自带的 JSON（undefined 存成 null），定下后原样交回提问方 | `ask` |
| `bot` | TEXT NOT NULL | 否 | 哪个机器人问的 | `ask` |
| `session` | TEXT | 能 | 原会话号 | `ask` |
| `state` | TEXT NOT NULL | 否 | `waiting` 等着 / `approved` 同意 / `rejected` 拒绝 | `ask` 写 waiting；`settle` 改：用户点同意/拒绝走 `decide`，自动结束走 `close`（记 rejected） |
| `decided_by` | TEXT | 能 | 谁定的，或自动结束的原因 | `settle` |
| `asked_at` | INTEGER NOT NULL | 否 | 登记毫秒时刻 | `ask` |
| `decided_at` | INTEGER | 能 | 定下的毫秒时刻 | `settle` |
| `card` | TEXT（补的列） | 能 | 卡片 CardData JSON；旧行是空的，读时照 title、detail 拼一张 | `ask` 写等待态；`settle` 改成定下后的样子；老库构造函数补列 |
| `customer` | TEXT（补的列） | 能 | 发起的客户号 | `ask` 照原会话取（`getInitiator`） |
| `actor` | TEXT（补的列） | 能 | 发起的个人身份 | `ask` 同上 |

依据：建表 `src7/plugins/approval/index.ts:229-231`，补列 `:233-236`；写 `:402`（`ask`）、`:471`（`settle`，由 `decide` `:437`、`close` `:452` 调）。
