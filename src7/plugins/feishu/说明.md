# feishu v1.1.19

登记的 builder 和 guest 工作区用 `utils/Files.ts` 的 `ensureDir` 创建。

飞书卡片提交审批决定或控制进度时，以下情况都提示核对。

- 超时
- 中止
- 监听异常

审批占用保留到明确收到结果。

1.1.16 的回执和测试说明

- 保留发送结果不确定时的传输异常链。
- 群回复测试等发送结束后再断言。

本插件管理飞书多应用收发，提供以下能力。

- 标准化 `channel/message` 事件收、回及历史。`onChannelReply` 带 `target` 时，飞书从自有群名缓存、配置、私聊表或流水自认聊天。
- 确认 `im.message.recalled_v1` 后把原话和撤回时刻交给 bots；随后回这条消息时直发原聊天。
- 消息附件与群聊身份。
- 审批与进度卡片。
- 云文档工具。
- Markdown 发件箱。

> 飞书开放平台配置消息撤回联动
>
> 1. 在「权限管理」持有既有 `im:message` 或 `im:message:readonly` 权限。
> 2. 在应用后台 **「事件与回调 → 事件配置 → 添加事件」** 搜索勾选 **`撤回消息`（`im.message.recalled_v1`）**。
> 3. 创建并发布版本后生效。

群配置 `groups[].daily` 由 `progress` 按运行机器的本地时间调度。

- `at` 使用 `HH:mm`。
- `bot` 登记发送机器人。
- `prompt` 登记日报提示。
- 同一机器人可用多个飞书应用时用 `app_id` 选定。
- 填了 `daily` 且未写 `listen` 时，默认收全部群消息供记忆索引。

主动发件按 Outbound 已确认的飞书应用 ID、聊天 ID 和原文，发到指定群或私聊。

- 正文保留 `@路径` 等普通文字。
- 直发使用意图 UUID 作为飞书去重键。
- 运输回执按结果区分
  - 明确拒收回 `failed`。
  - 传输结果无法确认回 `uncertain`。
  - 已受理回 `sent`。
- 成功后写入聊天历史，历史写入故障独立记日志。

确认契约见 [approval 说明](../approval/说明.md#本人确认渠道发件)。

定时提醒按以下步骤走。

1. 确认卡只送到来源应用中已登记的本人私聊。尚未和该应用私聊过时，可在网页审批面板确认。
2. 提醒到期后，由原 `channel/send` 监听投递到原群或私聊。

## 文件分工

渠道收发按职责分文件（1.1.13 起）。后四个各是一个 class，由 `Feishu` 构造时建好，构造只登记各自的事件，运行时目录交后续流程处理。

- `feishu.inbound`
- `feishu.reply`
- `feishu.history`
- `feishu.contacts`

| 文件 | class | 管什么 |
|---|---|---|
| `index.ts` | `Feishu` | 对外类型、`feishuCustomer`、配置校验（`checkConfig`）、长连接（connect/start/mark/findSelf）、群名缓存（`chats`、`chatNames`）、别的插件调的发送口（`sendText`、`sendCard`、`updateCard`、`sendFile`、bots 登记的 `send`）、`apply` |
| `Inbound.ts` | `FeishuInbound` | 长连接推来的收消息、撤回、点卡片：去重、`handleInboundMessage` 的 7 步、发 `channel/message`、`channel/recall` |
| `Reply.ts` | `FeishuReply` | 响应 `channel/reply`（回复去重、跨聊天认目标）和 `channel/send`（已批准的主动发件） |
| `History.ts` | `FeishuHistory` | 聊天日志 `channels/feishu/chats/` 的读写，响应 `channel/history` |
| `Contacts.ts` | `FeishuContacts` | 来往流水 `data/logs/feishu-contacts.jsonl` 的记和读，听 `bot/judged` |
| `Media.ts`、`Api.ts`、`cards/`、`doc/`、`outbox/` | 函数 | 媒体收发、SDK 调用重试、卡片、云文档、发件箱（没变） |

## 设计要点

- 以下模块共用同一个应用身份和客户端，作为一个平台插件分工。
  - SDK
  - 素材
  - 卡片
  - 云文档
  - 发件箱
- 渠道处理群 @、监听与身份，把平台地址交给 bots。
  - 审批和进度卡片桥接独立的业务服务。
  - 群或私聊的受众与 role 是权限输入。

当前边界

- 每个应用按配置投递给单个机器人。
- 发送异常可能只记日志。平台确认仍以平台回执为准。
