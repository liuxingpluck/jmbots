# decision-map v1.3.0

`/decision-map/` 是任务树和面向中控的收件渠道。插件、中控和网页可在同一棵树上登记任务。金色标主线，红星标待定。用户点一个选项后显示「已定 ✓」，中控收到并确认后变绿。

画布和清单都可以展开或折叠父项。「当前进展」优先显示主线、待定和进行中的任务。「只看待定」保留待定及其祖先。手机详情和选项从底部打开。

顶栏右侧的「看法」切换四种看法，用同一份快照、同一个节点侧栏：

| 看法 | 样子 |
|---|---|
| 思维导图 | 根在中间，一级分支左右交替排开，子节点往外一层层长，曲线连线；可切「上下」，根在上往下长。折叠、聚焦、待定醒目和放射看法相同。 |
| 放射 | 上面说的放射画布。 |
| 表格 | 一行一个节点，列：状态、标题、一句话、所属分支、要你定的选项（推荐、已选标出）、更新时间。可按待定、进行中、已定、做完筛，点一行打开侧栏。 |
| 清单 | 按一级分支分组的缩进列表，手机上最好读。 |

表格使用 antd Table 的 virtual 和数值滚动尺寸，清单使用 react-virtuoso，节点多时只挂载可见行；清单仍保留一级分支标题、原节点顺序与缩进。筛选、点击节点打开侧栏的行为不变。

看法和思维导图方向记在浏览器的 `jmbots.decision-map.look`、`jmbots.decision-map.direction`。没记过时，宽屏默认思维导图，手机宽度默认清单。新加的界面字经 `web/src/I18n.ts` 的语言包翻译。

点任意节点可读摘要和 Markdown 正文。侧栏的「加子项」只需标题，新项初始为未开始，可继续在下面加子项。侧栏可修改任务状态。「只看这棵子树」把当前节点作为视图的根，顶部路径可返回任一级或恢复全图。

侧栏的「发给中控」可直接留言。待定项可以只写答案，也可写完再点选项，把选择和留言放进同一条收件。用户留言和中控回话按时间列出。

## 依赖与配置

`resources` 提供运行时目录，`http` 提供 API，`web` 托管 `web/decision-map.html` 构建后的页面。

在 `plugins` 中加入 `name: decision-map`。`config.relay_helper` 取 relay 已配置的收件助手名，例如 `Claude`。`ztools/remote-claude/Wait_Relay.mjs` 可收网页、插件的新任务及状态变化，或用户给的选择和留言。relay 暂不可用时，中控可按版本号读变化接口。中控经 HTTP PUT 更新任务时仍记历史。

使用飞书提醒时，把手机可访问的决策图完整地址写入 `decision-map` 的 `config.public_url`。模板里的局域网地址可按实际网络调整。提醒链接使用同一运行时 `config.yaml` 中的 `server.token`。

## 接口

| 接口 | 参数和效果 |
|---|---|
| `GET /api/decision-map/graph` | 返回 `{ revision, nodes }`，供网页和中控读取。 |
| `PUT /api/decision-map/nodes` | 中控提交节点数组或 `{ nodes }`。已有节点保留未提供字段，整批校验通过才生效。支持 `body` Markdown 文本。 |
| `POST /api/decision-map/child` | 网页提交 `{ parent, title }`，生成 `work/open` 子项，返回 `{ id, graph, delivery }`。 |
| `POST /api/decision-map/status` | 网页提交 `{ id, status }`，返回 `{ node, delivery }`。只有状态实际变化才记历史并投递。 |
| `PUT /api/decision-map/status` | 中控提交同样的状态字段并返回节点，更新静默。 |
| `POST /api/decision-map/choose` | `{ node, option }`。先保存用户选择，再返回节点和中控收件号或变化接口。同一选择可重试。 |
| `GET /api/decision-map/changes?since=0` | 返回 `{ last, changes }`，按 `seq` 递增。用户选择的 `action` 为 `choose`。 |
| `POST /api/decision-map/ack` | `{ node, note? }`。记中控确认时间，同时归档对应的 relay 收件。 |
| `POST /api/decision-map/note` | `{ node, text, option? }`。用户写话。`text` 去掉首尾空白后非空、最多 2000 字，节点不存在回 404。带 `option` 时先照 `choose` 落盘再记话。返回节点、新留言和中控收件号或变化接口。只写话不改节点状态。 |
| `POST /api/decision-map/reply` | `{ node, note, text }`。中控回某条用户留言，`note` 是留言号。被回的留言记 `repliedAt`，回话作为中控留言存进同一列表，同时归档这条留言的 relay 收件。 |

同一图有一个 `goal` 根节点。`parent` 可指向任意已有父项或同批新增的父项，缺父节点或成环时整批拒绝。`main: true` 从根向外连成一条路径。`pending` 且 `status: open` 的节点有可选的 `options`，每项含 `id`、`text`，可带 `recommended` 与 `cost`。`body` 保存原始 Markdown 文本。`detailPath` 仍作为出处路径展示。

节点的 `notes` 按时间存留言，每条含 `id`（节点内 `n1`、`n2`…）、`author`（`user` 或 `central`）、`at`、`text`，用户留言可带 `option`、`repliedAt`，中控回复某条用户留言时带 `replyTo`。从 relay 接收的回话还记录 `relayReplyId`，供重试去重。中控批量写节点时不能改 `notes`。

导入历史决定时，`decidedBy` 可填 `user` 或 `central`，`createdAt` 和 `decidedAt` 使用毫秒时间戳，`sources` 保存出处文档路径。详情栏显示这些记录，并标出当时选中的选项。

## 数据

`data/decision-map/graph.json` 存当前图及最近一次提交，正文和留言随节点保存。`history.jsonl` 逐条追加序号、时间、操作者、操作和相关节点，操作者为 `central`、`user` 或 `plugin`。操作有 `put`、`status`、`choose`、`ack`、`note` 和 `reply`。新增任务和状态变化还记录 `tasks`，含节点号、标题、新状态及可选旧状态。快照先原子写入，中断后可用最近提交补齐最后一条历史。

## 听和发的事件

| 事件 | 用途 |
|---|---|
| 听 `decision-map/upsert` | 传一个节点或节点数组。按 `id` 合并，沿用节点校验。新增任务和状态变化提交后进中控收件。 |
| 听 `decision-map/status` | 传 `{ id, status }`，推进任务状态并通知中控，保留原决定和对话。调用方可用 `ctx.serial` 等待完成。 |
| 发 `decision-map/chosen` | 首次保存用户选择后通知订阅者，含节点号、选项号和标题。 |
| 发 `decision-map/relay` | 请求投递或归档中控收件。选择按节点去重，留言按节点和留言号去重，任务变化按节点和提交序号去重。回信地址始终是真实节点。 |
| 听 `decision-map/relay-result` | 按请求号接收 relay 收件回执。最长等待 3 秒，缺席时保留变化接口。 |
| 听 `decision-map/relay-reply` | 按收件地址落盘。留言回信关联原留言并记 `repliedAt`，选择和任务变化的回信追加到节点对话。旧收件使用原键定位。 |
| 发 `decision-map/relay-replied` | 回送写图结果。回信号重复时确认已有记录，relay 据回执更新已送状态。 |

## 中控命令

```text
node ztools/central/Decision_Map.mjs add <节点文件.json>
node ztools/central/Decision_Map.mjs child <父节点号> <节点文件.json>
node ztools/central/Decision_Map.mjs status <节点号> <状态>
node ztools/central/Decision_Map.mjs list
node ztools/central/Decision_Map.mjs done <节点号>
node ztools/central/Decision_Map.mjs notes
node ztools/central/Decision_Map.mjs reply <节点号> <留言号> <回话>
node ztools/central/Decision_Map.mjs notify --data <运行时目录>
```

`child` 读取一个节点对象，缺省使用 `work`、`open` 和自动生成的节点号，父节点由命令行指定。`status` 只改任务状态。`add`、`child`、`status` 的变更均记入历史，供中控按序号回查。

任务变化进中控收件的正文示例：

```text
任务树「核对附件」
节点 demo-review，状态从 open 改为 working。
```

`notes` 列出用户写过、中控还没回的话，每条含节点号、标题、留言号、时刻、内容和一并选的选项。`reply` 把回话写进节点并归档那条收件。也可以将 relay 收件号交给 `POST /api/relay/reply`，回信会显示在同一节点的对话里。

留言进中控收件的正文：

```text
决策图「<标题>」节点 <节点号>：用户写了：<内容>
同时选了「<选项文字>」（选项 <选项号>）。        ← 带了选项时
节点状态没改，处理完用 Decision_Map.mjs add 更新节点。  ← 只写话时
回话请运行 Decision_Map.mjs reply "<节点号>" <留言号> "<回话>"
```

脚本默认访问本机 jmbots，`JMBOTS_URL` 可指定别的实例。远程接口可使用 `JMBOTS_TOKEN`。

`notify` 也可通过 `JMBOTS_DATA` 选择运行时目录，查询端口取该配置的 `server.port`。命令把「决策图上有 N 件等你定」和链接写入 `integrations/feishu/outbox/` 的同一份 Markdown，终端只打印件数和文件路径。

## 实现位置

`Store.ts` 校验树、合并节点、记留言并持久化。`Routes.ts` 注册接口和通知，留言文字在这里校验。网页 `Layout.ts` 的 `getLayout` 用 d3-hierarchy 计算放射角度与层深，主线分支获得双倍角度权重；`getMindLayout` 用 d3 的定距树排思维导图。两者共用 `getVisible`（聚焦、折叠）和 `getFlow`（卡片、连线）。`Views.tsx` 是表格和清单，`Drawer.tsx` 是共用侧栏，`Words.ts` 接语言包。React Flow 显示画布，侧栏提交后跟随新快照显示中控确认和回话。
