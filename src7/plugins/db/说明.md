# db v1.0.0

提供主库的 Drizzle 实例、插件迁移和事务。首期选择 SQLite，包装 Resources 打开的 `data/jmbots7.db` 同一连接。Resources 管连接的建立、关停和 WAL。

## 依赖与配置

- 依赖 `resources`。在 `plugins` 里将 `- name: db` 放到依赖它的插件前。配置 `engine` 省略时为 `sqlite`。
- 插件在 `inject` 声明 `db`，自行用 `sqlite-core` 声明业务表。首个样板是 `context-fit` 的 `compress_log`。
- 无事件和 HTTP 接口。

## 对外函数

| 接口 | 输入与用途 |
| --- | --- |
| `ctx.db.engine` | 当前方言标识 `sqlite`。 |
| `ctx.db.orm` | 使用现有原生连接的 Drizzle 实例。插件用自有表定义建立查询。 |
| `ctx.db.migrate(plan)` | `{ plugin, migrations }`。业务插件启动时提交按版本从 1 递增的完整计划，再发起业务读写。迁移及记录一并提交。 |
| `ctx.db.transaction(work)` | 接收函数 `(tx) => value`，在同一 SQLite 事务内调用并返回它的值。函数内用 `tx` 执行同步查询，调用 `.run()`、`.get()` 或 `.all()` 取结果。抛错时回滚。 |

## 内部流程和数据

db 启动时建自己的 `db_migrations`。业务插件依挂载顺序提交各自迁移，同一插件依版本处理。SQL 文件由 Drizzle Kit 根据所属插件的表定义生成，按语句分隔符逐条执行。Bun 在打包时将这些文件作为文本嵌入，因此迁移不依赖运行目录中的项目源码。现有 `compress_log` 采用首版兼容建表定义，原记录直接供查询使用。

| `db_migrations` 列 | 用途 |
| --- | --- |
| `plugin` | 表和迁移的所属插件，参与主键。 |
| `version` | 插件内的迁移版本，参与主键。 |
| `hash` | 规范化换行后的 SQL SHA-256。 |
| `applied_at` | 成功应用的 Unix 毫秒时刻。 |

已提交的版本重启时只核对内容摘要。新迁移用下一版本，保留已发布的迁移内容。首版兼容建表的 `IF NOT EXISTS` 保留已有表和数据。

## 后续接入 PostgreSQL 或 MySQL

`DbEngine<TOrm, TTx>` 定义引擎、具体 Drizzle 实例、迁移和事务边界。接入网络库时，用各自的 Drizzle 驱动和事务类型实现同样的能力。拥有业务表的插件在各方言中声明相同的领域字段，并提交该方言生成的迁移。PostgreSQL 用 `pg-core`，MySQL 用 `mysql-core`。网络库的启动要等连接、迁移和事务完成，业务调用随之改成等待异步结果。发布前在 WSL 的 Docker 测试库分别验证启动、迁移、回滚和旧数据保真。
