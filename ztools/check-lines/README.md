# 教程行号检查

从仓库根目录运行，Bun + TypeScript，复用项目已有的 `typescript`，不装依赖。

```sh
bun ztools/check-lines/Check_Lines.ts
bun ztools/check-lines/Check_Lines.ts --fix
bun ztools/check-lines/Check_Lines.ts --all
bun ztools/check-lines/Check_Lines.ts src7/docs/组块阅读 src7/docs/骨架逐行
bun test ./ztools/check-lines/Check_Lines.test.ts
```

默认范围是 `src7/docs/**/*.md`、`src7/docs/骨架逐行/*.json`、`src7/plugins/*/说明.md` 和 `src7/README.md`。可以给文件或目录缩小范围。

## 查什么

- 骨架逐行 JSON：代码原文和源码逐行相等；同名骨架文件的叶子块从第 1 行连续盖到最后一行，不重叠、不缺行；子块盖住上级叶子块；分组标题、叶子标题、`**行号：…**` 和总行数相符。
- 解释：`- Lx–Ly：` 条目写的行号在本块里；写了别的文件名的不算本块；句子中顺带提到块外位置的给提示。
- `#lines=X.json&line=N`：目标 JSON 存在，N 在它的一个源码块里；链接前反引号里的名字应当在那行。类名指到构造函数、方法名指到方法体内也算。
- Markdown 代码原文：围栏里第一行是 `// src7/…ts` 或 `// node_modules/cordis/lib/index.js…`，后面是「行号 + 制表符或两个空格 + 原文」，逐行和源码核对；`…`、`...` 或跳号表示另起一段。
- 行内引用：`src7/Main.ts:78–80`、`Sessions.ts:531`、同一行前面提到文件的「第 194–213 行」，不能越界。有相邻名字时也核对名字是否在那几行；Markdown 函数/事件对照表里没有相邻反引号名字时，自动从第一格提取符号名（支持反引号、`Class.method`、参数括号、泛型、Markdown 链接与中文括号备注）核对定义与调用点存在性。
- `[文字 · 文件:行号](路径.ts#L行号)`：方括号里的「文件:行号」照行内引用核对，`--fix` 时同步更新圆括号里的 `#L行号`；校验模式也会检查两侧行号是否一致。
- 只写文件名的引用：同一文档代码块头写过的文件优先；插件说明先找本插件；带插件目录的（`bots/index.ts`）补 `src7/`、`src7/plugins/`；再按文件名结尾找，唯一才算。文件名按原样比大小写（Windows 上 `plugins/index.ts` 不会认成 `plugins/Index.ts`）。

归档快照（`docs/云端/`、`docs/任务/`、文件名带八位日期，以及进度、旧指导意见、旧问答）不按当前源码推测漂移；越界、缺文件仍列为提示，不擅自改历史判断。当前教程和插件说明里的越界是问题。

## --fix 的边界

只改有依据的：

1. 代码原文在源码里完整、连续、唯一命中，更新代码行号及 JSON 的标题、行号、解释、目录。
2. 相邻的反引号名字能在语法树里唯一定位，更新引用；类名.方法名可以用实例名写法（`sessions.find`）。
3. 同一文档的代码原文能证明某个行号在片段里，或行号前后最近两段原文挪动量一致，更新没有名字的引用。推不出时提示人工核对，不按全文件加一个固定偏移。
4. `#lines` 按名字或这次已定位的源码块更新目标和显示文字。

原文已经变了、同一片段命中多处、名字找不到或不唯一，不能可靠修复；输出位置和原因。`--all` 打印所有提示，包括缺文件、歧义、范围里没看到名字。**退出码 0 不代表没有提示，交回前应看一次 `--all`。**

默认校验不写文件。修复保留 Markdown 的逐行换行、JSON 的 CRLF/LF 和末尾换行；JSON 仅在按 1、2、4 格或制表符缩进重排后和原文一字不差时写回，认不出排版的报人工处理。写前重读，对不上最初文本就拒绝覆盖并行改动；请拉最新重跑，不要覆盖 Codex 的改动。

## 换版中控接入

在源码、教程文档都同步好以后，先跑只读校验。不要在换版流程里自动修文档：

```sh
bun ztools/check-lines/Check_Lines.ts
```

| 退出码 | 含义 |
| --- | --- |
| 0 | 没有确定的问题（可能仍有提示，`--all` 查看） |
| 1 | 有确定的问题；`--fix` 时是修完重查仍存在的问题，或有文件没写回 |
| 2 | 参数不认识或没有匹配到任何文件 |

Windows 调度用 `bun.cmd`，通过项目的 `ztools/jmbots-run/Run.mjs` 提交，命令审核不放行时由中控决定是否放行；不要绕过 Run.mjs 直接在 VM 上跑。

## 测试

`Check_Lines.test.ts` 在临时目录搭小源码库，覆盖连续原文定位、按附近片段推算、名字解析、校验只读、JSON 标题/解释/链接联动和 CRLF 保留。测试不改真实教程。
